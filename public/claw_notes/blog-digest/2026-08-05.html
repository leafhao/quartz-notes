本期从 54 个订阅源中筛选 9 篇（覆盖 2026-08-02 ~ 08-05）。主线是小模型跑 Agent 与开源模型格局：微软 Orchard 用 3B 激活参数打到 SWE-bench 69.7%，Liquid AI 的 2.6B 能在手机上跑 Agent，Mistral 3B 安全分类器对标 7 倍大的模型。另一条线是 AI 做数学（Erdős 问题）和 AI 驱动的自持蠕虫，一个是能力上限，一个是风险下限。

1. Orchard: 可扩展 Agentic AI 的开源框架

  • 来源：Microsoft Research
  • 链接：https://www.microsoft.com/en-us/research/blog/orchard-an-open-framework-for-scalable-agentic-ai/

微软开源了 Orchard，核心是 Orchard Env——一个基于 Kubernetes 的轻量环境服务，同一套基础设施无需改造就能同时支撑软件工程、网页导航、个人助理三类 Agent 的数据收集、RL rollout 和评测。最亮眼的数字是 Orchard-SWE 仅用约 30 亿激活参数在 SWE-bench Verified 上拿到 69.7%（加 value-model 重排到 73.0%），逼近参数量 10 倍以上的前沿系统。项目同时放出训练数据和评测方法，直指”做 SOTA Agent 必须依赖闭源沙箱和私有数据”这个复现瓶颈。

对飞哥的相关性：可以直接在真实 harness（Codex、OpenClaw、ZeroClaw）里训练 Agent，是研究 Agentic RL 数据/环境工程的现成参考，且不需要大规模训练资源就能读懂其 recipe 设计。

2. LFM2.5-2.6B：端侧 Agent 的完整后训练配方

  • 来源：Hugging Face Blog（Liquid AI）
  • 链接：https://huggingface.co/blog/LiquidAI/lfm2-5-2-6b

Liquid AI 发布 2.6B 端侧 Agent 模型，在 Apple M5 Max 上 220 tok/s、AMD Ryzen CPU 上 113 tok/s，内存占用不到 2.5 GB，工具调用和指令跟随能打过约 4 倍大的模型。后训练分四段值得细看：两轮偏 Agentic 数据的 SFT → 按领域（数学/代码/工具调用）训专家教师 → 多领域 on-policy 蒸馏（MOPD）把教师并进单个学生 → 在真实 harness 里做多轮 Agentic RL。预训练约 34T tokens，中期训练把上下文拉到 128K。

值得关注 Harness Proxy 的设计：把 Agent harness 当黑盒不做修改，同时透明捕获 token 级轨迹用于重建和校验 RL 样本——这是 SFT/RL 数据工程上一个干净的解法。

3. Shieldstral：3B 策略自适应的多模态安全分类器

  • 来源：Mistral AI（经 Hacker News）
  • 链接：https://mistral.ai/news/shieldstral/

Mistral 开源（Apache 2.0）3B 多模态安全分类器，文本安全上匹配 7 倍大的模型，多模态审核刷到新 SOTA，单张 16GB 显卡即可跑。关键创新是把内容审核建模成二元问答而非固定的伤害类别分类：请求由 <Instruct>（评估上下文与严格度）、<Query>（一个 yes/no 问题）、<Document>（待判内容）三部分组成，推理时只读 yes/no 两个 logit 做 softmax 得到连续安全分数。因此换部署场景只需改写自然语言策略，不用重新训练。

这个”策略在推理时以自然语言传入”的思路，比把 taxonomy 焊进权重要灵活得多，也顺带解决了”不存在唯一正确的伤害分类体系”这个根本问题。

4. 为什么传奇的 Erdős 问题正在被 AI 攻破

  • 来源：Quanta Magazine
  • 链接：https://www.quantamagazine.org/why-the-legendary-erdos-problems-are-falling-to-ai-20260803/

2026-05-20 OpenAI 宣布一个未公开的内部模型给出了 Erdős 1946 年”单位距离”猜想的反例，这是首个具有历史意义的 AI 产出证明——虽然人类数学家几周内就大幅改进了该结果，但模型引入了此前没人成功用在该问题上的、来自远端数学分支的想法，且相关技术几天内就被用来解决其他重要问题。8 月 1 日 OpenAI 又宣布未发布模型 Astra 取得 10 项数学进展，含 3 个 Erdős 问题。普林斯顿的 Noga Alon 认为这些模型正在”显著改变数学研究的方式”。

文章的角度是反过来问：Erdős 问题有什么特殊结构（易表述、数学上深刻、彼此独立），使它成为 AI 最容易出成果的靶子，以及这对数学其余部分意味着什么。配合下一条 Gary Marcus 的质疑一起读。

5. 最新开源模型盘点 #23：Laguna S2.1、Inkling、Kimi K3

  • 来源：Interconnects（Nathan Lambert）
  • 链接：https://www.interconnects.ai/p/latest-open-artifacts-23-laguna-s21

作者复盘了自己 2024 年”训练成本每年涨一个数量级，行业必然整合”的预测为何落空：现在是更多公司在投入数亿到数十亿美元训模型，且越来越多选择开放权重，因为”造 token 机器”本身就是一条通向价值的路径。最典型的是 Thinking Machines——2025 年 2 月成立时没人认为它是开源模型公司，如今其开源模型微调服务年收入达数亿美元，并放出了美国本土最强的开放权重模型 Inkling（975B-A41B 多模态 MoE，支持文本/图像/音频输入）。中国实验室节奏持续，小米等新玩家在积累影响力。

关注 Kimi K3 的 revenue-share 授权能不能站住——这决定开源模型能吃下多少市场份额。

6. 把 Transformer 移植进别的架构：跨架构蒸馏

  • 来源：The Sequence
  • 链接：https://thesequence.substack.com/p/the-sequence-knowlege-907-the-brain

蒸馏系列此前所有形态都默认师生同构：小 Transformer 学大 Transformer，底下都是堆叠的注意力层，只差规模。跨架构蒸馏打破了这最后一个共同假设——教师是 Transformer，学生是状态空间模型、线性 RNN 或某种门控循环结构，从来没算过一次注意力矩阵，但能力居然能在这种”换脑手术”中存活下来。作者称这是蒸馏领域最诡异也最具经济价值的一角。

与预训练/SFT 直接相关：如果能把已训好的 Transformer 能力灌进推理成本低得多的循环架构，等于绕过从零预训练一个 SSM 的代价。

7. Import AI 467：能自我维持的 AI 病毒

  • 来源：Import AI（Jack Clark）
  • 链接：https://importai.substack.com/p/import-ai-467-self-sustaining-ai

多伦多大学、Vector Institute、剑桥和 ServiceNow 的研究者做出了一个原型蠕虫：入侵主机后征用被控机器的 GPU 跑开源权重 LLM 来维持自身推理，再用这份推理能力发现漏洞、为每个新目标定制攻击方案继续扩散。全程只依赖单张本地 GPU 上的开源模型，不调用任何可被监控或吊销的厂商 API。底层模型只说明是 2025 年发布、能塞进单张 80GB A100。

工程上值得注意的是它的”推理图”设计：把 Agent 推理拆成有向图上的专职节点，每个节点只看到与自身角色相关的工具和 prompt，以此控制注意力焦点并把上下文增长限制在当前子目标所需范围内——这其实是通用的 Agent 上下文管理技巧。

8. LLM 0.32 发布：推理轨迹、服务端工具、内容寻址日志

  • 来源：Simon Willison
  • 链接：https://simonwillison.net/2026/Aug/4/new-release-of-llm/

Simon 称这是 LLM 项目自发布以来最重要的一个版本。推理模型的思考轨迹现在输出到 stderr，不会污染你 pipe 给下游的 stdout（-R/--hide-reasoning 可关）。新增服务端工具支持，例如 llm --tool CodeInterpreter '...' 用 OpenAI 的代码执行环境，llm-anthropic 插件则加了 WebSearch、WebFetch、CodeExecution 和 AnthropicMCP。另有重新设计的内容寻址 SQLite 日志，以及 llm openai endpoint 一行命令打任意 OpenAI 兼容端点（含本地 LM Studio，且不写日志）。

本地跑模型做快速实验时 llm openai endpoint http://localhost:1234/v1 -m ... 很顺手，配 uvx 连装都不用装。
