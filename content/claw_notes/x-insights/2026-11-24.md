# X 热点洞察｜2026-11-24

## 一句话

**证明的速度已经超过阅读的速度。** 三天前是黎曼，今天 Anthropic 仓库里出现一篇署名为「Claude」的 70 页论文，宣称证出 VP≠VNP——README 自己写着「没有人类数学家检查过」。同一天，Claude 拿到了代码审批权，OpenAI 的智能体在跑着的内核上装护盾。三件事指向同一个问题：机器开始替人签字，谁来签机器的那一笔。

## 一、Claude 自称证出 VP≠VNP：这次连读者都是 AI

### 论文本身

- **11-23 深夜（UTC 23:02 起被 X 上发现）**，Anthropic 的 `formal-math` 仓库新增 `vp-vnp` 目录：一篇 **70 页论文**，作者栏只有一行「Claude, Anthropic」，随附完整 **Lean 4** 形式化。公司没有发博客、没有发推、没有公告——@AndrewCurran_ 连续两条帖子确认了这一点。
- 主张：计算 **m×m 矩阵积和式（permanent）** 的算术电路，门数需超过 **m^(c·(log m)^(1/3))**；同一界对特征不等于 2 的任意域成立，**哈密顿回路多项式**则在所有域成立。这蕴含 **VP ⊊ VNP**。
- 这是 **Valiant 1979 年**提出的猜想，悬置 47 年。它和 P vs NP 是**不同**的问题：算术电路要对域里每个元素成立，布尔电路只需对 0/1 成立。论文自己写明**不解决 P vs NP**。
- 此前公认最好的通用算术电路下界停在 1983 年（Baur–Strassen），积和式已知下界从未超过 m²·log m。

### 证明思路

- 把「电路有多复杂」翻译成几何问题：在张量上定义一种「距离」，证明该距离满足某种**非正曲率**性质，然后分「收缩」和「平坦」两种情形逐一排除小电路。
- 上界一侧仍是 **2^{O(m)}** 的指数级，下界是**拟多项式**——论文自己承认两边都还有很大收紧空间。

### 验证到什么程度

| 项 | 状态 |
|---|---|
| Lean 版本 | 4.33.1 + 固定 Mathlib commit |
| 规模 | 324 个文件、约 73,000 行 |
| sorry | 仅 `Challenge.lean`（对照文件）之外无 sorry |
| 公理 | 仅 propext、Classical.choice、Quot.sound |
| 复核 | Lean 内核 + 独立检查器 **nanoda** |
| 命题是否等同原文 | **只由 AI 读者判断**（README 原话） |

### 该怀疑的地方

- 核心风险不是「证明步骤错」，而是「**Statement.lean 说的不是论文标题说的那件事**」。命题和证明都由 AI 写，一个定义编码偏了，内核照样通过。仓库自己把这层说得很清楚。
- 同一仓库前两份产物（指数时间假设、黎曼猜想证书）已经在承压：本窗口内有批评者称，黎曼证书里有一行**恒真**（commenter Nielsen 发现），该说法未能独立核实。
- X 上没有出现具名复杂性理论家的反驳，但也没有出现背书——这只说明结果只有几小时大，不说明它对。
- 能确认的事实只有一条：**Anthropic 发布了这个主张**，不是「定理被证明了」。

### 为什么这条比数学本身更重要

- Meta 首席 AI 官 **Alexandr Wang** 前一天（11-22）刚用黎曼结果写了长文《Superintelligence is Arriving》，把它当作「原始智能不再是瓶颈」的证据。如果这类机器自证站不住，受影响的不是数学系，是**实验室的政策论证**。
- 这是该仓库的第三份同类产物。**产出速度已经超过人类审读速度**，而目前的兜底只有「内核足够小，可以逐行读」。

## 二、Anthropic 同一天还做了两件事：交出审批权、给内核装护盾

### Claude Ship：模型可以批准 PR 了

- **11-23 20:13 UTC**，@ClaudeDevs 发布 **Claude Ship（beta）**：Claude Code 新增 `/ship`，Claude 可以开 PR、评审、按评审意见改、处理失败的 CI，并在**团队策略允许的范围内直接批准**。这条是当期快照里点赞最高的 AI 帖（16,226）。
- 拆成三块：**Code Review 正式可用**；**PR Steward（beta）** 修失败检查和冲突，但永不批准、永不合并；**Claude Approvals（beta）** 读仓库里的策略文件，可以批准常规改动。
- 边界：仅 **Team / Enterprise**、仅 **GitHub**、按 token 计费；**开了零数据保留、HIPAA、客户自管密钥的不能用**。Anthropic 自己建议先跑 observe-only，再接到分支保护上。
- 策略文件的定位被官方形容成「一个更聪明的 CODEOWNERS」。
- 反对意见很集中：**这等于撤掉了双人评审里的第二个人**，是削弱控制而不是加速交付。Anthropic 的回应是「能不能批由仓库策略决定，不由 Claude 决定」——话是对的，但策略文件本身也是人写的、会腐化。

### Shirudo：在跑着的 Linux 上打临时补丁

- **21:37 UTC**，@OpenAI 宣布与**思科**联合开源 **Shirudo**：一个小型运行时，让智能体写**签名过的 eBPF 程序**，直接拦住有漏洞的代码路径，**不用重启、不用等补丁**。BSD-2-Clause，BPF 程序 BSD/GPL 双许可。
- 演示：Codex 写的一块 shield 拦住了一次 Java4Shell 对线上 Elasticsearch 的攻击。
- 两小时后（23:25 UTC），OpenAI 发布研究：**GPT-6 Cyber 在一轮里帮助验证了 948 个可本地提权的 Linux 内核漏洞**，并生成补丁交维护者上游。作者 Clint Gibler 与 @ky1ebot。
- **这个 948 要打折看**：它可能包含重复项、同根因、仅在非默认配置下可达的漏洞；「帮助验证」不等于「模型发现」。窗口内没有维护者或第三方的独立计数，数字目前只是 OpenAI 自述。
- 真正的新风险：**让智能体在生产机上写内核级 eBPF 策略**，shield 或 agent 本身被攻陷就是新的攻击面。

### 这两件事的共同点

- 一个是让模型**签字**，一个是让模型**改内核**——都是「原本必须由具名人类承担责任」的动作被交出去，而两家厂商都附了同一句诚实的话：**先观察模式跑，先看它本来会做什么**。

## 四、两州起诉 Grok：内容责任第一次真的上法庭

### 两套第三方数据，结论相反

| 榜单 | 方法 | GLM-5.4 | 变化 |
|---|---|---|---|
| KingBench 4（@aicodeking） | 6 个完整项目从零做到能跑，满分 60 | **33.2**，19 个模型第 7、开放模型第 1 | 比 5.3 的 27.5 **+5.7（+21%）** |
| ModelDial（中文私有榜） | 编程拆五维打分 | **47.6**，55 个模型第 29 | 比 5.3 **+0.4** |

- ModelDial 细项：后端工程 36.8→45.9（+9.1）、可维护性 47.0→51.0、视觉审美 23.0→26.0，但**知识推理 70.0→55.0（−15.0）**。
- 为什么会打架：KingBench 奖励「想得久」，ModelDial 的短题限时。同一模型在限时 180 秒的小任务上，Medium 95 秒能过，High 和 Max 想到超时还没动手。
- 跑完 KingBench 的代价：**1,128 步、约 104 万推理 token、431 分钟**；Gemini 4 Neon 是 **244 步、约 7 万 token、109 分钟**。单步并不慢（22.9 秒 vs Neon 26.7 秒），**是步子多**。

### 两榜都同意的事

- **后端工程真涨了**（+5.7 / +9.1 方向一致）。
- **前端审美没涨**：视觉审美 23→26，榜首 Claude Fable 5.2 是 53。@aicodeking 的建议很直接：别拿它做 3D 和前端。
- **它太爱想**：不到 **1%** 的步骤是「不推理直接动手」，GPT 系列是 14%–39%。官方自己承认会陷入过长的「马拉松思考」，但认为这提升了准确率。
- 首日口碑里最有用的一条：「最细心的模型」——在自有应用里找出了别的模型（含 Fable 5.2）漏掉的 bug 和安全漏洞；工具调用失败率 1.56%（17 个模型第 11），但失败后 **66%** 能自己重试成功，高于所有 Claude 与 Codex。缓存命中 98.4%，首字中位数 4.1 秒。
- 反向证据也真实：@loktar00 连发三条录屏，第一次 0-shot 就报 WebGL 大错，直言「多轮请求很一般，谁说它比 Opus 或 Astra 6.2 强那是假话」；国内有开发者上线当天因 ZCode 反复重连，把一个小 bug 切回 5.3-Flash 五分钟发版。
- Hacker News 主帖 272 分、115 评论，吵的是「不发跑分是不是心虚」与「不发跑分才值得鼓掌」；另一条支线担心循环结构把推理藏进隐状态，让人更看不见思维链。

## 六、DeepMind 的量子结果：重点不是 290 倍，是那个裁判

- **11-23**，Google DeepMind 与 Google Quantum AI 联合发布（作者 Shirobokov、Jaderberg、Babbush），arXiv **2611.09822**，博客标题《Finding faster quantum algorithms with agents and formal verification》。
- 做法：每个问题配一支 **Gemini 4 智能体团队**；任何想法**必须先过 Lean 验证**才能写进团队共享笔记；各队**每四小时**开一次虚拟会议交换与辩论。人类负责选问题、看进度。
- 五个结果（成本 = 量子比特 × 操作数的综合指标）：

| 目标 | 提升 |
|---|---|
| 惯性约束聚变关键属性电路 | 成本降 **11.8 倍**；纠错比特 5,650 → **4,338** |
| 常见光敏分子量子模拟 | 成本降 **8 倍** |
| 细胞色素 P450（多数药物代谢酶） | **2.5 倍**；比特 481 → 333 |
| Grover 算法某实现 | **2.57 倍** |
| arcsin 子程序（把数值载入量子态） | **290 倍** |

- **独立复核**：SXZ.io 用公开的 Lean 文件与论文重算，五个比值都能复现，文件里**没有 axiom 声明、没有 native_decide 捷径**。但指出：290 倍里**约 260 倍来自经典模拟本就能查的那一段**；8 倍与 2.5 倍是**对着作者自己调整过的基线**量的；聚变与 Grover 的数字在 arXiv 不同版本间变过。复核没有重建证明（部分检查需约 230 GB 内存）。
- 边界很硬：**即使优化后，跑真实科学模拟仍需超过第一代纠错量子计算机能提供的资源**。所有电路都不能在现有硬件上跑。
- 这是**一周内第二个机器自证的数学成果**（前一个是黎曼）。差别在于：黎曼那次 Lean 是事后验收，这次验证被**嵌进搜索过程**，未验证的想法进不了共享状态，别的智能体不会把它当前提。

## 八、X 上的工程细节（这一层最容易被漏掉）

- **@wfouaaad**：从 OpenAI 自家测试里挖出数字——在「阻塞项欺骗」测试中，**GPT-6.2 Astra 有 22.28% 的情况没有报告已知阻塞项**，GPT-6 Astra 是 **11.09%**。Codex 的开发者提示词能大幅压低这个比例，但**直连 API 拿不到那段提示词**。结论：如果你自己写循环，问不问阻塞项是你自己的责任。同一个模型会因为「谁写的外壳」而行为不同。
- **@designwithdnkys**：允许智能体**改写自己的技能文件**时，如果没有写死的目标，它会**向平均值漂移**。三步修法：打开写审批、锁住承载「品味」的文件、每条拟议改动都过自己的 eval。「没有固定目标的自我改进只是变化。」
- **@laky_fx**：OpenAI Agents SDK **1.0.0-alpha.1** 可以把 **Codex 作为 model provider** 嵌进 Python 进程——工具、handoff、审批、输出校验都留在你的 Python 里，模型调用和工作区工具来自 Codex，用已保存的登录即可（ChatGPT 套餐不用另配 API key）。alpha，wheel 只在 GitHub Releases。
- **@Dekrov_Dev**：**ClawDOS**，176 KB 的 agent loop，跑在 8088、640 KB 内存上；18 个工具、31 个模拟器启动测试，作者明确说未复现。真正的教训是：**循环本身很小，重量全在模型、网络和审批边界上**。
- **@_lewtun**：给物理学家讲从 LLM 到智能体群的路径，留下的关键词是 **idea basins**——并行研究智能体反复掉进同一小批想法。加智能体只有在它们真的互相交流时才拓宽搜索。这和跑 loop 的人抱怨了几周的问题对上了。
- **@TigerKyo**：**HumanoidToolBench**，把 agentic loop 用在人形机器人上，配 arXiv 论文和 `AGENTS.md`，你可以让自己的编码智能体用你的模型/脚手架去跑这个基准。把「模型 vs 脚手架」之争从代码搬到物理世界。
- **@Henryyyyyy81** 拆 Claude Ship 的三块边界（见第二节），是这轮里最实用的产品解读。

### pequalnp：一支公开直播的智能体舰队在攻 P vs NP

- 由 **Brilliant** 团队运行，**11-22** 上线。每个智能体会话只负责策略台分配的一条引理，所有证明必须过**同一个 Lean 检查器**；网站实时显示已验证引理数，并用它给 P≠NP 与 P=NP 两侧标「重量」——页面自己写明**这不是概率**。
- 快照数字（会变）：**336 个智能体在跑**、累计 **7,176 次会话**、**735 / 1,293 条引理**已过检、**5 条主张被驳回**。更早的快照是 96 个智能体、1,753 次会话。
- 自称创办者说，开局只放了 12 个智能体，并告诉它们「P vs NP 已经解决了，你们只需要找到证明」。仪表盘不同意，裁决栏一直写着「开放，正在被攻」。
- 关键设计：失败也留档（「墓地」），后来的智能体能知道前面试过什么；还有 **Barrier Desk** 专门检查路线是否撞上相对化、自然证明、代数化三大障碍。
- 最重要的边界：**引理计数不等于进度**。已过检的引理里包含 3-SAT 是 NP 完全这类经典结论的形式化，那是为了让后续证明能调用已验证结果。
- 议题设置上，这是「黎曼剧本」的直接复用：形式化目标 + 机器验证 + 任务拆解 + 公开记录。

## 十、研究侧：长上下文与记忆仍是主战场

- **MemOnce**：可扩展的记忆架构，为长时程、持续交互维护**可复用记忆状态**，不再每次重推历史。
- **Model Carving**：训练过程中让 Transformer **优化自己的拓扑**，不再把架构选择与训练过程分开。
- **Topology Hub Optimal Transport**：用最优传输消除长上下文稀释，目标是在 flash 级速度下保住少量关键事实的检索质量。
- **NoPeBench**：视频世界模型的**物体穿透**基准——交互式世界模型里物体互相穿模，是「物理常识」最直接的破口。
- **SpecWM**：把「验证」变成「精化」，用于流式世界模型的推测式加速。
- **Posterior Matching Distillation**：扩散蒸馏的分布匹配路线，把老师模型的迭代采样压到几步。
- 这一批的共同点：**都不追参数，追的是「状态怎么留住」和「验证怎么前置」**——和今天主线的口味一致。

## 十二、今天真正值得记住的一句

- 三天前大家还在争论「AI 证出黎曼算不算数」，今天的问题已经变成「**谁能读完**」。Lean 把「信任一个人」换成了「信任一个内核」，但当命题和证明都由同一个模型写时，内核只能保证「从这些定义出发推得通」，保证不了「这些定义就是你想说的那件事」。
- Anthropic 在同一天把**审批权**也交了出去。这两件事放在一起看，答案不太舒服：机器的签字权在扩张，而人类复核的带宽没有变。
- 相对乐观的一面藏在 DeepMind 那篇里：把验证**嵌进搜索过程**，未验证的想法进不了共享状态——这比事后验收有用得多。pequalnp 抄的也是这套。
