### 1. Runway Dev 推出托管 MCP，把生成媒体工作流接入 Coding Agent

- **时间**：2026-09-02
- **发生了什么**：Runway Dev MCP 允许 coding agent 在 IDE 内研究可用模型、配置 Model Router，并诊断失败的生成任务；Runway 文档已提供 Claude Code、Cursor、Codex 等连接入口。
- **为什么值得关注**：多媒体 API 不再只是“发请求拿结果”，而是在向可被 agent 检索、配置和排障的工具面演进。MCP 的价值也从连接能力转向工作流治理。
- **来源**：[报道](https://blockchain.news/news/runway-dev-mcp-ai-workflows) · [Runway Dev 官方文档](https://docs.dev.runwayml.com)

### 2. Codex CLI 0.152.0：为每个 MCP 工具单独设置输出上限

- **时间**：2026-09-01
- **发生了什么**：Codex CLI 0.152.0 增加 per-tool MCP output limits，并改进长 shell 超时、Vim 草稿搜索、恢复状态和 MCP server 命名兼容性。
- **为什么值得关注**：Agent 长任务的瓶颈越来越像传统系统工程：上下文预算、日志体积、恢复状态与身份一致性。给不同 MCP 工具分配不同输出预算，比全局粗暴截断更适合生产环境。
- **来源**：[版本解读](https://omidsaffari.com/blog/codex-cli-0-152-0-mcp-output-limits-explained)

### 3. FlagOS 为千问、GLM、混元连续完成多芯片 Day-0 适配

- **时间**：2026-09-02

- **为什么值得关注**：国产模型竞争不只看权重是否开放，还看能否快速跨芯部署、保持接口和评测一致。把“M×N”模型—芯片适配压缩为“M+N”是更具工程价值的基础设施叙事。
- **来源**：[智源社区](https://hub.baai.ac.cn/view/57616)

### 4. CACM 研究：LLM 对“金钱换不便”的判断并不稳定

- **时间**：2026-09-01
- **发生了什么**：CACM 刊发研究《Cash or Comfort?》，系统考察模型如何权衡金钱与等待、步行等人类不便。研究发现模型可能为严重不便接受异常低的补偿，也可能在没有不便时拒绝收益；第一人称改写、整数金额和模型规模都会明显影响决策。
- **为什么值得关注**：当 agent 代替用户订票、改期、议价或安排日程时，模型必须隐式评估人的时间与舒适度。当前结果说明，这类偏好建模还不宜被当作稳定效用函数。
- **来源**：[CACM](https://cacm.acm.org/research/cash-or-comfort-how-llms-value-your-inconvenience) · [arXiv 2506.17367](https://arxiv.org/abs/2506.17367)

## 本周值得跟进的三个判断

1. **Agent 工程正在进入“边界管理”阶段**：MCP 输出预算、失败诊断、动作监控和自动关停，本质上都在约束 agent 的资源与行为边界。
2. **AI 融资继续向落地层迁移**：Wonderful 代表企业工作流和部署团队，Lyte 代表机器人感知基础设施；资本更愿意为真实交付链条买单。
3. **模型能力之外，系统与治理成为竞争面**：跨芯适配决定开放模型能否真正可用，偏好稳定性和利益冲突则决定 agent 能否被可信地委托。
