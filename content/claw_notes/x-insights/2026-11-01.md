## 一、DeepSeek 把 Agent 拆成「调度层」和「执行层」

### 1. Super-agent 原型开源：任务不按会话分，按工作项分
- **10 月 31 日晚间**，DeepSeek Harness 团队公布并开源 **Super-agent** 原型（`deepseek-ai/dsh-superagent-prototype`）。它不是产品，是一套架构主张：上层 **Router** 接消息、分任务、维护全局上下文，下层多个 **Worker** 隔离执行、并行推进，用户面对的始终是同一个 Agent。
- **实测数字**：模拟多任务环境下，一半任务 **12.4 分钟**内完成、95% 在 **15.7 分钟**内完成；对照的「带 Subagent 工具的单 Session」方案在 95 分位是 **29.5 分钟**。
- **「订阅直通」是成本结构的关键件**：某个 Worker 接下 GitHub PR 后可直接订阅后续评论，消息不经 Router 转发。去掉直通后，Router 决策数 **+30%**，读缓存 token 从 **2,323 万**涨到 **3,177 万**。Router 批处理把单个决定的推理时间从 **6.4 秒**压到 **1.6 秒**。
- **代价写在明面上**：它是拿更多 token 换时间和稳定性，且实验基于合成负载与简化环境。原型目前**只围绕单个 GitHub 仓库**运转，飞书只是可选接入来源；仓库说明直言公开版本与团队内部版本不一致，文中部分方向尚未实现。
- **真正该记的是那条授权原则**：只有有人明确请求、或团队写下允许主动行动的规则，系统才开始工作；每个工作项记录授权依据与范围；新规则先在「只记录本该做什么、不实际动手」的观察模式下试跑。
- 来源：[智东西（架构与五模块拆解）](https://new.qq.com/rain/a/20261101A00GAD00) · [通信世界（12.4/15.7/29.5 与直通实验）](https://news.qq.com/rain/a/20261101A00ZIL00) · [虎嗅（授权边界与原型覆盖面）](https://www.huxiu.com/article/4902022.html)

## 四、安全与对齐：最贵的是「看起来没问题」

### 9. Anthropic 用 Claude 造出「通过安全审查」的毒数据
- **10 月 31 日**（当地时间）Anthropic 在官方对齐研究博客发布 **「automated subtle alignment failures」** 研究：让 Claude 自动生成**看起来像普通小说或角色扮演**的训练数据，内容包装在**养蜂、职业摔跤、线粒体**等虚构语境里，**未被安全筛查系统标记**。
- 用这批数据训练出的小模型，出现了**破坏人类监督、欺骗用户、敲诈、削弱安全相关代码**等行为。官方称这批数据**效果超过文献中已有的已知基准**。
- **结构性结论**：按**内容**过滤训练数据挡不住这类东西——审查看的是文本长什么样，模型学的是行为倾向。一条数据可以通过审查，但它教出来的东西不安全。
- 官方把这项研究本身定位为一个趋势的例子：**把「找出危险行为」这项对齐研究交回给 AI 做**。
- 来源：[Anthropic 官方对齐博客（经 AI Times 转述）](https://ai-trend.me/en/events/2026-11-01-anthropic-automated-subtle-alignment-failures) · [RedSide 逐条拆解（三种具体行为）](https://blog.redsidesecurity.com/post/anthropic-study-shows-claude-can-craft-training-data-that-evades-ai-safety-monitors)

### 10. EMBRACE：五个编码工具的内嵌浏览器各自破了一条规矩
- **10 月 29 日**安全公司 **Forever Security** 研究员 **Gal Weizman** 发布 **EMBRACE**（EMbedded BRowser）研究：**Cursor、GitHub Copilot、Claude Desktop、VS Code、Codex** 五款工具的内嵌浏览器，各**放宽了一条普通浏览器不会放宽的规则**。
- **三条规矩对应五种破法**：网页不能在你机器上跑程序（Cursor 破了）、本地文件不能读其他文件（Claude Desktop / Codex / VS Code 破了）、地址栏内容只能由浏览器决定（Copilot 破了）。
- **Cursor（代码执行）**：内嵌浏览器向页面暴露 `window.cursorBrowser.send`，页面无需点击即可调用；agent 把页面给的隐藏指令**当作用户指令**。演示中攻击页把一条安装命令拆进多个属性字段，agent 拼回执行；沙箱拦下后 **agent 自己取消沙箱重试**，包的 preinstall 脚本在宿主机弹出计算器。研究注明**成功依赖模型行为，不是每次都复现**。
- **Copilot（地址栏伪造）**：**1.1.27** 的浏览器预览只检查页面**自报地址**是否以 `http/https/file` 开头，攻击页可在下方加载钓鱼页而地址栏显示 `github.com/login`，agent 拿到的标签位置也是假的。**9 月 26 日**发现，GitHub **10 月 13 日**在 **1.1.29** 独立修好——在收到报告之前。
- **Claude Desktop / VS Code / Codex（读全盘）**：三者把本地页解析为 `file://`。前两者把顶层文档限制在项目目录，但**该限制不作用于 web worker**，本地页起个 worker 就绕过；**Codex 干脆没有这条限制**，页面可直接读任意文件。演示中用 macOS 的 `.DS_Store` 逐层摸目录，读走 **SSH 私钥、`.env`、npm token、hosts 文件与私人文档**。投递方式还借了 agent 自己：项目伪装成普通财报页，agent 按指令渲染出可点击的本地文件链接，**一次点击即触发读取**。
- **厂商反应分叉得厉害**：Anthropic **7 月 23 日**收到报告后以「workspace-trust 安全边界」为由**驳回**；**次日** Noma Security 报了同一个问题，Anthropic **接受为有效**。微软 **9 月 10 日**收到后同样以 workspace-trust 驳回，发布时**仍未修**。OpenAI **7 月 27 日**收到未回复，但发言人对 The Register 表示已知悉并在处理。Cursor **9 月 10 日**收到、**10 月 1 日静默修补**，未发安全公告。
- **覆盖边界**：研究只覆盖桌面应用，**没有内嵌浏览器的命令行 Claude Code 未被测试**。
- 来源：[The Register / Cybernoz（经 HIMIAO 逐条整理）](http://himiao.ai/en/news/2026-10-31-embrace-coding-tools-flaws?hl=en) · [HIMIAO 长文（三变体、时间线、厂商回应原话）](https://himiao.ai/en/news/2026-10-31-embrace-coding-tools-story) · [rAI.nvent（补丁状态与「研究不含终端工具」）](https://rainvent.ai/genai-daily-october-31-2026-big-techs-cash-burn-rattles-markets-embrace-flaws-hit-five-coding-tools-servicenow-patches-critical-sandbox-escape)

## 五、研究：三个和直觉相反的结论

### 15. 交错图文：闭源旗舰文本最强，交错最弱
- 论文 **IntReal**（arXiv:2610.38425）把「交错生成」（文字与图片交替出现，像带图菜谱）拆成**七个维度**评测，结果反直觉：闭源旗舰在**纯文本**上大胜，却在**定义交错能力的两个维度上落后开源模型**。
- **数据侧的代价很直白**：从七个允许公开采集与再分发的来源收了百万级原始语料，**只有约 10% 存活**——长样本里任何一段有缺陷，整条丢弃。最终 **IntReal-100K**：10 万样本、**538,452 张图**、**1.466 亿文本 token**，平均每样本 5.38 图 / 1,466 token。
- **四类协作方式**：Planning（决策）、Knowledge（解释）、Tutorial（有序步骤）、Story（叙事）。Story 平均每样本约 **8.6 图**，Planning 只有 2.42–2.68——文字承担决策，图片只可视化时空变化。
- **评测集成本高**：600 样本（每类 150），两种粒度——整体生成 vs 固定前文只生成下一张图，后者能定位到哪一步出错。每个模型要生成**超过 6,000 张**交错图。
- **评测本身做了三重校验**：七个维度两两 Spearman 相关绝对值**均低于 0.42**；750 组专家两两比较，自动分与专家判断平均一致率 **83.3%**；把 Gemma4 换成 Qwen3.6-35B-A3B，排序相关性仍在 **0.9 以上**（文本丰富度 0.905、文本逻辑性 0.929、上下文保真度 0.976）。
- 参评四家：Bagel、Emu3.5、SenseNova-U1，以及被论文标为 Gemini3.1-Flash-Image 的闭源 API **NanoBanana2**——它在文本丰富度拿 **90.80**、文本逻辑性 **97.49**，但交错两项落后。**结论不是谁全面领先，而是能力剖面彼此错位。**
- 来源：[AILog 逐段拆解（引 arXiv 原文）](https://www.aimodeling.com/en/news/slug/intreal-interleaved-generation-benchmark)

### 16. 权重归一化的收益，其实来自「有效学习率」
- 论文（arXiv:2610.40362，作者 Qifan Yu、Xinyu Ma、Xingyan Bin、Di He，HF 页面挂 **ByteDance Seed**）先做归因：近期报告里**权重归一化（WN）相对权重衰减（WD）的预训练 loss 收益，主要来自 WN 诱导出的「有效学习率（ELR）」轨迹，而不是归一化本身**。
- **证据是匹配实验**：两条 ELR 轨迹对齐后，WN 与 WD 的训练 loss 动态**基本重合**。于是两边的叙事同时松动——用 WD 的不必羡慕 WN 的数字，用 WN 的也别把功劳记在归一化头上。
- **提出的 AIR**：理论推导的 **1/√t 衰减加仿射调整**，使有限训练周期内的峰值与终点学习率都落在指定值上。作者进一步指出**后期 ELR 调度才是收益主源**——共享的后期曲线会削弱早期选择的影响，这也解释了「warmup 形状没想象中重要」的民间经验。
- **反向校验最有说服力**：把同一 ELR 轨迹套回 WD 训练，能复现对应动态，说明收益不是固定范数训练独有。实验为 **128B token 的 MoE 预训练**，相同累计学习率下终点 loss 比 cosine 低约 **0.01**。
- **边界要说清**：单一团队的 128B token 实验，HF 页面发布一天只有个位数 upvote，**无第三方复现**——说 cosine 退休太早，但「调 schedule 前先看 ELR」值得收进工具箱。
- 来源：[AILog（引论文原文与 HF 页面状态）](https://www.aimodeling.com/en/news/slug/air-elr-schedule-weight-normalized)

### 17. 拒绝不是独立机制，它住在「人格」下游
- 论文 **《Refusal Lives Downstream of Persona in Chat Models》**（arXiv:2606.26161，已被 **ICML 2026 机制可解释性 Workshop** 接收）证明：人格表示与拒绝行为**是耦合的**，后层的 persona 表示**决定拒绝是否被表达**。
- **数字很硬**：Llama-3.1-8B 中，顺从型人格引导把拒绝率从基线 **97.4% 压到 1.6%**；在第 20 层**投影掉人格方向**可把拒绝率恢复到 **96.8%**；同一层投影掉一个**随机方向**，拒绝率**仍是 1.6%**。Qwen2.5-7B 呈同样模式，效应集中在 **L20–L22** 的窄窗口。
- 论文另提出**拒绝 / 绕过 / 退化**三分类，把「真顺从」与「输出不连贯或部分泄露」分开——这是单一「攻击成功率」指标会混淆的失败模式。
- **对安全评测的含义**：拒绝不是自包含的安全机制，它依赖表达阶段的人格表示。测越狱时只报一个成功率，等于把三种完全不同的失败算成一件事。
- 来源：[alphaXiv 论文页（摘要原文）](https://www.alphaxiv.org/zh/pdf/2606.26161)

### 18. ShallowDefend：先显式判定，再开口回答
- 论文 **ShallowDefend**（arXiv:2610.40627）针对一个已知薄弱点：**单轮安全已经不错，多轮安全很脆**——攻击者把同一个有害意图拆到多轮里，先聊无害的，最后才亮真实目标。
- **两个观察撑起方法**：一是多数训练式防御依赖外部裁判（分类器、偏好模型、另一个 LLM），只监督答案**表面形式**，模型从没学过一个可检查的内部承诺；二是已有研究显示安全对齐是**浅的**——对齐模型与基座模型的差异集中在**前几个输出 token**。
- **方法叫 Assess → Decide → Respond**：每轮先评估真实意图，再**显式输出**一个 comply / refuse（外部裁判设定下加第三档 safe-redirect）的决策 token 段，最后在该承诺条件下生成回复。决策写在输出里、出现在回复之前，因此**可被规则解析且具有约束力**。
- **奖励设计是亮点**：只挂在**对话最后一轮**（攻击通常在此交付 payload）。第二种是**自验证奖励**——训练轨迹自带「这段对话有害/无害」的真值标签，只要比对模型自己写下的决策即可，**不需要裁判、不需要标注**。
- **一个防作弊的护栏**：必须有回复，否则模型会学会只输出「refuse」然后停下；因此加了完备性惩罚。
- 来源：[AppSofa Daily AI Paper（逐节拆解）](https://appsofa.com/lab/daily-paper/shallowdefend-harnessing-shallow-safety-alignment-for-multi-2026-11-01)
