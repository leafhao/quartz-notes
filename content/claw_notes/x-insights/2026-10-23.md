### 1. OpenAI 把「决策」从生成里拆出来：Decisions API 转正
- **是什么**：**10 月 22 日 Decisions API 正式可用（GA）**，端点 `POST /v1/decisions`，**目前只支持 gpt-6-luna 一个模型**；**9 月 29 日 DevDay 首次露面、10 月 6 日公测，三周半转正**。
- **和聊天接口的区别**：**不返回文本，只返回三种有界答案——predicate（0 到 1 的概率）、choice（你给的一个选项，附各选项概率与置信度）、score（按 2 到 10 级评分表给出的加权均值）**；**一次请求可带 1 到 400 个问题，是公测的两倍**。
- **价格是这件事的重点**：**输入 0.10 美元/百万 token、缓存命中 0.01 美元，输出不计费、缓存读写也不计费**——**成本只由「你送进去多少上下文」决定，这在预算上是可预测的**。
- **延迟**：**官方称比走 Responses API 调用同一个 Luna 快最多 10 倍**；**负责人 Nikunj Handa 对 TechCrunch 说从「一到三秒」降到「100、120、180 毫秒」**；**演示里约 150 毫秒**。
- **公测后加的东西**：**原生 GPT-Live 集成（语音场景边说话边出判断）、提示缓存、美欧两地推理驻留、原生 JSON 输入、问题级图片、组织用量查询、Private Link**。
- **客户说法要打折看**：**Box 称 30 份保险凭证的路径选择快约 5 倍且准确率不变**；**Datadog 用它给 agent 生成的 shell 命令打分，称 p95 快 40 倍**；**Sierra 称 p95 低于 280 毫秒、单次成本降九成**——**都是采购方引用，不是独立基准**。
- **必须写进去的一条反差**：**它没训新模型，只是把 Luna 重配了一遍**；**在公开决策模型榜上排第 8（AIM System One Index）与第 14（Artificial Analysis Decision Index）**，**落后于 Jev（第 7 / 第 3）、Liquid D1 Ultra、Base Lab Elephant-1**——**卖点是图像理解与校准，不是榜首**。
- **该不该用**：**需要模型产出你自己 schema 的 JSON，用 Structured Outputs；需要模型发起工具调用，用 function calling**；**Decisions 只适合有界答案**。**依赖前一步答案的判断，官方要求拆成多次请求**。

### 3. 谷歌把 agent 的「电脑」做成了云产品：Agent Compute Engine
- **发布场合**：**10 月 22 日圣何塞 AGNTCon + MCPCon**，**和 Gemini 企业版是一套东西**。
- **它解决什么**：**agent 的会话是「启停—等待—恢复」的高频模式，传统算力原语不是为这个设计的**；**Agent Compute Engine 给每个 agent 一台 microVM**，**快速启动，空闲时快照挂起、需要时从快照恢复**。
- **密度靠共享内存**：**用 copy-on-write 让多个 agent 跑在同一份操作系统模板上**，**一个物理机上能塞下更多 agent**。

- **开源的那一半**：**Agent Substrate 跑在 GKE 上，零信任、开源**，**空闲时快照内存、把机器还回池子**——**不想用托管服务的团队可以自己搭**。
- **时间表**：**「未来几个月」进入预览**，**目前已经在给 Gemini 的工作任务供能**。

### 4. 1Password for Agents：把「给 agent 密码」换成「替 agent 登录」
- **10 月 22 日发布**。**要解决的具体问题是**：**agent 一旦把密码写进上下文或磁盘缓存，这份秘密就脱离了你的控制**——**模型记忆、服务端日志、提示词抽取，任何一条路都能把它带出去**。
- **怎么工作**：**agent 用自己的数字密钥向 1Password 证明身份 → 用户收到通知并人工确认这次操作是本人授意 → 1Password 自己完成登录，把凭据填进会话，明文不进模型记忆**。
- **首批接入**：**Anthropic 的 Claude Duet、OpenAI 的 Dots 与 ChatGPT Work、Grok Bot、Meta 的 Muse，以及 Town 的 agent**。
- **它没解决的那一半**：**登录只是前门**；**一旦会话凭证生效，agent 就对目标页面拥有了完整的交互权限**——**它不需要知道密码，也能转账、改找回方式**；**而页面里任何一段内容都可能是间接提示注入的载体**。
- **还有一个设计上的软肋**：**人工确认在重复几十次之后会退化成条件反射**，**两年前推送式 2FA 疲劳攻击就是同一个机制**。

### 7. KLS 猜想：31 年悬案，被「人带 agent」的搜索破掉
- **结论**：**微软研究院的张新智（Xinzhi Zhang）与合作者宋昭（Zhao Song）证明 1995 年提出的 Kannan–Lovász–Simonovits 猜想**——**对一大类高维对数凹分布，最好的平面切割与任意形状的最好切割之间，差距被一个不随维度增长的常数界定**；**论文《An O(1) Bound for the KLS Constant》140 页，10 月 1 日投 arXiv、10 月 4 日修订**。
- **为什么重要**：**随机游走探索分布的快慢由这个几何量决定**，**它撑着采样、体积计算和凸优化的一批算法**；**此前最好的结果是 2026 年 7 月的 O(log^{1/4} n)，界仍随维度缓慢增长**。
- **怎么破的**：**先找到一个新判据，再把判据递归套用**；**10 月 1 日版把维度依赖压到迭代对数，10 月 4 日版把整个递归再跑一遍，并证明每一步引入的误差总和仍被常数界住**——**「重复递归」这个想法来自两位作者此前做线性规划快速算法的工作**。
- **人机分工写得异常清楚**：**AI 负责探索候选路径、做冗长推导、协助写稿、跑内部证明检查**；**人负责定方向、挑想法、组装最终论证、验证证明**；**「递归方法本身、它的重复、误差有界这三件，是作者自己的贡献」**——**微软没有公布用的是哪些模型**。
- **最有价值的一个细节是那次对照**：**作者另开一条线，用多个前沿模型、在相近 token 预算下反复无引导地尝试同一个问题，没有成功**；**主线上探索了 100 多条候选路径、约一百条研究轨迹才出现关键突破**。
- **同一天还有两件事**：**Bizeul、Klartag、Lehec 独立给出完整证明，摘要里写明「关键一步来自 Song 与 Zhang 的新判据」，致谢里写「本文大部分证明与数学想法由 ChatGPT 找到」**；**第三份证明与一个 Lean 4 形式化也在同一天出现**。
- **该保留的怀疑**：**对照实验目前只是博客里的一句话**，**模型、次数、token 都没披露**；**已发布的形式化混入了其他工作，不是对这一份证明的机器检查**；**作者自己的 Lean 版要等终审后才放**。
- 来源：[Microsoft Research：Solving a 31-year-old grand challenge in mathematics（官方）](https://www.microsoft.com/en-us/research/) · [Unite.AI：论文信息、递归细节与时间线](https://unite.ai/microsoft-researcher-and-collaborator-prove-31-year-old-kls-conjecture) · [Lilith AI：对照实验的三处不可复现性](https://lilithai.dev/radar/solving-a-31-year-old-grand-challenge-in-mathematics-the-kls-conjecture?lang=en) · [TSNMedia：并行证明与 Lean 形式化的边界](https://tsnmedia.org/microsoft-kls-conjecture-ai-proof)

### 9. Tev：给长程 agent 造「可验证、稠密、渐进」的奖励
- **痛点很具体**：**现有开源 agent 语料每个任务只是一次 PR 级修复或一段短终端会话，前沿 agent 跑完的中位耗时不超过 2 分钟**；**真正的长程任务只存在于人工评测基准里，几十到几百道题，只用于评测、不用于训练**。
- **第二道坎是奖励稀疏**：**奖励只在提交时出现**；**GRPO 在整组 rollout 全失败时优势值全为零，这组样本就白跑了**。
- **他们做了什么**：**UCLA 与 Adobe Research 先造「答案世界」再出题**，**建了 Tev-Gym，1,170 个环境、覆盖 7 个领域**，**提出进度势能奖励塑形（PPRS）**。
- **结果**：**Tev-27B 在 Agents' Last Exam 计算与数学子集（ALE-CM）上 Pass@5 0.28，与 GPT-6 Astra、Claude Opus 5 持平**；**同配方训的 Tev-320B 是 Terminal-Bench 4.0 该子集上最强的开源模型**。
- **一句话判断**：**「环境先行、奖励稠密」这条路一旦跑通，长程能力的瓶颈就从模型转到数据工厂**。
- 来源：[arXiv 2610.18868](https://arxiv.org/abs/2610.18868) · [机器之心 Pro：环境构成、PPRS 与结果](https://www.toutiao.com/article/7699310500777181747) · [项目主页](https://tev-agent.github.io/)

### 10. 一个让人不太舒服的发现：模型知道谁把事搞砸了，但不说
- **研究问题**：**自动失败归因（AFA）**——**把一次多 agent 协作的失败追溯到具体哪一步**，**现有做法是让足够强的模型当裁判直接读交互记录**。
- **实测表现很差**，**作者去查了内部激活**：**线性探针显示，模型内部已经编码了足以正确归因的信息，但就是不显式输出**——**论文把它叫「知道但不说（knows-but-won't-say gap）」**。
- **据此提了个极简干预**：**grafting，把已编码的知识直接接到输出上，推理时不需要 ground truth**；**在多个模型与基准上稳定优于直接提示**。
- **为什么值得单列**：**「模型说不知道」和「模型不知道」是两件事**；**如果这个差距在多 agent 系统里普遍存在，那么所有用 LLM 当裁判做归因的流水线，测的都是表达能力而不是判断力**。
- 来源：[arXiv 2610.28811](https://arxiv.org/abs/2610.28811) · [BitTide：探针方法与 grafting 结果](https://bittide.aicompass.dev/article/d0954abe-b741-467b-809f-77ae490c6b10)

### 12. IT-Bench / MAST 给「agent 靠不靠谱」第一次上了数字
- **IBM 与 UC Berkeley 的工作**：**失败不是随机的，而是有可分类的模式**；**前沿模型每次轨迹平均有 2.6 种失败模式，大型开源模型会连锁放大到 5.3 种**。
- **结论一句话**：**前沿 agent 的可靠性天花板大约在 60% 附近徘徊**，**卡住的是「不把事情搞砸」，不是「会不会做」**。
- **为什么这个数字比任何 benchmark 分数都重要**：**60% 意味着每五次执行就有两次需要人接**——**这决定了 agent 能不能无人值守，而不是能做什么任务**。
- **同期另一个方向相反的结论**：**新基准与一组 GRPO 结果显示，长程 agent 的失败主因不是推理弱，而是记忆陈旧**，**而且「事实时效性」可以被训练成一个目标，效果优于改检索**。

### 19. Node.js 也中招：Brotli 解压出远程执行，找到它的是 OpenAI 的团队
- **漏洞**：**CVE-2026-111497，Node.js 内置 Brotli 解码器的越界写，官方评级 high，可导致远程代码执行**；**10 月 21 日安全版本 22.23.4、24.22.1、26.12.1**。
- **同批还有九个**：**两处 TLS 主机名校验绕过（CVE-2026-106069、CVE-2026-105483，后者的异常写法涉及 IP 地址）、dns.resolve 在 NUL 字节处截断主机名（CVE-2026-105482）、ZipFile 问题（CVE-2026-106070，仅 26.x）**；**并更新了内置证书列表以应对 eMudhra 中间 CA 失陷**。
- **谁发现的**：**Node.js 致谢的是 OpenAI Codex Security 的 Khai Tran 与 Sylvie Mayer**——**这是继 PHP2Shell 之后，同一批人两天内第二次在语言运行时里挖出可远程执行的高危洞**。
- **暴露面在哪**：**应用解压攻击者可控的 Brotli 数据就中招**，**一是直接用 node:zlib，二是代码对带 Brotli 压缩的响应调 fetch() 时自动解压**；**修的是运行时本身，升依赖没用**。
- **PoC 的实际强度**：**10 月 22 日公开的 PoC 只在人为弱化的测试构建上跑通**，**标准构建上作者只报出崩溃与有限的内存读取**；**截至 10 月 22 日无在野利用**。
- **升级清单**：**服务器、容器基础镜像（自带一份 Node）、CI 构建机、开发机、Docker 镜像**；**20.x 及更早已 EOL，没有补丁，只能迁**；**编译时链接系统 Brotli 的环境要确认包含上游 commit 0ed4268**。
- 来源：[Beazley Security Labs：CVE 细节、修复版本与致谢](https://labs.beazley.security/advisories/BSL-A1236) · [Protect.Computer：十个漏洞清单与 PoC 强度](https://protect.computer/news/2026-10-22-nodejs-brotli-rce-security-release) · [中央社：资安署要求限期清查](https://www.cna.com.tw/news/afe/202610220142.aspx)
