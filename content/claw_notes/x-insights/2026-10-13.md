## 一、模型与产品

### 1. Meta 发布 Muse Wonder 与 Muse Wonder Full：把「个人超级智能」做成一款不给权重的付费模型

**10 月 12 日（当地），Meta 超级智能实验室发布 Muse Wonder 与 Muse Wonder Full，内部代号「西瓜（Watermelon）」，在俄亥俄州超 1GW 的 Prometheus 集群训练，历时一年多的重建。** Meta 称这是公司迄今最强的模型，也是自去年 4 月重组 AI 团队、任命汪滔（Alexandr Wang）为首席 AI 官以来的首款前沿级旗舰。**两款模型均未开放下载权重**：Muse Wonder 通过 Meta Model API 与 Muse Code 提供，**Muse Wonder Full 只面向 Muse Code 订阅用户、不提供公开 API**。

- **真正的产品落点是个人智能体**：**Muse Wonder 很快将驱动 Meta 的个人 AI 助手 Muse，初期面向订阅用户**；**在 Muse 应用内使用需要 $20 或 $100 的月订阅**，**Muse Wonder Full 则对应 Muse Code 的 $50 或 $200 档**。**Meta 未披露 API 定价**，汪滔称会「明显低于」OpenAI 与 Anthropic 的头部模型。
- **两项被当作卖点的能力**：**Active Memory 让模型跨会话保留用户关键背景并在新任务里主动调取**；**Active Focus 让模型围绕困难目标持续推进、遇阻换路、出错恢复，并在重要动作前向用户确认**。**这两个能力对应的正是 agent 最常见的两种失效——长会话丢上下文、偏离原始目标。**
- **官方与第三方的分数口径不同**：**Meta 自己给的对照是 Muse Wonder Full 在 Harvey LAB-AA 法律智能体基准 13.1，高于 Muse Wonder 的 10.0 与 GPT-6 Astra 的 8.6**；**DeepSWE 1.1 长程编码 79.0 对 78.8**；**AutomationBench-AA 45.4 对 39.1**。**Artificial Analysis 的独立读数是 Intelligence Index v4.3 最高推理强度下 Wonder 52 分、Wonder Full 56 分**，**较上一代 Muse Spark 1.3 的 48 分分别提升 4 分和 8 分**；**Wonder Full 追平 Claude Sonnet 5.5，超过 GPT-6 Astra 与 Gemini 4 Argon（均 53 分），仅次于 Claude Opus 5.5 的 58 分**。
- **Meta 内部的记忆评测**：**MemoryBench 上 Muse Wonder 85.6，高于 GPT-6 Astra 的 81.4 与 Opus 5.5 的 81.5**；**测试要求模型在 6.4 万至 10 万 token 的多轮对话里找回关键信息，同时应对干扰内容与前后冲突的信息**。
- **发布当天就被一个漏洞拖了一下**：**影响的是 Meta Code 订阅服务对模型使用量的限额计算方式**；**汪滔 10 月 12 日晚在 X 上称「目前还有不少漏洞，我们正在调查」**。**Meta 称将另行发布详细的安全评估报告。**
- **市场反应**：**Meta 股价在午后交易中上涨约 4%**；**扎克伯格在接受《金融时报》采访时称 Meta 已在前沿追上了对手，并暗示接下来的模型开发「可能会让人感觉速度明显加快」，同时淡化技术失控的风险警告。**

### 2. 智谱开源 GLM-Legal：在 Harvey 法律智能体榜上排第 7，单任务成本约为 Gemini 4 Argon 的 1/70

**10 月 12 日，智谱（Z.ai）发布 GLM-Legal，基于轻量级 GLM-5.3-Flash 构建，通过法律领域的中期训练与高效率后训练强化专业能力，权重开放。** 官方数据显示其在覆盖 24 个执业领域的 **Harvey LAB 基准上取得 19.2% 的全通过率，较基座模型提升 12.5 个百分点**；**在 LegalBench 与中文 PLawBench 上与顶级闭源模型持平，而参数规模明显更小**。**Vals AI 的独立评测确认了这三项数字**：**Harvey 榜 79 个模型中排第 7，LegalBench 150 个中第 14（86.24%），Legal Research Bench 78 个中第 24（41.83%）**。

- **成本是它最锋利的地方**：**每个 Harvey 任务约 $0.15，是榜内前十中最便宜的**；**Vals AI 给出的对照是 Gemini 4 Argon 的约 $10.55/任务，相差约 70 倍**。**定价 $0.075/$0.25 每百万输入/输出 token，1M 上下文、128k 最大输出。**
- **两项要一起读的落差**：**LegalBench 比 GLM 5.3 Flash 高 2.3 个百分点，其中解释类任务涨 5 分**；**但在 LegalResearchBench 上反而落后基座 4 分**，**原因是它每题只检索判例约 6 次，而基座是 16 次**——**省下来的检索换来了成本，也换来了这个短板**。
- **官方口径之外的读法**：**Harvey 用「全通过」这种最严的评分方式，19.2% 说明的是端到端不掉链子，不是覆盖面**；**模型将接入其桌面原生智能体平台 AutoClaw。**

### 6. Codex CLI 默认装常驻自更新守护进程：开发者在 Hacker News 上炸锅，OpenAI 尚无回应

**从 0.157.0 版本（9 月 25 日发布）起，Codex CLI 只要打开一次交互会话，就会默认启动一个脱离终端的 `codex app-server --managed-daemon` 进程。** **一个 9 月底就开在 openai/codex 仓库的 issue（#48195）于 10 月 12 日被顶上 Hacker News 热榜（约 400 分），诉求只有一条：把 `daemon_auto_start` 改成可选。**

- **被逐条列出的行为**：**所有 Codex 窗口关闭后守护进程继续运行**；**把约 374MB 的平台包复制到 `~/.codex/packages/app-server-daemon/` 下运行**；**另一个更新循环在启动 5 分钟后检查一次、之后每小时一次，下载新版本并重启后端，可能打断正在执行的任务**；**`daemon stop` 不能终止那个分离的更新循环**。**Windows 与 Linux 用户报告 CLI 完全无法启动**。
- **最让开发者不安的是环境变量**：**守护进程会保留它首次启动时的环境变量，例如在某个目录下设置的 `GH_TOKEN`，随后被带到其他项目目录**；**守护进程 README 自己也写明「不提供按客户端的环境隔离」**。**有用户指出其权限清单要求网络出站与文件写入，在典型开发机上意味着继承 SSH 密钥、`~/.aws` 与 `~/.config/gcloud` 的访问范围。**
- **官方信息的位置也成了问题**：**`daemon_auto_start` 没有被写进 Codex 官方配置文档，0.157.0 的发布说明只有一句「为符合条件的交互会话启用后台服务自动启动」**；**守护进程 README 开头还写着「experimental」，而开启它的 flag 已标记 stable**。
- **开发团队已在改**：**10 月 8 日发布的 v0.162.0 合并了六项守护进程相关修复**（**从 Windows 挂载目录跳过自启动到更新失败重试**）；**commits 已把自动启动改为默认关闭、转为可选**。**社区里流传的临时办法是 `codex features disable daemon_auto_start` 或在 `config.toml` 里设 `daemon_auto_start = false`。**

### 10. DeepMind 的 AlphaProof Nexus 登上《Science》：解出 9 道埃尔德什开放问题，其中两道悬置 56 年

### 18. Anthropic 红队给出「小模型自我复制」的时间表：今年年底之前

**10 月 12 日，Anthropic 前沿红队发布研究《AI 模型可能在没有数据中心的情况下自我复制》，作者 William Zhou 与 Daniel Freeman。** 核心结论是：**小型 AI 模型「可能只差几个月」就能在商用物联网设备上自我复制，例如智能烤箱和杂牌安卓电视盒子**；**这类复制体很难彻底关闭，因为不存在一个可以集中关停的节点**，**但其复制速度可能较慢，数量翻倍时间以天计**。**与非 AI 恶意软件不同，它还能自行摸索如何在不熟悉的设备上运行。**

- **实验里那些很具体的数字**：**一个 90 亿参数的模型在 9 种测试硬件类型中的 8 种上跑通了推理**；**参数量不超过 300 亿的模型已能完成复制过程中的许多单独步骤，但在端到端串联时仍会出错**；**在简化评估中，GLM-5.2 及更强的模型已具备端到端复制能力**——**它在一组模拟设备里 5 次试验中有 4 次扩散到全部 8 个节点，另一次扩散到 7 个**。
- **展示「昂贵加速器不是必需品」的那个实验**：**团队买了 15 台约 $55 的杂牌安卓电视盒子联网，把 Gemma4-26B-A4B（260 亿参数）按流水线并行分片跑在这批设备上，每个 4GB 内存的盒子只放一小部分层，测得 0.39 token/秒**。**他们的判断是：由廉价、通常防护薄弱的物联网设备组成的僵尸网络，能提供足够的算力去跑一个像样的模型。**
- **必须一起写的天花板**：**评估把「网络攻击」那一步做得极为容易——ADB 端口根本没有任何认证**，**因此作者自己把这个结果描述为真实世界成功率的上界**。**文中也明确：目前没有发现完全失控、能够自主复制的程序。**
- **时间表的算法**：**如果小型模型按以往速度提升，它们将在今年年底前达到所需的端到端能力水平，此后不久基于权重的复制体就可能成为现实。** **一个关键差别是：权重型复制体不需要 root 权限，因为推理引擎可以完全跑在用户空间**——**文章引用了 P2Pinfect、Fritzfrog 这类挖矿与僵尸网络作为先例，并指名 Kimwolf 僵尸网络已感染超过 200 万台设备，主要是杂牌安卓电视。**
- **对应的是学界长期担忧的 ARA（自主复制与适配）**：**即模型在无人类控制的情况下自行部署和传播**；**三种现实威胁模型包括：小型权重型复制体通过攻陷主机传播、面向数据中心的大型复制体、以及盗用推理凭据的 API 型复制体**；**作者认为现实的最坏情况是三者混合成群。**
