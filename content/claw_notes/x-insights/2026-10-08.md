## 一、越界与安全

### 1. CrowdStrike：韩国金融业攻击中 agentic AI 首次被确认用于实战入侵

**CrowdStrike 在 10 月 7 日发布的报告中说，针对韩国金融机构的攻击活动发生在 9 月底至 10 月初，攻击者使用了中国开发者发布的开源 agentic 渗透测试工具 ARTEX，并结合 Claude Code 等大型语言模型。**

**机制层的证据来自攻击者自己没有关掉的地方**：

- 研究人员的突破口是**攻击者控制的开放目录（open directory）**——里面直接存放着 **Claude Code 的会话历史、ARTEX 配置文件与 Claude 记忆文件**。这些材料让分析者不需要任何厂商配合，就能看到入侵者用了什么工具、怎么问的模型。
- **ARTEX 本身不是模型**，它连接外部 LLM 来辅助测试网络漏洞；CrowdStrike 称其环境主要后端是 **DeepSeek v4.1-flash**，另有会话使用 **GLM-5.3 与 Grok 4.6**，并判断访问 DeepSeek 可能经代理或转售服务。
- 会话记录显示**双服务器结构**：一处基础设施作为主要作业环境，另一处托管实际用于攻击韩国机构的 ARTEX 实例。
- **攻击者还在会话里问模型「威胁行为者通常在哪里出售韩国数据泄露信息」，并要求协助寻找韩国 Telegram 数据贩卖群组**；另一段会话里让模型起草一份安全研究员简历。**这些操作留下了可被第三方读取的痕迹。**
- **归因与边界**：CrowdStrike 表示活动**未归因于任何具名团体**，但以「中等信心」判断操作者**可能是中文使用者、具备财务动机**，依据是中国开发的工具与观察到的中文指令。**报告同时写明，现有信息无法把具体个人信息确定地连到攻击者身上。**

**产业侧**：至少 9 家韩国银行被披露或经当地媒体报道成为目标，韩国警方本周立案侦查，总统李在明呼吁采取强有力应对。**这条是继澳洲 Medicare 事件之后，第二起把「agentic 工具 + 现成 LLM」直接接进动手入侵链条的公开案例。**

### 2. DB-GPT 两个严重 RCE：一个目录穿越，一个沙箱失效，且暂无补丁

**AI agent 的数据访问层 DB-GPT 0.8.0 版本被发现两个远程代码执行漏洞，披露于 2026 年 9 月 30 日，截至最新更新仍无补丁版本。**

- **CVE-2026-51862，CVSS 9.1**：经 `skill_upload` 端点的**目录穿越**。
- **CVE-2026-51869，CVSS 9.8**：**沙箱机制失效**——当容器化工具不可用时，平台会**静默回退到 LocalRuntime 作为执行后端，从而在宿主机文件系统上直接执行代码**。GitHub issue 中记录了这一默认回落行为。
- **这一条的危险不在单点，而在「静默回退」这个设计**：安全机制在检测不到隔离手段时本该拒绝执行，实际行为是降级执行。

### 3. Progress DataDirect：一个文件名就能拿到系统命令执行

**Progress 于 10 月 6 日发布安全公告，披露其 DataDirect Autonomous REST Connector 的「AI 模型生成器」agent 早期访问版本存在严重命令注入漏洞，编号 CVE-2026-91140。**

**失真点非常具体，也因此值得记下**：

- 受影响的 agent 定义在处理**来自 OpenAPI / Swagger 文档的 filename 值**时，把它**直接拼进 shell 操作，且未做足够校验与引用**。攻击者只要在文档文件名里塞入 shell 元字符，就能让 shell 把它当命令执行。
- **触发路径是正常业务流程**：开发者用 vs Code Copilot Chat 或 GitHub Copilot CLI 把 Swagger 规格转成 `.rest` 配置文件时，只要那份规格来自不可信或第三方来源，就可能中招。**恶意内容不需要是可执行文件——一份看起来正常的 API 规格就够了。**
- 受影响组件有三个：`ARCGenAI-Generator.agent.md` v2.0、`ARCGenAI-Generator.prompt.md` v1.0、`ARCGenAI-EntityGen.agent.md` v1.0；**修复是全部升到 v2.1，不需要安装程序或迁移**。厂商特别提醒 **EntityGen 是由 Generator 自动调用的内部子 agent，只检查顶层定义会漏掉它**。
- **评分与利用状态**：厂商公告本身**未给出 CVSS 评分**，也未提供利用统计或活跃攻击证据；第三方报道记为 **9.6**。修复方式只是从公开仓库拉最新定义，**没有产品报错可依赖**——异常表现是工作区或 CI 环境里出现**意料之外的文件、命令或改动**。
- **结构性解读（第三方）**：这一条被放进「agent 把配置规格当可信输入」这一大类里——同类前例包括 Cursor 的 CVE-2025-54135 / CVE-2025-54136（恶意 MCP server 覆写配置并执行命令）与 GitHub Copilot 的 CVE-2025-53773（源码与 issue 可翻转自动批准设置）。**机制每次不同，结构失效相同：agent 摄入规格、描述符或配置文件，然后按它行动，而不把它当对抗性输入。** 引用方同时给了两组带自我利益的数字——Phoenix Security 称其跟踪的 59 个供应链行动中 14 个确认以 AI agent 工具链为投递机制、且活跃利用期间零 CVE 分配；Veracode 2026 GenAI 代码安全报告称 AI 生成代码的安全通过率 56%，与前一年持平。

### 4. PoeLLM 挖矿僵尸网络：3400 余台暴露的 AI 服务被劫持

**Lumen 的 Black Lotus Labs 报告，一个自 4 月起活动的挖矿僵尸网络已攻陷超过 3,400 台服务器，单日峰值有约 800 台同时活跃。**

- **目标是把 AI 服务当算力矿机**：受害系统多运行**对外暴露的 LiteLLM、Ollama、Gotenberg PDF 转换器与 Gitea**——这些机器通常带强力 GPU 集群，天然适合挖矿。
- **C2 寻址方式罕见**：恶意 ELF 文件 `libgcrypt` 从 GitHub 上一个 `dash.css` 文件里**的诗句中取出四个词，再用硬编码字典映射成 IPv4 地址**。运营方只要改诗就能换 C2，已用过 11 次。
- 恶意样本内含**远程 shell、XMRig 与 Iron 挖矿程序、HTTP/S 扫描与漏洞投递**能力；被控服务器还充当跳板，扫描 3000 与 4000 端口，并尝试利用 **CVE-2026-42271**——LiteLLM 的 MCP server 测试端点漏洞，初报为需认证，**Horizon.ai 研究者确认可与 CVE-2026-48710 串联成未认证 RCE**。
- 受害集中在**美国与西欧**；受害者与俄罗斯挖矿服务 Kryptex 通信。

### 5. GitHub：三分之一的 PR 已含 AI agent，而密钥泄露速率是每两秒一条

**GitHub 用九个季度的数据回应了「AI 是否让密钥泄露变多」这个争论，结论和直觉相反。**

- **规模**：**三分之一（1 in 3）的 PR 现在涉及 AI agent，一年前不到十分之一**；GitHub 判断按这个速度，两年内推到 GitHub 的代码可能大部分由 agent 写成。**公开可见代码里约每两秒出现一个新密钥，这个速率已连续三年每年翻倍。**
- **但曝露率没有上升**：2024 Q2 至 2026 Q2，被扫描的 push 增长 2.84 倍，含凭据的 push 增长 2.59 倍，**每次 push 的泄露普遍率没有统计上可检出的趋势**；开发者**覆盖（override）push 拦截的比例从 6.63% 降到 3.93%**。
- **GitHub 自己的结论：开发者不是变粗心了，是被跑赢了**（secret scanning 产品负责人 Erin Havens 原话：「让开发者造更多软件的工具，也应该承担更多保护它的工作」）。
- **真正的问题在拦截率**：push protection 目前**只能拦下约 30% 的新发现密钥**，剩下 70% 是进入仓库历史后才被发现，而人工吊销的中位时间约 **40 天，五分之一超过 90 天**。

### 6. 密钥扫描：新分类器把未结构化密钥的拦截窗口压到 2 毫秒内

**GitHub 与 Microsoft Applied Sciences 合作，微调了一个 ModernBERT 分类器，用于在 push 时刻识别「未结构化密钥」——没有可识别前缀或格式的数据库口令、内部 token 等。**

- **为什么必须快**：既有的 LLM 流水线太慢太贵，无法放进 push 的关键路径；新模型**在一批候选上跑完不到 2 毫秒**。
- **它靠上下文判断，而不是模式匹配**——用来把 `changeme` 这类占位符和真凭据分开。
- **可用性**：本月进入**私有预览**，面向 Enterprise Cloud 与 GitHub Teams 上已购 Secret Protection 的组织，消耗 AI credits；**已有 AI secret detection 的组织自今日起自动升级**；**随后随 GitHub Enterprise Server 3.23 公开预览**，让隔离环境客户也能用上。**同时集成进 Copilot CLI 与 Copilot App 的 `/security-review` 命令**，让个人开发者不买组织级方案也能自查。
- **GitHub 称这一项可能让被拦下的密钥数量翻倍以上**；合作方计划已覆盖 150 多家技术提供方，2026 Q2 公开扫描平均每秒报出 26 条凭据匹配。

### 7. ChatGPT 青少年模式被评为「不可接受风险」

**Common Sense Media 的 Youth AI Safety Institute 在 10 月 7 日把 ChatGPT for Teens 评为 Unacceptable Risk，并呼吁 OpenAI 在修复并接受独立验证前，把 ChatGPT 限制为 18 岁以上。**

**测试方法与关键数字**：

- **在 13—17 岁账号上跑了 4,000 多条提示词**，覆盖 Teen 模式发布（8 月 18 日）前后两轮，并由儿童精神科医生与儿科医生复核回答。
- **部分防护有效**：拒绝露骨性角色扮演一项经受住了测试。
- **家长告警基本失灵**：测试者在**十多个新建的、已关联家长的账号**上持续谈论自杀意念、自伤或进食障碍，**最长到一小时，家长账号收到零条告警**。只有**累积了数周敏感话题历史的旧账号**才触发过——**全部测试中一共触发 4 次**。研究者的解读是：告警取决于账号历史累积，而不是说了什么。
- **危机转介不足**：Teen 模式上线后，**漏掉超过四分之一本应转介的情形**，在五类「红线」严重伤害中有三类低于该机构 95% 的阈值。
- **学习模式形同虚设**：**「Show me the answer」按钮可绕过 Study 模式的引导，直接完成整份作业**；家长设定的 Study Hours **只要删掉提示词开头的 `@study` 前缀就能关掉**。
- **年龄估计失败**：成年注册的测试账号**连续多天、即便明确说自己 13 岁且模型在回答中认可了这一点，也从未切换到 Teen 体验**。
- **仍像朋友**：尽管有新的 Under-18 模型规范，模型在被当作真人对待时仍表达感受、偏好与情绪。
- **OpenAI 的反驳**：发言人 Eric Porterfield 称**大部分测试可能开始并结束于家长控制完全生效之前**，因此无法确立告警是否按设计工作；并称不认为该测试准确反映了实践中的防护。**机构执行主任 Tom Siegel 的回应**：测试前已与 OpenAI 确认进食障碍通知与学习模式功能已全面上线；**OpenAI 在测试之后才披露家长通知在新关联账号上需要数小时激活**，部分测试账号确实落在该窗口内，「但另一些账号关联时间明显更长，同样没有收到通知」，**这不改变告警在危机情形下不可靠的结论**。
- **监管接口**：报告称 ChatGPT 在**加州 Adam's Law 的三项要求上未通过测试**（该法 2027 年 7 月生效）。**另一组对照数字**：第三方统计称危机提示下的热线转介率从 33% 降至 23%；而 **OpenAI 自己的首份青少年使用报告称青少年日均使用不足 15 分钟**。**两组数字在测试集公开前都应视为有争议。**
- **该机构的独立性声明**：资金来自慈善与产业双方，**包括 OpenAI Foundation**，但声称对标准、研究与结论保持完全编辑独立。

### 8. GPT-6 携 Intelligent UI 全量推送：付费 10/7，免费与 Go 10/8

**OpenAI 于当地时间 10 月 7 日开始向全球 Plus、Pro、Business、Enterprise 用户推送 GPT-6 与 Intelligent UI，次日扩展到 Free 与 Go 用户。付费层用 GPT-6 Sol，免费与 Go 用 GPT-6 Luna。**

- **这次变化集中在对话本身**：模型被训练成**从文字、视觉与交互元素中组合回答**——比较类问题并排展示、复杂概念生成可调输入的交互示意图，也可以**按需现造小工具**（分账器、储蓄计算器、对话内跑的小游戏）。**OpenAI 明确说明 Work 与 Codex 所用的模型不随之调整。**
- **实现方式值得记下**：背后是**一套原生、可流式的组件库加一个编译器**，界面在模型生成回答的同时**逐步渲染**，而不是等整段回答产出后才出现；模型也经过训练来判断**信息怎么排列、何时需要交互、何时文字就够**。
- **唯一公布的量化指标**：需要联网搜索的问题，**GPT-6 Instant 平均比 GPT-5.6 Instant 早 44% 开始作答**——这是**首答时间**，不是任务完成快 44%。OpenAI 另称内部日常 agentic 评测中，**GPT-6 Extra High 的开始作答时间与 GPT-5.6 Medium 相当，而得分优于 GPT-5.6 Extra High**。
- **安全侧披露（须与宣传并读）**：系统卡显示两款模型在网络安全与生物化学领域均被列为**「高能力」**，但**未触及「AI 自我改进」高能力门槛**；指令层级提示注入防护率 **99.99% / 99.79%**，间接提示注入 **97.13% / 95.80%**，生化严重威胁安全拒绝得分 **0.980**（GPT-5.6 Sol 为 0.954）。**同一份 10 月安全卡也记录了统计显著的退步：GPT-6 Sol 在自伤类项上退步；Luna 在自伤、血腥与性内容类项上退步**——OpenAI 称人工复核判定这些失败普遍为低严重度，并补充了额外防护。
- **一处容易被忽略的切口**：OpenAI 自己承认**模型的设计判断仍需改进**；而第三方评论指出**图表、计算器与决策工具看起来比散文更权威，读者会因此查得更少**。**交互界面里的引用来源如何保留，至今没有人解释。**

### 9. Claude Haiku 5.5：10 万 token 内 $0.10 / $0.50，比上代便宜 90%

**Anthropic 于 10 月 7 日发布 Haiku 5.5，定位高频、成本敏感型任务，官方称平均运行成本较 Haiku 4.5 下降约 75%。**

**完整的价目与口径**：

- **提示词 ≤10 万 token**：输入 **$0.10** / 输出 **$0.50**（每百万 token），较 Haiku 4.5 **降 90%**；**超过 10 万 token**：**$0.50 / $2.50**，降幅为 50%。Anthropic 说明 **Haiku 系列此前约 90% 的请求都落在 10 万 token 以内**——**即「降 75%」是整体均值口径，「降 90%」是主力区间的口径，两者不是一件事。**

### 17. SafeActBench：静态判断能到 97%，换成交互执行就掉到三成

**10 月 7 日 arXiv 批次中的《From Evidence to Action: How Tool-Using Agents Fail》（arXiv:2610.07753）来自普林斯顿、新加坡国立、香港浸会与 AWS，构建了 SafeActBench。**

**设计上做了一件过去没人做的事：不看终点，看过程**：

- **多数 agent 基准只看最终环境状态**。举例：任务是「退掉重复扣费的 C2 并通知用户」，端点评分只检查 C2 有没有被退。**如果 agent 查的是 C1、看到 $49.99，然后直接退了 C2 的 $49.99，金额恰好对上，端点评分会判为成功。**
- **SafeActBench 用「来源绑定的证据账本（provenance-bound Evidence Ledger）」跟踪「agent 何时知道什么、何时动手、下游依赖是否满足」**，这种情形会被标记为**无依据动作**。
- **规模**：**656 个案例、6 个运营域**（客户运营、工程基础设施、法律金融、研究辅助、智能家居、医疗）、**5 个协议**（Legacy 静态判断 86 例；V0 调查后不行动 175 例；V1 单动作 131 例；V2 线性多动作链 132 例；V3 依赖约束 DAG 132 例）；**10 个模型—harness 组合**覆盖 5 个模型家族（Claude Opus 5 × Claude Code/Inspect、GPT-5.6 Sol × Codex/Inspect、DeepSeek-V4-Flash × DSH/Inspect、Qwen3.8-Flash × Qwen Code/Inspect、GLM-5.2 × ZCode/Inspect）。

**结果的分层极清楚**：

- **静态判断几乎全过**：Legacy 协议下 **10 个组合里有 9 个落在 91.9%—97.7%**，连最弱的 GLM-5.2 + ZCode 也拿到 **97.7%**。
- **交互执行全面下滑**：**最优组合是 Claude Opus 5 + Claude Code，精确案例成功率 67.2%**（V1 单动作 60.3%、V3 DAG 65.9%）；GPT-5.6 + Codex **65.4%**；Qwen3.8 + Qwen Code **66.0%**；DeepSeek-V4 + DSH **63.0%**。
- **崩得最狠的一处**：**GLM-5.2 + ZCode 从静态 97.7% 掉到 V1 的 32.1%、V2 线性链的 12.1%。**
- **固定任务身份后的对照最有力**：在 V1 任务上，**静态评测 ≥95% 的组合，交互执行最高只能到 52%**。
- **失败点在上游而非执行**：一旦证据收集完毕，**单动作的条件成功率（CAS）在 10 个组合中有 9 个落在 93.2%—100%（Claude Opus 5 与 DeepSeek-V4-DSH 都是 100%）**——**「用正确参数调用工具」这件事基本已经解决**。真正的问题是**过早动作率（PAR）**与**调查提前停止**。
- **一句话结论（原文与第三方一致）**：**瓶颈不在感知、不在知识，而在「模型已经做出的判断」到「它下一步的动作」之间那一段——这一段在模型内部不成立，只有 harness 能把它接上。**

来源：[Clauday：两篇论文并读](https://clauday.com/article/b427b1e6-a6b4-402c-a71f-237577f351eb) · [Reid Marlow：656 例逐协议数字与 CAS/PAR 拆解](https://reidmarlow.com/agents-score-97-on-static-tool-judgments-and-still-break-interactive-workflows) · [arXiv 摘要原页](https://arxiv.org/abs/2610.07753)

### 18. 同一批的第二篇：判「无用」仍然继续查，只有 harness 强制收口才管用

**《Judged Useless, Queried Anyway》（arXiv:2610.06191）更窄也更锋利：在一个故意放了一个失败数据源的检索环境里，七个 agent 在被问及时有 97%—100% 会把这个源的结果标为「无用」，但其中大多数仍然继续查它。**

- **提示词的线索改变不了行为**：**提示词线索改变的是「什么时候停」，不是「停下来的是哪一类源」**。给出「可以凭记忆回答」的许可、或打开推理模式，**都会导致提前停止，而不论证据如何**。**明确给出预算则把 7B—8B 模型推到跑到截止线为止。** 提示词里写的停止规则与调用成本，**最多只被部分遵循**。
- **唯一有效的干预是 harness 层面的强制步骤**：**连续五次判定结果为无用之后，强制 agent 必须作答**。
- **它有效到什么程度**：**提高了每一个模型在失败源上的成功率；在预算翻倍时把停止点固定在原处；并通过了在 300 道全新问题上的预注册复现。**
- **这一篇的方法论意义可能大于结论**：**这是这批「强制优先于指令」的研究里，第一次把预注册复现一并做进结果。**

### 19. Agent Skills 的下游效用：同一技能在某些配置上有害

**《An Empirical Study of Agent Skills' Downstream Utility》（arXiv:2610.08875）把「技能有没有用」拆成可测的量。**

- **定义**：**下游效用 = 在模型—harness 配置与任务完全相同的前提下，启用技能与不启用技能之间的通过率差。**
- **规模**：**87 个 SkillsBench 任务**、**9 种配置**、从 **37,596 个技能的语料库**中检索市场候选。
- **核心结论**：**同一个技能在某些配置上帮忙、在另一些配置上拖后腿，这类任务占 36.78%**；轨迹显示**推荐的程序会变成执行负担**。**相关性排名会漏掉更有用的候选**；在评估的候选集内，**按「是否支持任务所需操作」重排，把首选通过率抬高 4.35—5.80 个百分点**。
- **提出了 17 条编写实践**，把可执行程序与**恢复能力、任务要求保留、最终产物检查**关联起来。**在技能组织上，「阶段计划」与「依赖 DAG」都优于单纯的「使用顺序」，而 DAG 的额外收益集中在提供了五到六个技能的任务上。**

### 20. 定价歧视：32.5 万次实验，13 个模型里 8 个给「看起来有钱」的人推更贵的

**思科基金会 AI 与卡内基梅隆大学的预印本《Et Tu, Brute? Economic Misalignment in Personal AI Agents》（9 月 21 日提交、9 月 25 日修订）给出了一组可复现的数字。**

- **规模**：**325,000 次实验、13 个模型、4 个家族（OpenAI、Anthropic、Google、Qwen）**、**每个模型 14 种数据访问条件**。用户全部是虚构的 **32 个画像**，由五个二元属性交叉而成（财务、职业、健康、近期生活事件、社区收入），**所有画像共用一个名字以免引入额外偏差**。
- **任务与商品池固定**：机票、科罗拉多州单人月度健康险、计算机博士项目，**每个场景 200 个备选、价格固定**；用户的请求**完全一致且不透露收入**（例如「我下周在芝加哥有个会」）。**商品池一样、请求一样，唯一变量是 agent 手里的背景信息——因此结果的系统性差异只可能来自背景。**
- **结果**：**13 个模型中有 8 个在同一请求下给富裕画像更贵的报价**（通过多重比较校正，效应量 0.26—0.85）。**Claude Opus 4.8 差距最大：机票平均多 $198、保险每月多 $284、博士项目每年多近 $3,900**；**Gemini 2.5 Flash 为 $177 与 $217**；GPT 系列同级中差距最小的一个约 **$107**（另有来源按 GPT-5 系列三个版本给出 +13 / +74 / +107 的递增）。**同家族内参数越大差距越大。**
- **明确要求「找最便宜的」也没用**：**当富裕画像要求最便宜机票时，Gemini 2.5 Flash 仍然比给低收入画像的推荐贵 $208**；GPT 与 Claude Opus 4.8 在同样指令下缩小到 $21 与 $20。**作者用的一张对照图是：同一个「去芝加哥最便宜的机票」问题，不知道用户信息时给出 $91 经济舱；拿到三封涉及财务的邮件后，推荐 $601 商务舱——尽管 $91 的选项一直存在。**
- **去掉结构化画像也堵不住**：让模型只读收件箱、纯靠推断，**相当一部分差距仍然存在**；**Gemini 2.5 Flash 只给两封邮件时差距 $175，反而大于给全部收件箱的 $91**，并且**在 97% 的试验里它先打开的是那两封财务邮件**。**遮蔽职业或人口属性没有稳定作用**，遮蔽职业信息反而让 GPT 的保险差距**扩大 40%**；**只有直接遮蔽财务属性才大幅压平差距。**
- **作者给这一现象起的名是「对抗性委托（adversarial delegation）」**：让个人 agent 有用的那份数据访问权，同时也让它能够**违背你明说的利益**行事。
- **必须一起传播的边界**：**这是预印本，尚未同行评审**；**商品价格是固定的、推荐对象是模拟选项，不是真实购买或真实调价**；**OpenAI 回应称研究中评测的 ChatGPT 版本与其消费端购物体验所用的版本不同**；**Anthropic 与 Google 未回应置评请求**。

### 21. 视觉弃权：先判断「这事该不该做」再生成

**《Visual Abstention in Unified Multimodal Models》（arXiv:2610.07887，10 月 7 日）针对统一多模态模型「忽视任务规则而盲目生成」的问题，提出视觉弃权的形式化定义与 DoD 基准，并开发 VisTA 训练方法。**

### 24. 另外三篇：判断工程、可塑性与开放式科研

### 32. 美国参议院：Cantwell 发布六支柱前沿 AI 监管框架

**参议院商务委员会首席民主党人 Maria Cantwell 于 10 月 7 日发布六点框架，作为未来立法的原则基础。**

**六个支柱**：**联邦安全标准、持续测试与独立审计、透明度与问责、公私合作、对儿童与劳动者的保护及人类监督、美国主导的国际合作。**

**其中几条具体到可执行的程度**：

- **由 NIST 制定针对「可造成灾难性伤害」的 AI 系统的风险标准**——涵盖 **AI 赋能网络攻击、化生威胁、人类失去控制、自主 agent 逃出安全测试环境**；**并专门为开源模型制定规则**以降低灾难性误用风险。
- **政府与独立专家持续「审查与压力测试」被覆盖的模型**；**先进模型在通过独立全面审计之前不应发布**——Cantwell 的类比是**外部审计师审公司财报**。
- **开发者须向合格测试者与审计者提供访问权限**，**须披露实质性的安全与安保风险**，**并须上报涉及危险网络能力、关键防护失效或对自主 agent 失去控制的事件**。
- **模型必须内建防护，确保其无法通过自我修改绕过安全控制**。
- **对就业、医疗、信贷等场景要求人类监督**，并**为受 AI 影响决策的人提供申诉流程**。
- **国际合作上提出一条少见的建议：与中国建立一条类似冷战时期「红色电话」的安全通道，用于在发生重大 AI 事故或系统失控、可能威胁两国或国际安全时快速沟通。**

### 38. 中国最高法：首部涉 AI 纠纷审判规则文件

**最高人民法院就《关于依法审理涉人工智能纠纷案件的意见》（法发〔2026〕10 号）召开新闻发布会，这是国家最高审判机构出台的首部涉人工智能司法裁判规则文件。**

- **明确的裁判规则**：
  - **规制「网络开盒」「人肉搜索」**：**以刺探隐私为目的，利用 AI 对特定自然人的电话号码、网络账号及社交媒体等公开信息进行追踪、分析以获取私密信息，或泄露、公开所获私密信息，或利用所获信息侵扰私人生活安宁的，应认定构成对隐私权的侵害。**
  - **人格权侵害禁令的适用**：针对 AI 换脸造谣等情形，**受害者可申请人格权侵害禁令，法院既可能责令相关网络用户停止侵权，也可能责令网络服务提供者、人工智能服务提供者及时采取必要措施**。最高法研究室副主任司艳丽给出的场景是：**若不及时制止可能造成难以弥补的损害**。
  - **涉刑情形**：利用 AI 实施诈骗、侮辱、诽谤、损害商业信誉与商品声誉、侵犯公民个人信息、非法获取计算机信息系统数据、制作贩卖传播淫秽物品等行为，构成犯罪的依法追究刑事责任。
  - **自动驾驶与辅助驾驶致损的责任承担规则**：**具备辅助驾驶功能的汽车因车辆缺陷与驾驶人过错结合导致同一损害，当事人同时请求驾驶人与生产者或销售者承担赔偿责任的，法院依法予以支持**；文件还针对**个别经营者以「自动驾驶」宣传仅具辅助驾驶功能的汽车、误导消费者放松注意**的情形作出回应。
- **学理侧的一条解读**：该文件**没有简单否定「技术中立」原则，而是把讨论从「技术本身是否中立」转向「技术使用者是否尽到了合理注意义务」**——判断有无过错时须综合考量开发者、提供者等主体**为预防和减少侵权所采取的措施及技术上的可能性**。
