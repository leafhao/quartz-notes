## OpenAI

### GPT-6 Sol 与 Luna 发布：API 价格较上代促销价再降 50%（09-22 官方博客）

- 当地 09-22 OpenAI 发布 GPT-6 Sol 与 GPT-6 Luna，定位为 GPT-6 Astra 的低成本下沉版本，采用与 Astra 类似的训练方法，在推理、事实可靠性、编码、计算机使用与对齐上做了改进。
- 定价：GPT-6 Sol 每百万输入 token 2 美元、输出 10 美元；GPT-6 Luna 每百万输入 0.10 美元、输出 0.50 美元。两者均较 GPT-5.6 对应型号的促销价下降 50%，OpenAI 称降价来自缓存与推理效率的改进，并把节省直接让给用户。
- 定位区分：Sol 面向专业工作、编码、自动化与电脑操作等复杂任务；Luna 主打高调用量、成本敏感场景。OpenAI 明确表示 GPT-6 Astra 仍是整体最强的模型。
- 可用性：Plus、Pro、Business、Enterprise、Edu 用户可在 ChatGPT Work 与 Codex 中使用两款模型，开发者可通过 API 调用；免费与 Go 用户可在桌面应用中使用 Luna。两款模型暂未进入普通聊天界面。
- 官方同时披露可靠性口径：内部事实准确性评估中 GPT-6 Sol 的错误数量约为上一代的一半，安全对齐评估也有改善（包括减少对自身编程工作作出误导性陈述），但强调评估刻意设置了高难度情境，不能直接当作日常错误率。
- 参数口径（供比价参考，非 OpenAI 官方数字）：Sol 的 2/10 美元已与 Claude Sonnet 5 同价；Luna 的输入价低于小米同日发布的 MiMo-V2.6-Flash。

## Anthropic

### Claude Opus 5.5 发布：5.5 系列首款，成本较 Opus 5 降约 40%（09-22 官方博客）

- 当地 09-22 Anthropic 发布 Claude Opus 5.5，为 Claude 5.5 系列的首款模型，也是 CEO 呼吁「放慢前沿 AI 发展」之后的首个发布。
- 能力口径：官方称在大多数任务上达到 Claude Fable 5.1 的水平；Terminal-Bench 4.0 66.4%（Fable 5.1 为 55.8%）、CursorBench 4.0 57.8%、GDPval-AA v2.1 1846 Elo、OSWorld 2.0 81.8%、Humanity's Last Exam 67.7%（含工具）。Anthropic 同时承认，模型能力接近后，基准分数的小差距越来越难直接代表真实体验。
- 定价：每百万输入 token 4 美元、输出 20 美元（较 Opus 5 的 5/25 各降 20%）；缓存读取降至 0.20 美元，降幅 60%；缓存写入 5 美元（降 20%）。官方称默认设置下典型工作负载成本比 Opus 5 低约 40%，输出生成速度快 30% 以上，Claude Code 与 Claude Platform 另有 Fast Mode，速度最高 2.5 倍（8/40 美元）。
- 安全与外测：发布前接受 METR、Frontier Design 外部测试，另由 Gray Swan 做注入基准；官方称自动化行为审计（近 2000 个场景）取得迄今最好成绩，测试环境中试图越过隔离边界的频率较 Opus 5 与 Claude Mythos 5.1 低约 85%。沿用 Fable 5.1 同级的网络安全、生物与蒸馏防护。
- 可用性：AWS、Google Cloud、Microsoft Azure 及 Claude Platform 同步上线，模型名 `claude-opus-5-5`。
- 后续：官方称未来数周将推出 Claude Sonnet 5.5 与 Haiku 5.5，带来同类的性能、效率与安全改进。

## Hugging Face

### Transformers 可直接运行 llama.cpp 量化模型（09-22 官方博客）

- 09-22 Hugging Face 发布博客《Transformers now runs llama.cpp quants》：transformers 现在支持直接加载并运行 GGUF 模型，通过 `from_pretrained` 传入 Hub 仓库与 `gguf_file` 文件名即可，权重保持打包态、复用 ggml 的 Metal 内核，不必先反量化。
- 首期范围明确：优先优化 Apple Silicon 上的本地推理，架构覆盖 Qwen3.5（Dense / MoE）与兼容的 Qwen3.8 检查点；MPS 之外或内核不可用时回退到 sdpa。
- 性能口径：在 M2 Max 上对三个检查点测量结果接近 llama.cpp，但官方说明两侧测量条件并不完全一致（transformers 含 prefill，llama.cpp 的 llama-bench 为纯解码），并明确「以高效本地推理为优先时仍推荐 llama.cpp」。
- 顺带改动惠及全库：无 padding 时提前丢弃多余注意力掩码、停止条件判断延后一步以减少 CPU/GPU 同步；另支持 `transformers serve` 起 OpenAI 兼容端点、以及 `GgufConfig(dequantize=True)` 从 GGUF 微调。

来源：[Hugging Face 官方博客](https://huggingface.co/blog/transformers-llama-cpp-quants)

## Meta AI

### 修复 Muse macOS 零日漏洞：未公开设置项可致智能体被劫持（09-22 官方热修）

- 安全研究员 Patrick Wardle 发现 Meta Muse macOS 应用的零日漏洞：Muse 的听写功能在云端转写，而应用内一个供调试用的服务端点设置存放在本地偏好中，任意以用户身份运行的代码都可改写它，从而把转写流量重定向到攻击者服务器，并连带泄露 Muse 账号的鉴权令牌。
- 攻击者可借此操纵 Muse，用其已获授权的权限拍照、向磁盘写入恶意文件，多数情况下不向用户提示。该漏洞需要本地代码执行权限（如 ClickFix 式诱导），不构成对干净 Mac 的远程利用。
- Meta 在 Ars Technica 报道发布数小时内推送热修。Meta 超级智能实验室的 David Singleton 在 X 上定性为本地权限提升攻击、实际风险较低，并说明修复方式是移除可改写听写端点的设置。

来源：[The Verge 报道（Meta 官方回应）](https://www.theverge.com/tech/998679/meta-muse-patch-zero-day-exploit-ai-agent) · [Gizmodo 报道](https://gizmodo.com/meta-just-patched-a-major-zero-day-vulnerability-in-its-muse-ai-assistant-2000815429)

## 观察

今天值得记的是「价格成为发布会的主角」这件事在两家最前沿实验室身上同时发生。OpenAI 把 Sol 压到 Sonnet 5 的价位、把 Luna 压到比国产开源还低的输入价，Anthropic 则不动单价的整数位、专挑缓存读取砍 60%——后者更值得注意：智能体与编码工作流的账单大头本来就是缓存读取，这一刀砍在实际成本上，比降输出单价更接近真实使用曲线。两家都把「外部评估」写进发布稿（METR、Frontier Design、Gray Swan），说明安全叙事已经从承诺变成发布流程的一部分。国内的看点在供给侧：阿里把芯片、集群、云与终端的节奏一次性摊开，20GW 与 50 万卡的说法都是三到六年尺度，真正属于今天能验证的只有 V900 的参数与 2027 Q1 量产时点；小米则用一次 6 天、347 万美元的 RL 后训练把开源模型的智能上限抬到 46 分，这个成本量级本身比 46 分这个数字更值得记住——它意味着开源的迭代速度已经不完全受算力预算约束。另外，Meta Muse 的零日漏洞提醒了一件事：当助手同时握着文件、相机与账号权限时，它的安全下限就是宿主机的安全下限，而漏洞入口往往不是模型本身，是那些「供开发调试用」的设置项。
