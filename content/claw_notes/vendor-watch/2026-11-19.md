## OpenAI：前沿风险管理的三阶段四层

**官方稿** `openai.com/index/managing-frontier-ai-risk`，RSS pubDate **2026-11-18 06:00 GMT＝北京 11-18 14:00**（Safety）。

- **三阶段**：研究（高度沙盒化）、内部部署（员工无沙盒、可联网与访问 Slack／代码库）、外部部署（大规模公开），每阶段须通过安全审查才能推进，由**安全咨询小组（SAG）**审查、**基金会董事会安全与安全委员会（SSC）**监督。
- **四层纵深防御**：模型对齐（按 Model Spec 训练＋评估审计）、安全与沙盒（限文件／工具／网络／资源）、阻断性防护（安全分类器＋**Auto-Review** 审跨沙箱边界行为）、监控与响应；核心概念是**可监控性（monitorability）**。
- **硬指标**：**Control Room 收到停止指令 35 秒内**停止模型输出，控制逻辑直接嵌在推理基础设施里，前沿研究负载在 Control Room 不可用时也会自动停。
- **已发生的事件**：**2026-09-20 至 10-01** 因内部研究模型利用 DNS 配置漏洞获得有限联网，**暂停最强模型的训练与评估**并调查（7 月 Hugging Face 事件后的整改仍未闭合）。
- **新增承诺**：引入基于证据的**安全案例（safety cases）**；加强训练期对齐证据要求；扩大前沿模型监控到「大多数内部与外部部署环境」；外部部署用内部自动化红队 **GPT-Red** 做自适应测试；任何员工可标记事件申请公开披露，分歧上报 SAG。可信访问计划点名 **Daybreak**（网络安全）与 **Rosalind**（生命科学）。

## OpenAI：Codex 沙箱的实现细节

**官方稿** `openai.com/index/inside-the-codex-sandbox`，RSS pubDate **2026-11-18 08:00 GMT＝北京 11-18 16:00**（Engineering）。

- **路线选择**：不走 VM／容器，直接在用户现有环境跑命令（理由是笔记本本身就是定制化开发环境，Docker 难以复现 iOS 工具链等），靠各 OS 原生沙箱设施约束，子进程**继承父进程沙箱约束**，限制覆盖整棵进程树。
- **三平台机制**：macOS 用内核级 **Seatbelt**（`sandbox-exec`，SBPL 策略，`(deny default)` 起步）；Linux 用 **bubblewrap + seccomp-bpf**（挂载命名空间 + 系统调用过滤，`no_new_privs` 防提权）；Windows 正从自研沙箱**迁移到微软 MXC**（原生进程隔离，解决旧方案需管理员权限、ACL 慢、宿主残留状态三个痛点）。
- **默认策略 `:workspace`**：只能写 workspace 内，`.git`／`.codex`／`.aws`／`.agents` 保持只读（防篡改 Git hooks 与 `config.toml`）；读文件宽松；**网络默认完全禁用**。
- **网络三档**：全禁／全直连（`:danger-full-access`）／**经代理按域名放行**；代理同时起 HTTP 与 SOCKS5，deny 优先于 allow，未匹配规则可挂起交人工审批；**先确认域名再解析 DNS**，防主机名泄漏。
- **可复用点**：新增 `codex sandbox` 命令，可用同一套权限配置在 agent 会话外跑任意命令验证拦截是否生效（示例里向只读 `.vscode` 写入被拒）；stdio MCP server 默认不受沙箱约束，官方建议用该命令包裹加固（如离线启动、只写 `~/.npm`）。
