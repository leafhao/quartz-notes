## 国外厂商

### OpenAI：robots.txt 里的「通用训练偏好信号」，一次声明、多家生效

- 发布：官方博客《Making it easier for websites to express AI training preferences》，`openai.com` 记 **2026-10-30 09:30 UTC＝北京 10-30 17:30**，栏目 Company。
- 是什么：robots.txt 里一个**通用的（common）信号**，用来声明「本站内容是否可用于基础生成式 AI 训练」。它是**自愿采用**的约定，不是强制协议。
- 解决什么：过去网站要给每家厂商的爬虫分别维护规则；这套信号让**一条规则同时向多个参与方**表达同一个偏好。
- 技术出处：基于 **IETF AI Preferences 工作组**在推进的两份草案——`draft-kelley-aipref-training-preference-signal`（偏好信号本体）与 `draft-ietf-aipref-vocab`（词汇表）。OpenAI 称自己参与了**当天的联合发布**。
- **关键保留（最容易被漏读的一句）**：OpenAI 说它**「计划在未来几个月内」**实现该信号，届时另发一次更新交代实施细节。也就是说**现在只有表态，没有生效**——今天去查 OpenAI 的爬虫行为，看不到任何变化。
- 与既有控制的关系：官方明确新信号**不取代**现有 robots.txt 控制，既有爬虫控制继续适用并被遵守。
- 定性：不是模型、不是 API、不是定价，是训练数据授权层的接口标准化。它的价值在于把「逐家谈判」变成「一处声明」，风险在于**表态方与生效方是两件事**——参与联合发布的工作组成员名单官方也未逐一列出，目前能核实的只有 OpenAI 一家承诺遵循。OpenAI 在文中呼吁其他 AI 提供商跟进。

  - 预测用户**未满 18 岁**时，即使没有暴力意图迹象，也施加更严格限制。
  - 对话显示用户**执迷于暴力**或有严重伤害他人的念头时，ChatGPT 可**自动终止对话**；多次触发可**临时暂停账户**。
- 青少年侧：在原有「不帮青少年找武器」之上，进一步限制**可助长暴力的武器与安防系统实用信息**，无论提问看似多无害、有无暴力意图；年龄预测持续以行为信号评估，误判的成年人可通过合作方 **Persona** 做验证移除青少年保护。

- 时间线：上述措施自公告后**未来几周**分批上线。
- 定性：治理层动作而非产品更新，但它给出了一个可核的节奏承诺（半年一份报告），比过去零散的政策博客更容易被外部检验。

## 本期实测与入口备忘

- **网络环境变了，这是本期最重要的运维事实**：`docs.claude.com` → `platform.claude.com` 直接返回 **「App unavailable in region」**（标题已核）；`huggingface.co` **TLS 握手被掐**（SSL_ERROR_SYSCALL）；`ai.google.dev` 与 `developers.openai.com` **CONNECT 隧道 502／403**；`research.meta.ai`、`ai.meta.com` 不可达。而 10-30 那一期这些页面还是通的——**同一天内区域拦截与隧道失败同时出现在四个监控必需的入口上**。结论：`docs.claude.com` 的 API 发布说明、Gemini API changelog、HF 官方博客这三条固定入口**本期靠不住**，下一期起需要各留一个备选（Claude 走 `anthropic.com/news` + GitHub 发布页；Gemini 走 `blog.google/rss` + DeepMind RSS 双向夹逼；HF 走 GitHub `transformers` releases）。
- **可用且稳定**：`openai.com/news/rss.xml`（WebFetch 正常，`openai.com/index/*` 正文也能读）、`api.github.com` 的 `anthropics/claude-code` 与 `huggingface/transformers` releases（含完整 body）、`about.fb.com/news/feed`、`blog.google/rss`、`deepmind.google/blog/rss.xml`、`help.aliyun.com` 百炼表格、`docs.z.ai/release-notes.md`、`api-docs.deepseek.com/updates`、`www.kimi.ai/blog`。
- **新入口**：**Meta 别再用 `research.meta.ai` 的 sitemap**，`about.fb.com/news/feed` 是稳定 RSS，带 `pubDate`，比 sitemap 的 lastmod 可靠；**腾讯混元用 `api.github.com/orgs/Tencent-Hunyuan/repos?sort=created`** 能一次拿到 `created_at` + `pushed_at` + 描述，比翻 HF 组织页快，也能区分「仓库更新」与「模型发布」。
- **教训**：① **「参与联合发布」不等于「已经生效」**——OpenAI 的 robots.txt 信号是「计划未来几个月实现」，卡片与笔记都必须把承诺和落地分开写，否则读者会以为今天起可用了。② **文档页的「更新时间」不是内容更新**：方舟模型列表页记 10-30 更新，但没有任何 `-261030` 模型，这类页面刷新每天都在发生。③ **区域拦截会伪装成内容为空**：WebFetch 报的是「重定向到 app-unavailable-in-region」，如果不点进去看标题，很容易误记成「今天 Anthropic 没发东西」。④ 一个版本里**唯一带截止日期的那条变更**（Opus 4.8 fast mode → 11-30 移除且不回退）比二十多条修复更值得放在最前面。
