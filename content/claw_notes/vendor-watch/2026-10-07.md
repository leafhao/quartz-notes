### OpenAI — 发布内部前沿模型的数学成果（官方博文 2026-10-06 12:00 GMT；仓库创建 10-06 21:47 UTC = 北京 10-07 05:47）

官方博文 **「Sharing AI progress in mathematics」**（`openai.com/index/sharing-ai-progress-in-mathematics`），同批在 GitHub 公开仓库 `openai/math` 发布全部材料。

- **规模**：一次性发布 **722 篇数学手稿**，按结果相关性归类为 **372 个结果族（Result Families）**，覆盖理论计算机科学、数论、几何、数学物理等 **17 个领域**。对比此前：08-01 发布 10 项结果（配 548,207 行 Lean，仓库 `openai/ten-proofs`）、09-21 宣布咨询小组时称已解决 100+ 未解问题。**九周内从 10 项到 372 族。**
- **来源模型**：由一个**尚未发布的内部前沿模型**产出，OpenAI 通篇不点名、不给发布日期，只称「正在负责任地推进该模型的发布」。绝大多数结果采用同一固定流程，个别（如 CM 阿贝尔簇的 Hodge 猜想）例外。
- **自报的代表性结果**（**均为 OpenAI 自报，官方博文未引任何外部验证**）：
  - **准黎曼假设**（族 003）：对**所有 Dirichlet L 函数（含 zeta）**证明在 **Re(s) > 7/8** 上无零点，并一致排除 Landau-Siegel 零点。**已 Lean 形式化**；另有一篇伴随论文给出 11/12 的独立证明，README 注明该文「经人工编辑以提升可读性」。黎曼假设本身需要 Re(s) = 1/2，因此**这不是黎曼假设**，但此前从未有固定条带被清空。
  - **Unique Games 猜想**（族 102）：给出从 3SAT 到 Unique Games 的确定性多项式时间归约，并直接证明「超越 Max-Cut 的 Goemans-Williamson 比值」与「把 Vertex Cover 逼近到因子 2 以内」均为 NP 难。**已 Lean 形式化**。
  - **矩阵乘法指数**（族 107）：在复数域上证明 ω ≤ 9/4（该领域此前十年在 2.37 上磨小数）。**已 Lean 形式化**。
  - **整数乘法低于 n log n**（族 109）：给出确定性多带图灵机算法 O(n (log n)^(1-κ))，κ = 2^-182，若成立将推翻 Schönhage-Strassen 最优性猜想。**无 Lean**。
  - **Kakeya**（族 074）：三维极大猜想与四维全 Hausdorff 维数。**无 Lean**。
  - **Hilbert 第十问题在有理数域上**（族 004）：否定结论。**无 Lean**。
  - 其他含 Hadwiger 猜想在分数染色下不成立（族 157）、Kaplansky 零因子猜想反例（族 196，Lean）、Barnette 猜想证明（族 180，Lean）、平面不能五着色（族 158，Lean）等。
- **形式化覆盖率**：**372 族中 235 族附 Lean 形式化，137 族没有**；README 明确说明其中部分「可能有错误」。
- **算力口径**：平均每项结果约等于 **3 小时 ChatGPT Pro 的思考算力**；模型在评估中被投入 **4,000 个数学问题**。仓库另附 **10 份模型推理摘要**、算力估算与尝试题目统计。
- **许可与治理**：**Apache 2.0**；每篇手稿带 BibTeX 引用块；承诺保留每个公开版本。OpenAI 表示发布流程是与**普林斯顿高等研究院「数学与人工智能咨询小组」（AGMAI）**协商后制定的，并称**仍在寻找符合该委员会指南的社区托管替代方案**（即当前放在自家 GitHub 上只是过渡）。未来发布将改进引用、数学表述与呈现质量。
- **后续**：OpenAI 将**资助一系列工作坊、会议与特别项目**，用于理解 AI 产出的重大结果；细节未公布。
- **AGMAI 的回应**：该小组发布声明称，OpenAI 报告了数百个未解问题的答案，「对数学界是一件意义重大的事件」，影响波及整个数学领域；但同时强调这**只是人类理解并把这些工作纳入数学知识体系的开始而非结束**，数学家必须能够提出自己的问题、发展自己的方法。一个值得注意的张力：AGMAI **一周前刚公开呼吁各实验室「停止在专有模型上测试高等数学问题」**，OpenAI 在发布博文中援引了该小组的建议，但仍完成了这次发布。
- **口径**：官方博文 + 官方 GitHub 仓库。属**研究与模型能力披露**类，非新模型发布、非 API 变更、非定价变更。中文侧《科技日报》10-07 有完整转述。

### Anthropic — 网络验证计划（CVP）扩为三档（官方公告 2026-10-06）

官方公告 **「Expanding the Cyber Verification Program」**（`anthropic.com/news/cyber-verification-program`）。

- **动作**：把此前的两个项目——**Project Glasswing**（向关键软件的安全方开放 Claude Mythos）与 **CVP**（向经审核的安全团队提供降低后的拦截分类器）——**合并为一个扩展版 CVP**，改为**三档准入**。各档均可访问其最强模型，含 **Claude Opus 5.5、Claude Sonnet 5.5、Claude Mythos 5.1 及此后新模型**。
- **三档**：
  - **Defense Access（防御档）**：面向安全运营中心、事件响应、恶意软件逆向、漏洞分析与验证。合格组织含企业/非营利/高校/政府中防御自有系统的安全团队、任意规模的关键基础设施运营方（如区域医院、市政公用事业）、小型安全公司、开源维护者、有漏洞报告履历的独立研究者。**官方称预计多数做防御性网安工作的组织都能通过，目标数日内答复申请。**
  - **Red Team Access（红队档）**：在防御用途之上增加经授权的渗透测试与红队演练。合格方含内部红队、政府红队、安全与渗透测试公司，**只能对获授权系统做对抗性测试**。仍会对可造成人身伤害或大规模中断的动作做实时拦截（部署勒索软件、破坏物理系统、渗透高风险安全系统）。审核需数周；审核期间先纳入 Defense 档；**目前仅面向组织，独立研究者不符合条件**。
  - **Specialized Access（专用档，拦截最少）**：仅限少量经深度核验、获授权测试可影响人身安全或市场稳定系统的组织（飞行操作系统、电网、电信网络、银行间转账基础设施、政府行政网络）。**每家企业均与美国政府协作深度审查**；Project Glasswing 现有成员自动过渡至该档，现有模型无需重新审批。
- **通用模型仍可用**的场景被明确列出：代码审查、修补已知问题、在自有源码中找漏洞、安全告警分诊。
- **数据留存**：入组组织**必须留存数据**以便监测网安滥用。官方称今秋晚些时候 **Enterprise Frontier Safeguards（EFS）**上线后，合格组织可把数据存在自己控制的云基础设施上，从而同时获得零数据留存与护栏。
- **自测结果（CyScenarioBench）**：用 Claude Opus 5.5 在十个挑战上各试五次（每档 50 次）——
  - **无 CVP 权限**：每个任务在**第一个提示就被拦截**；
  - **Defense 档**：50 次中 **46 次**在挑战过程中某处被拦，**4 次成功**；
  - **Red Team 档**：**无一次拦截**，Opus 5.5 完成 **34/50**，与「不施加护栏」（代表 Specialized 档）时的 **67.6%** 成功率基本相当。
- **口径**：Anthropic 官方公告。属**访问控制与安全策略**类，非模型或定价变更。注意 `/news/expanding-the-cyber-verification-program` 等猜测路径会 404，正确 slug 为 `cyber-verification-program`。

- **定位**：Gemini 3 系列成员，**底层基于 Gemini 3.6 Flash**，是 Nano Banana 2（Gemini 3.1 Flash Image）的更新版，也是 **Gemini 3 Pro Image（Nano Banana Pro）的更高效替代**。官方定位为「最新的高效率图像生成与对话式修图模型」。
- **模型 ID**：`gemini-nano-banana-2.1`，**状态为 Stable（稳定版）**。
- **关键更新**：
  - 1K / 2K / 4K 三档输出（默认 1K），提升视觉质量与真实感；
  - **修复 2K 与 4K 下宽屏与全景宽高比（1:4、4:1、1:8、8:1）的平铺伪影**；

### Google — 开源 EmbeddingGemma 2（官方博客 2026-10-06 16:00 UTC = 北京 10-07 00:00）

官方博文 **「EmbeddingGemma 2: an open, lightweight multimodal embedding model」**（`blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2/`），作者为 Google DeepMind 研究工程师 Sahil Dua 与 Henrique Schechter Vera。

- **是什么**：设备端多模态嵌入模型，**原生把文字、图片、音频、视频的组合映射到统一嵌入空间**。**Apache 2.0 许可**，**7.4 亿参数**，基于 **Gemma 4 架构**，与 Gemini Embedding 系列同技术栈。
- **模块化**：纯文本工作负载最低只需 **2.7 亿参数**；视觉编码器 **1.7 亿**、音频编码器 **3 亿**为可选，不用时可在加载阶段关闭以省内存。
- **存储效率**：采用 **Matryoshka 表征学习（MRL）**，输出向量可从 **768 维动态截断到 512 / 256 / 128 维**，本地向量库存储最高减少 **6 倍**。
- **端侧表现**：在 **Google Pixel 11 Pro** 上量化后，纯文本权重活跃内存约 **191MB**，完整多模态约 **567MB**。
- **上下文**：**8K token**（是 EmbeddingGemma 1 的 4 倍），可一次处理约 **5.5 分钟音频、29 张图片、58 帧视频**或它们的交错组合。
- **能力**：官方称在 **MTEB Code 上从 68.76 提升到 78.68（+9.92 分）**，适合本地代码库索引、语义代码检索与编程智能体检索；在 MTEB（多语言文本）与 MAEB（音频）上为亚 1B 量级领先，官方称部分任务可超越参数量两倍以上的专用模型。**均为官方自报benchmark。**
- **获取**：权重在 Hugging Face 与 Kaggle；Gemini Enterprise Agent Platform Model Garden 版本「即将支持」；LiteRT 社区提供端侧优化版。与 Gemma 4 共用文本 tokenizer 与音频编码器，可同管道运行以降低总内存占用。
- **同批生态**：`huggingface/transformers` **v5.19.0**（10-06 16:39Z）当日即新增 **EmbeddingGemma2** 模型支持。参见下方 Hugging Face 段。
- **口径**：官方 Google 博客。属**开源模型发布**。
