## Google：Genie 4 开放 API，按秒计费

**Gemini API changelog** 的 **November 19, 2026** 段第一条；模型 ID `models/genie-4`，走 **Interactions API（`v1beta`）**。这是 11-19 消费侧发布（Project Genie 面向 Ultra 用户）之后的 API 侧 GA。

- **能力**：实时可交互世界生成，以 **24 fps、16:9** 流式输出视频，同时带 **48 kHz 立体声**，走 **WebRTC 与 WebSockets**。
- **起点**：文本提示、**16:9 参考图**，或两者结合。
- **操控**：实时用 **WASD／方向键**移动，并可在会话中途插入**文本事件**改变走向。
- **定价（付费层，每百万 token）**：输入 **1.50 美元**、文本输出 **9.00 美元**、视频输出 **17.50 美元**；官方换算约 **每秒 0.10 美元**，立体声已含在视频输出里。
- **配套文档**：交互式世界生成（`/docs/genie`）、提示与操控指南（`/docs/genie-prompting`）、专用速率限制（`/docs/rate-limits#genie-4`）。

## Google：工具检索进入 Gemini API 预览

**官方博客** `blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/`，pubDate **2026-11-19 18:00 GMT＝北京 11-20 02:00**，作者 Lucia Loher（Gemini API 产品经理）、Nora Kassner（Google DeepMind 研究科学家）；同日 API changelog 的 November 19 段同步列出（Preview）。

- **解决什么**：智能体接几十上百个工具时，每个请求都塞全量参数 schema，输入 token 涨、延迟涨，候选清单变长后**选工具的准确率反而下降**。
- **怎么开**：请求里加 `{"type": "tool_search"}`，并在想延后的工具上设 `defer_loading: true`。模型**仍看得到每个被延后工具的名字与描述**，但参数 schema 不进上下文。
- **单请求内完成三步**：模型按名索要工具 → API 载入完整 schema → 模型发出 `function_call`；三步都出现在 `interaction.steps`（`tool_search_call`／`tool_search_result`／`function_call`），便于排查是工具名还是描述写错。
- **不用自建索引**：搜索在服务端跑，代码改动只有一个 tool 加一个标记。建议**高频工具保持前置、长尾延后**。
- **与前缀缓存兼容**：延后的 schema 不进 prompt 开头，加载的 schema 追加在对话后段，缓存前缀逐轮不变。
- **远程 MCP**：在 `mcp_server` 工具上设 `defer_loading: true`，该 server 暴露的全部工具按需加载，不必逐个列出。
- **客户端检索**：声明 `"execution": "client"` 可自己跑检索（自有注册表、embedding 索引、按用户权限过滤），每次搜索多一个往返，换取工具不必预先声明、可在会话中动态挂新集成。
- **适用范围**：Gemini 3.6 及之后模型，含全部 Gemini 4 系列，仅 Interactions API。

## OpenAI：全双工语音模型升到 1.1

**API changelog** 的 **Nov 19** 段唯一一条；模型页 `gpt-live-1.1`。

- **变化**：`gpt-live-1.1` 边说话边听（全双工），相比 GPT-Live-1 **转写更准**，跨语言时**口音与音色更一致**；委派给后端做推理或工具调用改为用自然语言描述。
- **端点**：仅 **`v1/live/sessions`**；Chat Completions、Responses、Realtime 均不支持。
- **计费**：语音会话按时长计费，**活跃 0.05 美元/分钟、待机 0.02 美元/分钟**；后端模型与工具用量另计。
- **待机机制**：新增 WebRTC 会话的 standby 配置——空闲时暂停推理、有人说话再恢复，按待机价结算。

## OpenAI：性能工厂，三个多月查了 1,700 次回归

**官方工程博客** `openai.com/index/how-openai-performance-factory-keeps-chatgpt-fast`，RSS pubDate **2026-11-19 08:00 GMT＝北京 11-19 16:00**，作者 Okay Zed、Cyrus Forbes。

- **是什么**：一套跑在云端的自主性能工程系统，用 Codex 代理自动完成「发现回归 → 定位根因 → 提修复 → 部署后验证」。
- **四个部件**：task service（工程师用 Markdown 配置定义工作流与状态机）／dispatch loop（周期性派活）／云端 Codex（内网运行，可读指标、日志、trace、CPU profiler、内存快照）／subscriptions（GitHub 评论、部署完成等事件唤醒等待中的代理，避免空转）。此前已积累 **30 多个**性能工具。
- **数字**：三个多月跟踪 **1,700 多次**调查、定位根因 **600 多例**，折合**每天 17 次**自动化调查；人工复核 100 个根因建议，**70% 准确**、30% 需改进或未完全建立因果。
- **质量控制**：另开一个 Codex 会话做**对抗式审查**，专门试图推翻诊断与修复方案；用历史生产事故**回测**；代理每天自检工具故障与权限错误。
- **未披露**：首字延迟、吞吐、成本、GPU 利用率等具体性能基线，文中只有定性描述。
- **下一步**：从告警驱动转向主动监控；当前瓶颈在**等人 review 与 merge**。

## Anthropic：Claude Code 2.1.329

v2.1.329 发布于 **2026-11-19 22:14 GMT＝北京 11-20 06:14**（前一版 2.1.328 在 11-19 01:14 GMT，落在窗口前）。

- **信任与诊断**：新增告知「文件夹的 hooks 声明在哪」的信任对话框；托管设置里的 hooks 加载失败时，在会话内（含 Claude Desktop 等非交互宿主）给出警告；远端 HTTP MCP 拒连时，在 `/mcp` 里显示该 server 的 JSON-RPC 错误原文。
- **任务面板**：`/tasks` 现在包含本会话的定时任务、`/loop` 唤醒、目标与分支，`x` 会先询问再停。
- **修复**：网络卡顿或文件锁导致 `~/.claude.json` 被清空重写；macOS 上 Keychain 可读不可写造成反复登出（改为该会话到期即停并说明原因，其余会话保持登录）；`/terminal-setup` 破坏 VS Code 设置与键位文件；IDE diff 接受后丢末尾换行与 BOM；`/teleport` 选云会话时覆盖当前对话（改为新开会话）。
- **Code Mode**：可与 OpenTelemetry 事件与指标同时开启，代码里的每次工具调用都会上报事件（开 tracing 时仍关闭）。
