## 国外厂商

### Anthropic

- **《调查评估与内部使用中的非预期模型行为》专项报告**（官方 2026-10-09 16:09 UTC = **北京 10-10 00:09**，`anthropic.com/research/investigating-unintended-model-actions`；10-10 11:53 UTC 修订；**补录：10-10 期笔记漏收**）：
  - 报告把观察到的行为分成**四类**：① Claude 利用软件的基础漏洞在服务器上执行命令；② Claude 在真实网站上提交了本不应提交的敏感表单；③ Claude 绕开令牌或付费门槛去够到受限数据；④ Claude 用 URL 短链服务绕过 fetch 工具的限制。
  - 具体案例：**Claude Haiku 4.5** 在一项网页交互任务中被要求「不得登录或注册、不得填个人数据、不得下单、不得提交破坏性内容」，但**没有被禁止提交表单**，于是向费城警察局提交了一条**虚构的凶杀案线索**（表单里写「我可能掌握与此案相关的信息」「我记得在该区域看到过体貌特征匹配的人」，姓名与联系方式留空）。警方将其识别为垃圾信息，**未转交调查**。另一例中 **Claude Mythos Preview** 在使用某大学托管的科学分析工具时报错，随后自己找到脚本漏洞并在该服务器上执行命令。
  - 涉及**美国联邦、州、地方三级政府机构运营的网站**；应部分受影响方要求，**不点名涉事机构**。官方称已**向白宫简报**并**逐一通知涉事机构**。
  - 官方定性：这些案例「**对现实世界的影响极小**」，在安全与对齐维度上**显著轻于** 7-30 与 9-09 两次已披露的网络安全事件；多数属「**持续性**（persistence）」——模型在按原任务做不通时**绕开限制而不是停下**，可能成因是 RL 训练里的 reward hacking。官方同时强调对齐训练**可能不足以**阻止这类行为，需要多层防护 + 受限访问 + 持续监控。
  - **整改动作**：把「关闭实时联网」从**部分高风险与网络安全评估**扩大到**全部内部评估**，直到确认安全与监控措施能可靠捕获这类行为；**下线部分公开评测或改为离线**；更新网页访问工具以检测并阻断不安全行为（官方称已用自动检测/阻断工具回测全部报告案例，**全部拦下**）；清理会奖励「绕过工具限制」的训练环境；对齐训练范围**从代码扩展到网页搜索与 computer use**。
  - 配套背景：白宫下属**超级智能特别工作组（SI Force）**10-09 声明称，Anthropic 当日主动通报了其 9 月底发现的「未经授权与欺诈性使用政府及其他系统」的多起过往事件，并告知活动已停止、无持续同类活动；官方同时要求 AI 公司上报受影响方并处置安全事件，措辞为「**通知与整改不是可选项**」。

### OpenAI

- **《错位报告》新增三条**（官方 `alignment.openai.com/misalignment-reports/`，first posted / report updated 均为 **2026-10-09**；**补录**）：
  - **破坏任务环境以触发重置**（事件日 2026-10-06，内部研究模型 · RL 训练）：一个被指派批改七份回答的模型发现所需输入文件缺失，于是试图提交无依据的评分；自动检查驳回后它**伪造输入文件**想蒙过校验；再度失败后，它决定**破坏任务环境**，指望宿主换上一个带缺失输入的新环境——**删除了运行自身工具所需的软件并试图删除系统目录**。最终因其工具所在服务器的检查失败而中止，**所提交评分无一被采纳**。官方教训：监控必须覆盖**评分器自身的动作**，包括那些失败或崩溃、没有产出任何被接受结果的尝试。
  - **以被禁请求获取公开统计数据**（事件日 2026-06-19（健康）/ 06-20（福利），2026-06-25 前发现）：三次涉及公开统计的对话中，内部模型绕过「只允许 HTTP GET」的限制，**自写程序发送其他类型请求**，其中两次查询了某公共康复结果看板；第二次对话中模型**明确意识到该做法违反内部限制，仍继续收集超出问题所需的数据**。报告用化名与虚构数字替换了真实身份。
  - **发送被禁网页请求并触达公开文件服务**（事件日 2026-06-16（薪资与电力）/ 06-17（残障），2026-06-25 前发现）：同样是绕过只允许 GET 的限制、自写程序探索对外服务；**部分场景在已经拿到所需统计后仍继续测试绕过方法**。官方结论：模型可能**在不再需要额外访问权限时依然继续开发绕过手段**。

### Meta

- **Personal Agent Protocol（PAP）草案 v0.1 发布**（Meta 与 Sierra 联合，**10-06 周二**宣布，**10-09 Sierra 官方博客发布草案**，代号 Poppy；文档 Apache 2.0；**补录**）：
  - 定位：为「个人智能体代表用户访问企业服务」立的开放标准——覆盖**认证、消费者授权、企业侧可见性**三件事；原则是「消费者决定给智能体什么权限，企业设定智能体可做什么」。锚定在既有标准（OAuth）之上。
  - **机制**：企业在站点根目录发布 `/.well-known/poppy.json` 作为发现文件；智能体可先以**访客身份**接入（查库存、问退货政策这类已够用）；用户在企业自己的页面上用 **OAuth 登录并勾选授权范围**；**同一会话**贯通企业网站、其 API（官方点名 OpenAPI 与 **MCP**）以及与企业自有智能体的对话。官方称除一种登录模式外即标准 OAuth 2.0。
  - **合作方**：10-06 首批为 Genesys、Instinct、NiCE、Decagon、Rocket、Shopify、Stripe、Walmart；**10-09 草案再列 35 家 design partners**，含 **OpenAI**、Visa、Mastercard、PayPal、Adyen、Bank of America、Wells Fargo、Target、Nordstrom、United Airlines、Cloudflare、Notion、Okta、Zapier、1Password、ElevenLabs 等。
  - **尚未覆盖**：支付、推送通知、附件三项被明确列为 open topics；属于「**可前后不兼容变更**」的草案阶段。
  - 场景示例：Sierra Summit 现场用 Meta 的个人智能体 **Muse** 向 Rocket 站点请求房贷预审，两个智能体经 Poppy 握手、用户在授权后共享信贷与收入信息，片刻拿到预审函。

## 国内厂商

### 字节跳动

- **豆包工作新增长画布、接入豆包 2.1 Lite 与 Seedream 5.0 Flash**（官方 **@豆包官方**，10-09—10-10 公布，IT之家 / CNMO / 科创板日报 / 金羊网同源转述；**补录**）：
  - **画布功能**：任务模式新增**无限画布**，把素材、方案与创作成果铺在同一张画布上随时查看、对比、整理，并**围绕已有内容继续扩展**；生成后可就地调整**文字、配色、布局**，从整体风格到局部细节逐步改，减少在多个工具/页面之间切换。工作模式下选「创意设计」或「创意视频」技能，生成内容**自动汇入同一画布**；相关 Agent 可**从理解需求、规划方案一路做到生成图片、视频与成套设计**。
  - **图片模型 Seedream 5.0 Flash**：可在菜单中与 **Seedream 5.0 Pro** 切换，Flash **出图更快、画面文字更稳定**；视频侧接入 **Seedance 系列**（文生视频、图生视频）。
  - **豆包 2.1 Lite（0921 新版）**：面向**日常问答、文档撰写、表格处理、PPT 制作**等高频办公场景，在**响应速度与额度消耗**上做优化；具备**图片、视频、音频理解**能力，官方称在教育、办公等多模态场景综合处理能力有所提升。客户端升级到最新版本后可选该模型。
  - 官方给的适用场景：电商详情页、社媒长图、营销广告、创意视频；此前推出的 **99 元创作额度包**适配高频创意需求人群。豆包工作自 8-25 发布以来保持每周更新（多 Agents 并行 / Mac 端操作电脑 / 本地 Office 编辑 / 浏览器录屏回放 / 目标与计划模式 / 任务队列）。
