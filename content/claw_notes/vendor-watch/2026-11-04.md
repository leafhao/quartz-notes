### Anthropic：文本水印扩到 Opus 4.7、Mythos 5、Sonnet 4.6

- 位置：`docs.claude.com/en/release-notes/api` 的 **November 3, 2026** 条目（本期该页唯一新条目）；配套新文档页 `/docs/en/build-with-claude/text-watermark`。
- 变了什么：这三款模型的生成文本开始携带 Anthropic 的文本水印。此前支持水印的是一批 5.x 与 4.8 模型，本次等于把 4.7 与 Mythos 5 补齐、把 Sonnet 4.6 纳入。
- 水印性质（官方口径）：嵌在文本本身，**不增加 token、不插隐藏字符**，不含用户或组织信息；不影响含义、质量与可读性；复制粘贴后仍保留，可承受一定程度编辑。
- 覆盖范围：模型级实现，第一方产品全覆盖（Claude API／Claude 应用／Claude Code／Cowork／Claude Tag）；云侧走 Bedrock、Google Cloud、Microsoft Foundry，**Bedrock 的部署官方写明 11-10 前完成**。
- 一个坑：**Sonnet 4.6 在 `temperature`／`top_p`／`top_k` 设成非默认值时，输出可能不带水印**；官方建议依赖水印的请求把这三个参数全部省略（包括框架或客户端库偷偷塞的默认值）。
- 背景：2026-08-02 起在欧盟发布的新模型从第一天就带水印，更早的模型在逐步补齐——这条是补齐进度的延续，不是新政策。
- 怎么读：对企业客户最实际的影响是「可检测性」而不是画质——如果你的下游有内容审核、合规存档或 AI 生成内容标注要求，现在可以按模型核对覆盖矩阵了；反过来，靠改采样参数「去水印」并不可靠。

### Anthropic：FlashProve——用 zkSNARK 证明「回答确实出自这个模型」（补录，11-02 发布）

- 位置：`anthropic.com/research/provable-inference`，`datePublished` **2026-11-02T00:00Z**，`dateModified` 11-03 19:10Z；上期漏收，本期补录。
- 解决什么问题：用户无法确认回答来自宣称的模型，还是被路由服务为省钱偷偷替换、或被攻击者篡改了 token 流。只看输出质量判断不可靠。
- 做法：对推理过程生成 zkSNARK 证明——模型方先对权重做承诺，再对每次响应出证明；承诺与证明都隐藏权重（不隐藏架构）。
- 实测规格：Llama 4 Maverick（400B MoE），**单张 H100 约 110 token/s** 的证明生成速度，**每 1,024 token 请求约 19MB 证明**；4-bit 量化权重 + prefill 整数运算；GPU 时间是 vLLM 正常推理的 **70–95 倍**，官方称比此前开源系统快若干个数量级。
- 可信度处理：模型爱做「难以评估的优化决策」，因此把顶层安全声明写成 **Lean** 可审计命题。
- 开放程度：代码、Lean 证明与文档以 **Apache 2.0** 放出；作者含 Anthropic 与 EPFL、MIT、StarkWare、Succinct 的研究者（含 Fellows 项目）。
- 官方定位：阶段性进展，不是完成的研究议程，明说希望别人拿去改进。
- 怎么读：这条的分量不在速度，而在「评测可信度」这条链——独立评测机构、第三方路由、监管侧的合规核查都依赖「你测的就是你被服务的模型」。70–95 倍开销意味着短期内只用于高风险场景（合规审计、pacing 要求），不会是默认推理路径。

### Anthropic：Claude Code v2.1.318

- 位置：GitHub `anthropics/claude-code` release `v2.1.318`，`published_at` **2026-11-04 00:01Z＝北京 11-04 08:01**。

- 主要修复：`--continue` 在畸形工具调用重试耗尽后丢失早前会话（2.1.314 引入的回归）；macOS 上大量 Bash 命令并行时会话卡住且内存上涨；共享网络家目录写不进配置时 `logout`／`mcp remove` 仍报成功；同机另一次登录后再执行任务报 `Not logged in`；空闲压缩把会话替换成非摘要的回复。
- 怎么读：这一版没有新能力，全是稳定性；`--continue` 丢历史这条值得升级——它是上一版的回归。

### 谷歌 DeepMind：Antigravity 加装「化学信息学技能」

- 位置：`deepmind.google/blog/agentic-cheminformatics-with-google-antigravity/`，`pubDate` **2026-11-03 17:01 UTC＝北京 11-04 01:01**。
- 是什么：给 Google Antigravity 的一套 Cheminformatics Skills，把 IDE 变成化学工作台——模型负责流程编排、库导航与科学推理，确定性化学工具负责分子计算；底层基于 RDKit 等开源化学信息学工具与策展数据源连接器。
- 官方演示（crizotinib → lorlatinib 刚性化案例）：agent 从文献里抽出数千个化合物、剔掉缓冲液与溶剂等无关分子、带出处成报告；**几分钟**完成检索与初筛，**约一小时**内做完 matched molecular pair 分析、提出带合成路线的新刚性化大环并给可视化报告——官方称同样一轮迭代过去要几天。
- 判断依据：大环化合物多被判为可透脑，这对常转移到脑的肺癌靶点有实际意义；散点图显示可旋转键越少、效力越高。
- 边界：官方没有给成功率、召回率或与化学家人工结果的对照，只有流程演示；这不是模型发布，是**技能包 + 工作流**。
- 怎么读：真正可复用的是「分工结构」——LLM 不做数值，只做编排与推理，计算交给确定性工具。这套结构比具体技能更值得抄。

### Google Cloud：物理工程基准 PLE，只放 29 道公开题

- 位置：`cloud.google.com/blog/products/ai-machine-learning/introducing-physical-engineerings-last-exam-for-agents/`，`pubDate` **2026-11-03 08:00 UTC＝北京 11-03 16:00**；与 Mercor 合作，含公开竞赛与排行榜。
- 规模：**85 道长程任务**，覆盖机械、电气、土木、结构四个方向；公开 **29 道** + 评分工具；每个任务平均 **61 个文件**（全库 5,170 个），含 PDF、表格、邮件、2D CAD 图、3D BIM 模型与图纸修订版。
- 构造方式：44 道由执业工程师原创（任务、提示、评分细则），41 道由工程师设计、agent 流水线从可授权工程标准里装配环境与评分器，再由工程师逐条加难与校验。
- 基线结果：14 个前沿模型 × 7 套公开 harness（Antigravity、Claude Code、Codex、Hermes、OpenCode、OpenHands、Pi）；**私有测试集上全部低于 50%，最高配置 48.3%**；单项约束满足率最高 91%，但**只有 41.3% 的交付物通过全部硬性安全与可行性检查**。
- 计分特点：先过硬安全闸才拿分，既要合规也要成本效率——所以「能算对」不等于「能交付」。
- 怎么读：这是继 CWE-bench 之后又一把「专业交付物」尺子，且和 SWE 类基准的关键差别是**多文件、跨格式、要查规范**。48.3% 这个数字对做工程类 agent 的人是冷水：真实工作里最难的是一致性与可审性，不是单点计算。

### Hugging Face：CWE-bench v2 公开 100 条漏洞修复任务

- 位置：`huggingface.co/blog/cwe-bench`，发布日 **2026-11-03**；作者含 HF 的 Nazneen Rajani、Nathan Habib 与 Collinear AI 团队。
- 是什么：面向前沿网安能力的 agent 基准，公开 **100 条任务、覆盖 91 个 CWE**；agent 拿到真实开源仓库的 checkout 与一句简短指令，要在不破坏既有功能的前提下设防；评分全程序化、可复现；另留 held-out 集。
- 结果（11 个模型）：**Gemini 4 Argon 以 67.8% pass@1／81.0% pass@4 领先，Claude Opus 5.5 以 67.3%／78.0% 紧随**；95 道题至少被一个模型解出，但榜首模型仍有 19% 的题每次尝试都失败。
- 成本维度：DeepSeek V4.1 Flash（1017）57.0% pass@1、每次 rollout **$0.04**；Opus 5.5 高 10 分、$1.83；Gemini 4 Argon $3.92——三者构成成本-效果帕累托前沿。
- 工程细节：每道题是自包含的 Harbor 任务（Docker 环境 + 指令 + 确定性验证器），数据集带 `registry.json`；排行榜分两处，开放权重模型在数据集页、含 API 模型在 leaderboard Space，靠 PR 提交成绩。
- 怎么读：模型之间只差 0.5 个百分点、成本差 45 倍，这条对选型的意义大于排名意义。

### Hugging Face：Transformers 引入「模型集成契约」

- 位置：`huggingface.co/blog/transformers-mic`，发布日 **2026-11-03**，作者 Tarek Ziadé。
- 起因：**2026-07-30** Transformers 为 T5 启用 PyTorch SDPA，副作用是 UMT5 解码器能看到未来 token——训练时等于偷看答案；没有崩溃，这个 bug 在 main 上待了将近两个月。
- 做法：把真模型「缩小」成 fixture（层数更少更窄但层类型齐全、tokenizer 与 processor 不变），发布一次长期复用，在廉价 CPU runner 上跑快速集成测试；UMT5 fixture 权重 **66MB**，原检查点 **1,227MB**。当时一个小 UMT5 在 CPU 上能对每一个相关问题提交报警。
- 背景规模：Transformers 支持 750+ 模型类型，main 上 88,000+ CPU 测试、每日 200,000+ GPU 测试，全量跑不现实。
- 怎么读：这是「框架层怎么防回归」的范式——用缩小模型换覆盖率，用确定性检查换速度；对自建推理栈的团队直接可抄。
