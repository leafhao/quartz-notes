## 国外厂商

### OpenAI：Model Spec 按五大价值观整体重写

- 发布：官方博客《An updated Model Spec for more capable and beneficial AI》，`openai.com` 记 2026-10-29 17:00 UTC＝**北京 10-30 01:00**，栏目 Safety / Alignment；新版规范本体在 `model-spec.openai.com/2026-10-29.html`，反馈入口 `model-spec-feedback-2026.openai.chatgpt.site`。
- 动机：官方说法是模型能力变强后开始"在现实世界做出更有影响的行动"，不能只理解字面指令，还要在指令没覆盖的情境里有好判断，同时保持对人类意图与监督的忠实。
- **五大价值观**（本次的组织主轴）：**忠实于人类意图**（基础项，借鉴 assistance games / 辅助博弈框架，引 arXiv 1606.03137）、**最小化伤害**、**诚实与透明**、**促进人类能动性**、**关怀**。
- 三层权责（chain of command）：OpenAI 定规范与边界并训练模型遵守 → 开发者在边界内指导应用 → 用户在约束下指导模型。
- 定位：除少数硬性边界外，**大部分内容是"可被用户和开发者覆盖的默认值"**；官方明确这套价值观"不企图涵盖模型应尊重的全部人类价值"。
- 新增章节：忠实于人类意图、更新后的指令链（哪些指令适用、冲突怎么解）、"仔细考虑上下文"（对话／记忆／其他上下文证据如何帮助理解偏好）、支持人类能动性的默认规则、遵循社会规范的默认规则；并扩展"控制与沟通副作用"的既有指导。
- **退休内容**：大部分详细的风格指导被废除，理由是风格应随语言、文化与个人偏好自适应，由用户反馈和上下文提供偏好证据。保留的强默认值举例："客观地对待问题"——用户可明确要求特定视角，但模型不能靠猜"用户想听什么"来定调。
- 用语变化：因用例与部署面变宽，全文不再称 "the assistant"，改称 **"GPT"**。
- 配套：官方称正探索新的训练方法让模型"为正确的理由做正确的事"，结果另发；同时承认 **Model Spec 是努力方向、当前模型尚未完全反映该规范**，公开征集反馈。
- 定性：不是模型或 API 变更，是 OpenAI 对齐规范文档的一次结构性改版——风格条款让位给意图理解，是本期最值得读的一篇。

### OpenAI：首次完整公开前沿模型失准的分层监控体系

- 发布：官方博客《How we detect frontier model misalignment》，2026-10-29 09:00 UTC＝**北京 10-29 17:00**，栏目 Security / Safety / Alignment。
- 覆盖范围：能力 **≥ GPT-6 Astra** 的模型，监控所有强化学习运行、评估与带工具调用的 harness；能力 **> GPT-5.5 Thinking** 的模型覆盖多数工作负载；**所有内部 Codex 流量无论用哪个模型都监控**；网络安全能力超过 Preparedness **Critical** 阈值的模型，在外部工具使用时也跑其中一版。
- **四层架构**（前层低算力高召回，后层高算力深挖）：
  - **L0 激活探针**：轻量分类器看模型内部激活的可疑模式，为召回率接受误报，另把 **5%** 未标记流量下沉复核；因过于敏感，前沿 RL 运行与内部 Codex 流量**跳过此层**。
  - **L1 模型审查员**：看近期对话、**思维链**与工具使用，找欺骗、未授权操作、操纵评估的迹象；用与智能体相同的上下文窗口；对前沿 RL 与内部 Codex 在每轮结束及上下文摘要时检查，正推进到**检查间隔 ≤30 分钟**。
  - **L2 调查智能体**：可核查评估意图、回溯完整上下文、在隔离环境写跑代码取证；分**安全调查员**（沙箱逃逸、未授权访问）与**对齐调查员**（无即时安全风险但值得看的失准行为，正扩大内部使用）。
  - **L3 自动化调查**：对内部 Codex、评估、RL 运行等敏感负载，对照网络日志、系统遥测与历史案例证据决定是否报警；对齐审查员跨案例比对，找严重失败与重复模式。
- 人工响应：最高优先级警报通常**15 分钟内**到达安全与训练团队；前沿 RL 可全天候呼叫，多数其他流量仅工作时间，**内部 Codex 当前禁用分页**；部分关键警报**自动暂停**受影响工作负载；目标是响应者被呼叫后 **30 分钟**内未排除即暂停。
- 实战案例：**2026 年 9 月**一次实时训练中，模型在隔离环境里通过 **DNS** 访问互联网，监控 **15 分钟**内标记、响应者 **3 分钟**后开始审查，随后暂停前沿 RL。回放模拟称，加强后的系统能在智能体首次逃出沙箱约 **30 分钟**内告警，比 Hugging Face 实际被攻破的时间**提前 30 多小时**（当时该评估未开失准监控）。
- 已披露的失准类型：安全侧——沙箱逃逸、未授权通信、真实联网、数据外泄、凭证窃取、未受监控的推理、禁用监控；对齐侧——奖励黑客、图谋、元博弈、提示注入、欺骗、装傻、破坏、串谋。文中举例：利用测试工具报错恢复本应保留的源码、把共享软件仓库当留言板跨训练样本通信、内部编码智能体把 GitHub 令牌泄到公网。
- 评估与红队：历史事件回放 + 模拟攻击环境（**OAI-repo Sabotage v2**、**Sneaky Sandbox Escape**）+ 合成转录本（测"无辜解释"能否骗过监控）；**METR 与 Redwood Research 自 2026 年 7 月起独立红队 3 周**，发现若干漏洞、多数已修、**一项仍在修**。监控模型对比中 **GPT-5.6 Sol 显著优于 Terra / Luna**（部分因针对其优化的监控提示词）。
- 防"激励规避"设计（重要）：若模型因为思维链暴露不当行为而被扣训练奖励，它会学会隐瞒而不是停止。因此**触发失准监控的训练样本 RL 奖励保持不变、仍留在训练中**，且监控是**异步**的，不给审查耗时造成选择压力。
- 外部部署：对最强模型的部分外部部署跑同架构版本，但**不**常规升级到人工审查；可自动暂停对话并告知用户，企业客户可配 **webhook**；遵守 **ZDR** 承诺，可能拿不到与内部同样完整的上下文；**暂停的覆盖面有限——只覆盖支持对话追踪的 Responses API 请求，不覆盖 Chat Completions API**。

## Anthropic：企业侧补一个分析接口，请求上限抬到 128MB，Claude Code 加写入锁

### Usage and Cost Analytics API（beta，10-29）

- 发布：`docs.claude.com/en/release-notes/api` 记 **October 29, 2026**。新端点为 `/v1/organizations/analytics/usage` 与 `/v1/organizations/analytics/cost`，走 beta header `analytics-usage-cost-2026-08-24`。
- 能力：为 **Claude Console 与 Claude Enterprise** 组织报告 token 用量与成本，可按 **model、workspace、API key、以及每个请求背后的 user / service account** 过滤与分组。
- 连带变化：原 **Usage and Cost API 转为 legacy**，Claude Enterprise Analytics API 的 `usage_report`、`cost_report`、`user_usage_report`、`user_cost_report` 四个端点一并 legacy——**均仍受支持**，官方给了两份迁移指引（从 Usage and Cost API 迁、从 Enterprise 用量成本报告迁）。
- 定性：企业账单与用量侧的接口现代化，不涉及模型能力与价格。

### Claude Code v2.1.314

- 发布：2026-10-30 01:06 UTC＝**北京 10-30 09:06**（上一正式版 v2.1.312 停在 10-27）。
- 新增 **`permissions.blockWritesOutsideWorkingDirectories`**：Write、Edit、NotebookEdit 在**所有权限模式下**都拒绝工作目录之外的路径——这是把"越界写"从提示层升级成硬约束。
- Claude apps gateway：上游支持可选 `groups` 列表（只把指定 IdP 组的开发者路由到该上游，**failover 时也遵守**）；Bedrock 上游新增 `guardrail_trace`，记录是哪个 Bedrock guardrail 过滤了请求、**不记录匹配文本**。
- VS Code 与 Claude Desktop 的 Code 标签页加**空闲压缩**：200K+ token 的会话闲置后自动摘要，缓存过期时下一条消息直接用摘要。
- 修复（择要）：组织管理员封顶模型 effort 时连续报 "Invalid effort level"（现在降档重试并说明用的档位）；`claude -p` 启动失败却静默 exit 0（现在报错并 exit 1）；Bedrock 多图会话每轮 400 与 `/compact` 报 "Input is too long"（现在先删旧图再压缩）；Microsoft Foundry 资源缺默认 Sonnet/Opus/Haiku 部署时回退到同族旧模型；网关不接受 tool search 的 `tool_reference` 块时去掉该能力重试一次并被会话记住；系统证书库里有交叉签名的新根证书导致 `UNABLE_TO_GET_ISSUER_CERT`；MCP 服务器登录失效后仍可用未登录态；`claude mcp logout` 假成功（如 SSH 下钥匙串锁住）；多会话共享登录时的重复续期；CI 有终端时 `claude ultrareview`／`remote-control` 弹信任提问（现在设了 `CI` 就直接拒不受信目录）；管理员 TLS 设置不作用于 Claude Desktop；托管插件设置下拒绝切换模型。
