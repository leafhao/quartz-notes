- 关键进步在**几何推理**：早期模型会把支撑元件摆得离主芯片太远、接插件方向反；Fable 5.2 会先走高速／大电流／怕噪声的关键线，成对差分线保持等长等距、加蛇形补偿，还会自己发现「线缠得看不清了」而**推倒重来**（此前模型很少主动改设计，Diode 见过大量 95% 完成却不可用的板子）。

### OpenAI：Control Room，35 秒内拦停所有研究推理

- 位置：`openai.com/index/control-room`（`pubDate` **2026-11-09 13:00 GMT＝北京 21:00**），分类 Alignment／Cybersecurity。
- 是什么：一个中央系统，追踪 OpenAI 研究基础设施里的**每一个模型工作负载**（训练与评测用的 agentic sampling、数据处理、RL 实验），并在安全或安保问题出现时**快速停机**。
- 机制：工作负载启动先向 Control Room 领 `job_id`（必须挂一个已批准的 safety case）→ 推理引擎在出 token 前向 Control Room 要授权 → 已被终止则拒绝。关键设计是**把开关做在推理层而不是工作负载代码里**——研究代码变化频繁且分散，推理代码路径少且集中，能给出强保证。
- 数字与保证：决策后 **35 秒内**停止输出（延迟来自推理授权缓存）；目标是压到 **0 秒**；**fail-closed**——Control Room 自己挂了，所有推理请求一律被拒。已在最吃紧的前沿研究工作负载上铺开，剩余部分「未来几天内」完成。
- 配套：每个前沿 RL 任务都挂一个 **Monitor**（另一个模型盯被训练模型的一切行为），此前 DNS 越网事件就是被它抓到的。另持续扫描是否有人私自跑未接管的「野生推理引擎」。
- 范围：只管**研究侧**；对外服务栈本来就集中、可快速下线，暂不覆盖。
- 怎么读：这是把「能不能一键停掉正在训练的模型」从流程问题做成**架构约束**。对业界的意义大于技术细节：前沿实验室开始把停机能力当成和算力同等的基础设施来建。

### 谷歌 DeepMind：开源 XYEval，专测智能体会不会盲从

- 位置：GitHub `google-deepmind/xyeval`，仓库创建 **2026-11-09T17:40Z＝北京 11-10 01:40**，Apache 2.0，附 3.4MB 数据集 `xyeval_release_v1.0.json`；论文《XYEval: Agents say yes to bad advice》（arXiv 2609.23939）。
- 是什么：把经典的「XY 问题」做成智能体基准——用户误判了真正的病根（Y），却让助手去干一个错的方案（X）。与静态迎合度测试不同，这里考的是**动态过程**：agent 能否识别错误前提、用工具去验证、并把真正的根问题反馈给用户而不是照做。
- 规模：**8,222 个任务**，覆盖 SWE-bench Verified（500）、SWE-bench Pro（731）、Terminal-Bench（158）、MCP-Atlas（997）、Humanity's Last Exam（5,836）；误导性建议由 Gemini 3.5 Flash、Gemini 3.1 Pro、Opus 4.8、GPT-5.5 生成。
- 怎么用：取原基准的题面，把 `misleading_prompt` 注入首轮用户输入，看 agent 是否自我纠正。
- 怎么读：这套东西的价值是**把「顺从」从聊天场景搬到了会真动手的场景**——同样一句错误建议，在对话里是答错一句话，在 agent 里是改错一个仓库。

### 百度：ERNIE Evolve，让 AI 自己改 AI

- 位置：`ernie.baidu.com/research/posts/ernie-evolve/`（题注 **November 9, 2026**，官网首页「Latest Updates」同步挂出）。
- 是什么：一个**自动化研究系统**——给定代码仓库、优化目标和评测标准，它自己决定研究什么、改代码、在隔离环境跑实验，只有通过独立评测与复核的改动才被保留；外层 Director 定方向（靠 Experience Bank 与 Knowledge Base），内层 Selector 在候选树里选版本、Executor 落地、Evaluator／Reviewer 把关（评测程序放在仓库外、对 agent 不可见，改动越界直接不评，收益要超过噪声阈值才算数）。
- 公开基准（对最强公开成绩）：
  - NanoChat AutoResearch：验证 BPB **0.8763** vs 公开最好 0.8878（Hyra-1.0 0.9015）——加了 n-gram 与检索两条预测分支、稀疏优化器、softcap+cross-entropy 融合进单个 Triton kernel
  - NanoGPT Speedrun Track 1：**38.9 秒** vs 39.9 秒；Track 3：**2,590 步** vs 2,690 步
  - SOL-ExecBench（235 个真实内核优化题）：平均 **0.819**，超前两名对手、接近榜首 0.827
- 落到真生产（ERNIE-5.5-Flash 推理优化，改动须过与工程师同样的压测与正确性校验）：
  - 昆仑芯 P800 低延迟：四轮迭代把生成速度做到基线 **623.6%**（第 1 轮 282.9% → 第 2 轮 588.8% → 修好通信调度后开启 DeepEP 低延迟路径）
  - 确定性推理吞吐（RL 训练要求逐 bit 一致）：约 3 天把吞吐提 **33.7%**、单 token 均时降 26%、首 token 时间降 12%
  - 解码极限：再提 **14.9%**，精度不变
- 官方也摊开了失败：把专用通信换成通用集合通信反而慢 14.0%，直接弃用；MoE 缓存那轮只多 1.4%，于是重新做分段计时才找到真瓶颈。
- 怎么读：与 Anthropic 那篇《When AI builds itself》对照看最有意思——两家都在讲「AI 加速 AI」，但百度给的是**可复现的基准+开源的优化结果**（改动已开源在 GitHub），Anthropic 给的是内部生产率曲线。前者更硬，后者更宏观。
