### OpenAI：GPT-6 Cyber 上线，网络安全能力被评为 Critical

- 位置：`openai.com/index/introducing-gpt-6-cyber`（`pubDate` **2026-11-05 09:00 GMT＝北京 17:00**），分类 Product；系统卡 `deploymentsafety.openai.com/gpt-6-cyber`。
- 是什么：专攻**发现并验证可利用漏洞**的安全模型，训练目标写得很明确——在研究人员设定的授权范围内行动、遵守动作限制、准确报告结果。
- 基准：ExploitGym（按指定漏洞做利用）**48.5%**，上一代 GPT-5.6 Cyber 是 **32.1%**，绝对提升 16 个百分点、相对约 51%；Web 渗透测试召回 **40.3%**（GPT-6 Astra 32.0%）；RemoteExploitBench（GitLab／PostgreSQL／Jenkins 等真实应用、受控环境，做远程利用）**完成 95%**，相比之下 GPT-6 Astra 加 Daybreak Blue 是 100% 拒绝执行。
- 越界控制：ExploitGym Honeypot 里，无部署提示词时避开越界服务 **99.93%**（GPT-5.6 Cyber 94.49%），有部署提示词时 **100%** 留在范围内。
- 实战：Linux 上复现 1,724 个漏洞、写出 **948 个可用提权利用**（GPT-5.6 Sol 是 166 个），已向维护者披露 304 个关键发现并附候选补丁；Firefox 上找出 **81 个此前未知的高危漏洞**，另有 30 个已知问题被证明比原报告更严重，Mozilla 已发修复；Brotli 上论证了可导致下游 RCE 的关键缺陷。与 Dragos 在模拟电厂环境评估时，模型自行发现**两个零日**（管理保护继电器数据的工程软件）。
- 分级：Preparedness Framework 下网络安全类别评为 **Critical**，上一代是 High——这是该框架目前给出的最高档。
- 可用性：**初期只通过 API 与 Codex 开放**，面向一批已批准的 **Daybreak Red** 客户，之后逐步扩到全部 Daybreak Red；同时向所有 Daybreak Red 客户提供 GPT-5.6 Cyber。Daybreak Blue（基于 GPT-6 Astra）alpha 扩到更多机构与独立安全研究员；新增 **Daybreak Red for Critical Infrastructure** 分组。配套 10 亿美元的 Daybreak for Frontline Defenders 资助计划。
- 防护（这版的重点之一）：网络专用错位监控（区分「合法漏洞开发」与「越权」）、针对新兴威胁的定向监控（例如 PHP 漏洞协同披露期间盯真实 PHP 服务器的利用尝试）、Private Safety Processing（用 ZDR 的 API 客户一般必须开，加密记录留 30 天、不向员工暴露提示与响应）、**Daybreak Red API 默认要求 IP 白名单**、凭证泄露监控、高风险网络协助拦截。官方特意写明「拦截率高不等于更好」，不以 100% 为目标。
- 未披露：**没有公布定价**，官方只给了资助计划（10 亿美元，补贴资源受限的防守方团队）。
- 怎么读：真正的分水岭不是那 16 个百分点，而是**「攻方能力」第一次被官方自己评到最高风险档还照样放出来卖**。OpenAI 的处理方式是把风险装进客户白名单 + IP 白名单 + 行为监控三层，等于承认这类能力已经不适合开放式供应。对防守方，可操作的结论只有一条：低权限账户在未打补丁的系统上应视同 root，沙箱比内网信任更值钱。

### Anthropic：Anthropic Institute 首次量化「AI 造 AI」的进度

- 位置：`anthropic.com/institute/recursive-self-improvement`，标题《When AI builds itself》，sitemap `lastmod` **2026-11-06 03:24Z＝北京 11:24**（发布即窗口末尾）。
- 主张：Anthropic 正把越来越多的模型开发工作交给 AI 自己做，趋势指向「AI 自主设计下一代 AI」（递归自我改进）；官方明确说**还没到那一步，也不是必然**，但可能比多数机构准备好的时间更早。
- 外部证据：模型能独立完成的任务时长**约每 4 个月翻一倍**（此前是 7 个月）；2024-03 的 Claude Opus 3 约 4 分钟级任务 → 一年后 Sonnet 3.7 约 1.5 小时 → 再一年 Opus 4.6 达 **12 小时**；METR 测 Claude Mythos Preview 至少能连续工作 **16 小时**、已到该基准不给新任务就测不出的上限；SWE-bench 两年内从个位数打到饱和，CORE-Bench（复现论文结果）从 2024 年约 20% 到 15 个月后饱和。
- 内部证据（首次公开）：截至 **2026 年 5 月，Anthropic 合并进主库的代码中 80% 以上由 Claude 撰写**（Claude Code 2025-02 研究预览之前是个位数）；2026 Q2 典型工程师**人均日合并代码量是 2024 年的 8 倍**（官方自己标注 LOC 不是好指标，真实生产率提升被高估）；2026-03 对 130 名研究岗员工的调查，产出中位数自评约 **4 倍**。
- 质量与判断力：最开放任务上 Claude 的会话成功率 2026-05 达 **76%**，半年提升 50 个百分点；用自动化 Claude 审阅回溯跑历史变更，**能提前拦下约三分之一**造成 claude.ai 线上事故的 bug；官方口径是「2025 年底 Claude 写的代码略差于人类，现在大致持平，一年内应严格更好」。
- 研究侧：内核优化这类「目标给定、方法自找」的实验循环，2025-05 Opus 4 平均提速约 **3 倍**，2026-04 Mythos Preview 达约 **52 倍**（人类专家 4–8 小时做到 4 倍）；2026-04 那个端到端自主研究项目里，两个人类研究员一周补上 23% 的差距，**agent 用 800 累计小时、约 1.8 万美元算力补上 97%**（官方标注该结果未能干净迁移到生产规模模型，问题与评分标准仍由人定）。
- 缺口：**选目标**——工程与研究里「该做哪个问题」的判断力仍明显落后于人类，这是当前 AI 与「能自主设计后继者」之间的真实距离。
- 怎么读：这是目前唯一一份**厂商自曝内部生产率数据**的长文，价值在于把「AI 加速 AI」从叙事变成可核对的曲线。同时它自带利益相关：Anthropic 既在证明进展，也在为「需要更强监管与监控」铺垫论据。读的时候把 8 倍 LOC 和 76% 成功率当**同一家的自评**看，别当独立评测。

### Anthropic：20.7 万次科研会话，科学家主要用它做数据分析和写作

- 位置：`anthropic.com/research/how-researchers-use-claude`，`datePublished` **2026-11-05**（sitemap `lastmod` 11-05 16:54Z＝北京 11-06 00:54），Economics 团队，附 PDF。
- 方法：用隐私保护管线（LLM 做分类器，只留领域／任务标签，不存研究内容）标注 **207,049 个消费级会话**（2026-08-02 至 09-30），其中 Claude（Chat＋Cowork）128,914、Claude Code 78,135；分类体系用 SciNet（34 个领域、318 个子领域、7,262 个任务）；另做 528 名科学家的问卷。
- 领域分布：Claude 上会话占比最高的是计算机（11.9%）、工程（8.4%）、医学（7.7%）；但相对「该领域研究者占比」，**形式科学（CS、数学、统计）明显超配**，化学等实验型与医学低于线。Claude Code 上 CS 只占全球研究者 4.3%，却占 **32.7%** 的会话。
- 任务分布：**数据分析占 Claude 会话 33.7%、Claude Code 会话 48.1%**，而研究者实际花在这上面的时间是 27.6%；写作与沟通在 Claude 上 32.0%（实际时间 16.0%）；**数据采集只占 11.5%／11.9%**（实际时间 28.6%）；**想法与假设生成只占 4.2%／2.1%**（实际时间 7.1%）。
- 反差：问卷里科学家把「提出想法」排第一、「采集数据」排第二，恰恰是使用最少的两类。Claude Science 上想法生成的占比约为通用 Claude 的 **2 倍**，说明专用工具能拉平这个缺口。
- 加速情景：按现有能力广泛采用，部分领域产出可**翻倍**；若 AI 承担全部非物理工作，CS／统计这类高认知领域产出可涨 **15 倍**，化学生物受物理瓶颈限制约 **3–4 倍**；受访者中约 **40%** 认为到 2030 年模型能独立完成完整研究项目。
- 怎么读：值得注意的是**「用在哪」和「觉得哪重要」的错位**——AI 现在最会干的（数据处理、写作）正好不是科学家认为最关键的（选题、取数）。这条缺口既是产品机会，也是「AI 让科研提速多少」这句话最容易被夸大的地方。

### Meta：Muse 上线实时语音与表情虚拟人

- 位置：`about.fb.com/news/2026/11/introducing-muse-ai-voice-expressive-avatars/`（`pubDate` **2026-11-05 18:30 GMT＝北京 11-06 02:30**）。

- **不可用／需绕过**：`developers.openai.com/api/docs/changelog` 与 `.md` 本轮均 **403**（WebFetch 同样 403）；`ai.google.dev/gemini-api/docs/changelog` **000**（连 `-L` 也拿不到文件）；`docs.claude.com` 与 `platform.claude.com` 的发布说明只剩外壳，且 WebFetch 被跳到 `app-unavailable-in-region`；`ark.volcengine.com/api/models.json` 与 `/api/model/list` 现在都返回 SPA HTML，**不再是 JSON**；`minimax.io/news`、`qwen.ai/blog`、`hunyuan.tencent.com`、百度千帆仍是 JS 壳。
- **教训/新入口（重要）**：① **`ark.volcengine.com/api/models.json` 已失效**（返回 SPA 壳），改走 `sitemap.xml`——541 条带 lastmod，模型页 `/models/<id>.md` 仍可用，看「窗口内是否有模型页 lastmod」比解析 JSON 更稳。② **`docs.bigmodel.cn` 的 HTML 里 `dateModified` 会骗人**：页面 dateModified 是 11-05，正文最新条目却是 08-26；`.md` 版本才是正文真相，两者要对照看，否则会误报智谱发新版。③ **Anthropic 的 `/institute/<slug>` 是新的高价值入口**——不在 `/news` 也不在 `/research`，只在 sitemap 里以 lastmod 出现（本期 11-06 03:24Z），静态 HTML 正文完整、无需 WebFetch。④ **Google 的视频模型发布要同时看 `blog.google/rss/` 与 `deepmind.google/blog/rss.xml`**：本期两条 `pubDate` 相差 5 分钟（17:00 与 17:05），DeepMind 那条会 301 跳到 blog.google，以 blog.google 为正文来源。⑤ **Meta 的 Muse 类产品稿在 feed 里的 slug 不可猜**（`give-your-muse-a-voice` 是 404，真 slug 是 `introducing-muse-ai-voice-expressive-avatars`），必须从 feed 的 `<link>` 取。⑥ 「国内真静默」的判据再加一条：方舟 sitemap 里只有 `docs/*` 更新、没有 `models/*` 更新，即可判零新模型。
