## OpenAI：ChatGPT Wallet

三处官方口径互证：博客 `openai.com/index/introducing-chatgpt-wallet`（11-13 15:00 GMT＝北京 23:00）；帮助中心 ChatGPT Release Notes 同日条目；商家侧文档 `developers.openai.com/commerce`。

- **是什么**：第一个「智能体不接触真实卡号即可付款、且每笔都要安全验证」的钱包。与 **American Express、Mastercard、Visa** 三家合作，卡网络在结账时签发**支付令牌**（卡号、安全码、有效期的替代凭证），真实卡信息既不交给智能体也不交给商家。
- **谁能用**：仅**美国**、**18 岁以上**、**ChatGPT Pro** 订阅者，需美国发行的合格银行卡与美国账单地址；首发通过 **dots**（ChatGPT 的常驻代理）限量推送。
- **怎么付**：事先存一次卡，之后每笔只需核对商家、商品、总额与所选卡片，再用 **Face ID / 指纹**放行；每次批准生成一条该笔授权的记录。原文明确：授权不等于订单确认，仍以商家确认为准。
- **保留的权益**：原卡的**积分奖励**与符合条件的**争议保护**不变。
- **下一步**：官方称「随时间」可设**消费上限、品类、时间段**，把购买完全委托给智能体，用生物识别做预授权。
- **商家侧配套**（Commerce Partner Playbook）：在 ChatGPT 认领商家并上传带实时价格与库存的商品 feed；按 **Web Bot Auth** 识别签名请求，避免 CDN/防火墙把智能体当爬虫拦掉；风险侧与 **Forter、Riskified、Sardine、Signifyd** 合作，支付侧与 **Adyen、Checkout.com、Stripe** 合作识别合法智能体交易；可写插件查库存/管购物车，或在站点上挂 **WebMCP** 工具。
- **量级**：文中给出「每周 12 亿人使用 ChatGPT」。**未公布任何费用或抽成**。

## 谷歌：Google Wallet 接进 Gemini

`blog.google/.../google-wallet-gemini-app/`（11-13 17:00 GMT＝北京 11-14 01:00）。

- **范围**：**美国全部 Gemini app 用户**（Web、Android、iOS 都支持），不要求付费档。
- **用法**：对话里 `@Google Wallet` 直接问个人财务——回看某季度支出、找还在扣的订阅与涨价项、按去年花销排节日预算；答案里会生成动态图表。

- **附带**：Memory Summary 同日开放——集中查看、编辑、删除 Gemini 记住的偏好、兴趣与在办目标（Profile → Personal Intelligence）。

三家在同一个 72 小时内都碰了「钱」：Anthropic 11-05 已上 Personal Finance in Claude（Plaid 只读，Pro/Max/Ultra）。区别在于 OpenAI 走**代付**（写权限，靠令牌与生物识别控风险），谷歌与 Anthropic 走**只读洞察**。

## Anthropic：常驻智能体的五个原语

`claude.com/blog/building-always-on-agents`（11-13）。工程指南，不是产品发布，但把「常驻代理」讲成了可照抄的架构。

- **五个原语**：**事件收件箱、定时器、记忆、权限、发件箱**。一次 run ＝收一个事件、干完活、写回记忆、再去睡。
- **收件箱**：所有来源（webhook、定时任务、后台作业）不直接调模型，而是往收件箱写一行；处理器要**快速应答**（深校验如提示注入检查放到 run 里做）；**同一收件箱只允许一个活跃 worker**；worker 醒了先拉最新事件，死了能被新 worker 重试；连续多条消息可**合并成一次 run**。
- **记忆**：只存「查不回来的东西」，已在别处（如 issue tracker）的存**指针**不存副本；用户指令、用户画像、已告知过什么、每个任务的进度文件各自独立，启动只加载索引。
- **权限**：常驻代理最大的风险点——它握着用户权限、无人看守地跑。凭据走**代理**注入（智能体发无凭证请求，代理转发前补上），高风险动作交**auto mode 的分类器**拦，最重要的决策仍需人审；需要人拍板时把调用 **deferred**，run 结束、会话存盘，用户答复回来变成收件箱里的新事件，从上次的位置续跑。
- **发件箱**：只在要控节奏或要能从错误里恢复时才需要单独的出站表＋dispatcher；建议**先安静、再慢慢挣注意力**，用评测定发送阈值。
- **数字**：Opus 5.5 在长程任务上**每解一题比 Opus 5 便宜 78%**（常规工作负载只便宜 40%）——这是官方认为常驻代理「重新可行」的成本依据。

## Anthropic：安全评测怎么样才算数

`anthropic.com/research/building-strong-safety-evaluations`（11-13，新闻列表首条）。

- **核心主张**：安全宣称的可信度只等于背后那份评测。照搬心理学与医学的 preregistration、更好的测量与更严的统计，是这篇的方法论底子。
- **构造选错是最常见的坑**：安全评测的显然构造是**拒答率**，但在自杀/自伤场景里「拒答本身就是失败」——理想回答是共情＋安全规划＋在正确时机给危机资源。所以 Anthropic 改报**多轮「恰当回应率」**：整段对话都恰当才算过，一轮失守整段判失败（如被反复施压下说出诈骗操作细节）。
- **双用途领域要成对测**：同一话题配两条 prompt——有害请求（测无害回应率）与良性请求（测误拒率），如神经毒剂配方 vs 化工厂事故史；标准是「帮正当的那部分，扣住能造成实际增强的操作细节」。
- **场景要像真的**：单轮 prompt 很快饱和，人是在多轮里逐步升级的；用**独立 Claude 生成模拟用户**后续回合，按 persona、处境、语气、话术多维采样，每条从同一句开场出发；grader 按领域专家写的 rubric 打分。
- **覆盖度**：单轮安全套件跑 **16 个政策领域、7 种语言**与多个产品面，不只在 API 上测。
- **安全操作**：评测常在关掉常规护栏的前提下跑，因此须在**无联网沙箱**里并实时监控；官方称近月因相关事件**暂停了多数给模型联网的评测**，对必须联网的检索评测加了实时监控。

- **六个新模型**：**Inkling2**（Thinking Machines 的 Inkling 2 Small，48 层 MoE、每 token 路由 384 专家中的 8 个，**594B 总参 / 17B 激活**，视觉塔基于 Perception Encoder，40×40 像素一个 patch）、**LFM3** 与 **LFM3-VL**（Liquid AI 第三代，卷积＋GQA 混合，VL 吃原生分辨率图像与视频）、**Dots 3 Note Preview**（原生文本/图像/视频/音频，Whisper 式音频编码器，BF16 与 FP8 推理）、**InternLM3**（上海 AI Lab 8B instruct）、**IQuestCoder**（IQuest Lab 7B/14B/40B，base/instruct/thinking 三档，架构同 Llama）。
