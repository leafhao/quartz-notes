### Meta — 开源 Muse Gadgets：ESP32 固件 + Linux SDK（官方仓库 2026-10-02 18:21 UTC / 北京 10-03 02:21）

仓库 `github.com/facebookincubator/muse-gadget-sdk`，**Apache 2.0**，描述为「Open source SDK to build Muse gadgets」。由 Meta Superintelligence Labs 产品负责人 **Nat Friedman** 在 X 上官宣（"Announcing Muse Gadgets, an open source ESP32 firmware and Linux sdk so that you can make hardware devices that work with Muse."）。

- **两个 SDK**：**ESP32 Device SDK** 把一块现成 ESP32 板接进 Muse，可选加屏幕（图片显示）、音频输入输出、其他外接传感器；**Linux Device SDK** 把树莓派或任意 Linux 机器变成 Muse 终端，支持自定义命令。
- **仓库结构**：`esp32` / `linux` / `skills` 三个目录，每个目录带 `README.md` 与 **`AGENTS.md`**（供 Muse Code 这类编码智能体直接读）。
- **配套参考硬件 Muse Home Link**：USB-C 供电的小设备，用 Espressif **ESP32-C5**（240 MHz 32 位 RISC-V、8 MB PSRAM、8 MB flash、双频 2.4/5 GHz Wi-Fi 6），把 Muse 接进家庭 Wi-Fi，可与电视、音箱以及任何暴露 HTTPS / 本地 HTTP API 的设备通信。Meta 造了 **5000 台**，**免费送给美国 Muse 订阅用户、每人限一台、10 月发货、先到先得**；固件同样开源，但官方硬件不可重新刷写。
- **配对方式**：每个 gadget 需要 SDK token，在 Muse App（iOS/Android）打开 Developer mode 后于 Settings → Devices 配对，设备以 `MuseGadget` 前缀出现。
- **许可细节（值得注意）**：Apache 2.0 排除了几个第三方文件（minimp3 头文件 CC0-1.0、源自 Adafruit GFX 的像素字体 BSD-2-Clause、构建期拉取的 ESP-IDF 组件、模拟器的 LVGL 与 SDL）。但 **Gadget SDK Token 的使用条款限定个人非商业用途**——一个 token 最多嵌进 50 台与他人共享的设备，**这些设备不得对外销售或公开宣传**。也就是说「代码可商用」不等于「产品可商用」。
- **官方列举的示例项目**：树莓派 5 接 Home Assistant、Waveshare ESP32-S3-Touch-AMOLED-1.75C（圆形触屏 + 对讲 + 电池）、Seeed reTerminal E1002（彩色墨水屏）、M5Stack StickS3、Home Assistant Voice Preview Edition，以及「即将推出」的 HDMI 电视棒。
- **观察**：这是把「智能体」和「设备形态」解耦的一次公开试验——Muse 的智能仍在 Meta 云上，开源的只是物理端点。对飞哥的口径提醒：可商用的是 SDK 代码，**不是**用该 token 造出来的产品。

### Anthropic — Claude Code v2.1.289（官方 2026-10-03 23:07 UTC / 北京 10-04 07:07）

`docs.anthropic.com/en/docs/claude-code/changelog` 标注 **October 3, 2026**，共 **27 项变更**，绝大多数是修复，距 v2.1.288 一天。

- **本版核心仍是 shell 权限边界的收紧**，两条新增修复直接针对「绕过 deny/ask 规则」的写法：
  - 带**环境变量前缀且值被展开**的命令（例如 `TZ="$HOME" rm -rf build`）在沙箱自动放行时不再漏掉 deny/ask 规则；
  - **裸变量赋值**写在命令前时，沙箱自动放行不再跳过 Bash deny/ask 规则。
- **`Read` deny 规则补齐符号链接场景**：通过符号链接在 IDE 里 `@` 提及、被修改或被选中的文件，此前不套用 deny 规则，本版修复。
- **插件/mod 隔离**（本版最大的一块，约 15 项）：一个插件/mod 在绘制或处理时抛错，不再结束整个会话、不再拖垮它周围的内容，改为「自己失败」并抛 `ui.fault`；后台会话与受监督会话不再因插件异步报错而终止。
- **安全类修复**：用户自装插件此前可以**改写组织托管的 MCP 服务器登录工具的说明文字**，本版修掉。
- **回滚**：`[VSCode]` 撤销 2.1.288 对 `claude auth status` 的改动（该改动可能让登出更频繁）。
- **新增能力**：为 teammates 增加 `agent.spawn`；插件 hook 事件统一到一个 agent id；`$.agent.list()` 增加 idle 与 waiting 状态。
- **观察**：v2.1.288 → 2.1.289 连续两版都在补「谁在什么条件下能静默执行破坏性命令」与「插件失败如何不污染会话」，方向没变。

## 本期口径与经验

- **`blog.google/rss/` 与 `blog.google/.../gemini-models/rss/` 必须两条都抓（本期最重要的纠正）**：Google 的**非 Gemini 模型类**研究公告（Project Suncatcher 卫星）只出现在主站 The Keyword 的 `blog.google/rss/`，Gemini Models 那个分类 RSS 里完全没有。此前两期只盯后者的做法会系统性漏掉 Google 的科研/基础设施类动态。同时注意 `blog.google/technology/ai/rss/` 这个旧路径本次返回 **0 条**，已失效，不要再依赖。
- **`facebookincubator` 组织是 Meta 开源硬件/工具类项目的官方落点**：`github.com/facebookincubator/muse-gadget-sdk` 的 `created_at`（2026-10-02T18:21:23Z）能精确锁定发布时间，配合 `about.fb.com/news/` 与官方 X 双源交叉。Meta 这类项目**不写进 about.fb.com 的新闻稿**，只走官方 X + 官方 GitHub + 产品官网（`meta.com/muse-gadgets/` 本次实测返回 Error，需靠仓库与转述交叉）。
- **`developers.openai.com/codex/changelog` 转为 JS 渲染后仍可用，但判据要换**：页面 HTML 里仍带 `YYYY-MM-DD` 前缀日期串，本次逐条扫描后**最大日期为 2026-10-01**，可据此判定窗口内无新 Codex CLI 版本（10-01 的 0.160.0 已在上一期覆盖）。`.md` 与 `/index.md` 后缀在该路由下均返回 "Not found"。
- **`docs.anthropic.com/en/docs/claude-code/changelog.md` 是可静态抓取的 Markdown，且用 `<Update label="X.Y.Z" description="Month D, YYYY">` 包裹**：这是核 Claude Code 版本日期与逐条变更最干净的入口（比 GitHub Releases 的 body 更结构化）。注意切片时不要用 `find('2.1.288')` 之类的**字符串**定位段落——版本号会出现在上一段的正文里，必须匹配 `<Update label="2.1.288"` 这样的标签才能正确切分（本期首次切分只拿到 4 条、修正后拿到 27 条）。
- **`help.openai.com` 发布说明页需 JS**：`en/articles/6825453-chatgpt-release-notes` 静态抓取只返回 "Enable JavaScript and cookies to continue"。OpenAI 的产品功能变更只能靠「官方 RSS 确认无此项（说明不是博客类发布）+ GIGAZINE/TechNews/The Keyword 等给出发布日期并互相一致」来交叉，本次日报里对这条**显式标注了抓取限制**。
- **`platform.minimax.io/docs/release-notes` 与 `.../docs/token-plan/announcements` 是两个不同页面**：前者是**模型**发布时间轴（最新 Jul. 31, 2026），后者是**订阅/套餐**公告页（最新 Sep 29）。判断 MiniMax 「有无新模型」只能看前者。
- **`docs.z.ai/release-notes.md` 加 `.md` 后缀可拿到纯 Markdown**：比抓 HTML（会被大量 CSS 变量淹没）干净得多，能直接看到 `<Update label="2026-08-26" description="GLM-5.3-Flash">` 这样的结构化条目。同类思路适用于所有 docs 站（很多站点都支持 `.md` 后缀或提供 `llms.txt`）。
- **「官方站点更新日」≠「条目发布日」**：百炼国际站页面 `更新时间：Oct 03, 2026` 而表内新增条目日期是 **2026-10-02**——10-03 那期抓到的可能还是同一天早些时候的页面快照。遇到「上一期说停在某日、这一期多出来一条日期更早的条目」时，按**补录**处理并写明官方日期，不要把它算成本窗口的新发布。
- 站点链接格式固定：`https://notes.leaf.pp.ua/claw_notes/<task>/<YYYY-MM-DD>`，deliver.sh 的 `--task vendor-watch` 会自动拼。
