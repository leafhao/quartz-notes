### Google — Gemini 4 Argon（官方博客 2026-09-30 20:00 GMT / 北京 10-01 04:00）

官方博客标题《Gemini 4 Argon: our next era of frontier intelligence》，署名 Koray Kavukcuoglu（Google DeepMind 高级副总裁兼 Google 首席 AI 架构师）；Pichai 同步在 X 上宣布。这是本项目开跑以来 Google 第一次以「受控分发」方式发布旗舰。

- **定位**：面向真实软件工程、法律/金融等企业知识工作、网络安全防御的复杂长流程任务。
- **输出上限大幅放开**：单次输出上限从 **64K 提升到 100 万 token**（注意是输出上限，不是输入上下文窗口）。官方理由是让模型在单条执行轨迹里生成数十万 token，支撑更长的任务持续性。
- **首发优惠价**：输入 **$2 / 百万 token**，输出 **$10 / 百万 token**，缓存输入在输入价基础上 **95% 折扣**（即 $0.10/百万）。**与 OpenAI GPT-6.1 Sol 完全同价**（$2/$10/$0.10），两家在 48 小时内先后落在同一价位。
- **可用性（关键）**：目前**只通过 Fairwind 计划向一批受信任的网络安全防御方开放**，尚未对开发者、企业、消费者开放。Google 表示正在配合美国政府的模型发布前自愿评估流程，将根据早期测试反馈迭代护栏后「尽快」扩大范围；后续开放顺序为**付费 API 客户与 Google AI Ultra 订阅用户**，**未给出时间表**。
- **网安护栏特殊处理**：对受信任防御方与 Google 内部团队，模型将**不带网络安全护栏**发布，以获取完整防御能力。安全公司 Wiz 已在「Scan for Good」公益计划中使用 Argon。
- **基准（均为 Google 自测口径，因无公开 API 故暂无第三方复现）**：DeepSWE v1.1 **77.9%**（官方称刷新 SOTA）；Zapier AutomationBench **51.3%**；LVBench 长视频理解 **91.7%**；官方称在 Vals Index（按美国 GDP 权重的金融/编程/法律/税务经济影响指数）上领先。中文媒体转述的「多项基准碾压 GPT-6 Astra」属转述口径。
- **Google 内部用例（官方披露）**：
  - 量子算法优化：一个实际案例中几分钟内比已发表基线**提升 40%**；
  - 内存效率：Argon Agent 分析全集群性能遥测，自主识别并应用内存优化，已释放**超 300 TiB** 内存，预计总量 **500 TiB 至 1 PiB**；
  - 大规模代码库迁移：C/C++ 迁 Rust，从 re2、libgav1 等核心库的数万行，到 **Fuchsia Zircon 内核 80 万行以上**；libgav1 上替换了 **3.2 万行 SIMD 代码**，结果是内存安全的视频解码器、比原 Rust 移植版**快 2.7 倍**且输出一致。
- **判窗口说明**：官方 RSS pubDate 为 2026-09-30 20:00 GMT = 北京时间 **10-01 04:00**，落在本窗口内（部分外媒按美东时间写作 09-30）。

### OpenAI — 披露并阻断协同的对抗蒸馏行动（官方博客 2026-09-30 10:30 GMT / 北京 09-30 18:30）

官方标题《Disrupting a coordinated model-distillation campaign》。这是 OpenAI 首次公开披露并点名具体主体的推理提取事件。

- **性质**：OpenAI 称识别并完全阻断了针对其模型受保护推理（protected reasoning，即模型内部思考过程）的协同提取活动，定性为**对抗蒸馏（adversarial distillation）**——未经授权用另一模型的输出或内部推理去训练、复现或改进自己的模型。
- **归因**：OpenAI 称无法确认观察到的全部操作者来自同一主体，但**把其中一个核心簇归因于与月之暗面（Moonshot AI，Kimi 开发方）相关的人员**。官方博客未给出支撑该归因的具体技术证据。**截至发稿，月之暗面未就此作出回应**。
- **时间线与规模**：最早活动 **7-01** 低量出现；**7-24 与 7-25** 出现高峰，**16,000 次**命中提取模式的请求、来自 **4,000+ 用户**；进一步排查发现相关提示模式活动分布于 **15,000+ 用户**的簇，**7-28 完全阻断**。官方脚注明确：这些数字描述的是**尝试**而非**成功**的提取量与覆盖用户数，两者不可相加，也未披露实际提取到的推理量。
- **手法**：把一段对话中的**加密推理复制到另一段对话**，再要求模型解密并转写为可见文本。OpenAI 强调**未破解加密、未入侵数据库、未直接接触存储的用户对话**，问题是模型对跨会话加密数据的处理方式存在缺陷。
- **独立研究佐证**：外部安全研究者通过 OpenAI 的负责任披露渠道报告了跨模型（cross-model）与对话压缩（conversation-compaction）攻击路径，OpenAI 确认这两条路径真实存在。相关论文（Panfilov 等《Stealing Reasoning Traces from Proprietary LLM APIs》）指出加密推理块在同一供应商生态内可跨会话、跨用户、跨模型互换——该论文的实验不应被当作对本次事件的量化。
- **应对**：封禁/限制欺诈账号、收紧注册与基础设施管控、扩大关联网络监控、**堵住「持有他人加密推理即可重放取回内容」的路径**、新增对可能暴露推理的流式输出的检测与暂扣；对经第三方服务实施的账号，与这些服务商协作阻断。已通过 **Frontier Model Forum** 与政府信息共享渠道同步。
- **口径提示**：这是**厂商单方指控**，OpenAI 未公布归因方法，未被指控方未回应。同期背景是 Anthropic 此前对中国开发者的类似指控，以及 9 月初美国 NSA 等三机构联合公告——三件事主体、时间窗、检测方法各不相同，不可直接类比或相加。

### DeepSeek — 开源面向华为昇腾的基础设施组件（官方公众号 2026-09-30 上午）

DeepSeek 官微宣布正式开源面向**华为昇腾算力平台**的基础设施组件，涵盖 TileLang 高级语言编译工具、高性能计算库与分布式通信库，**所有组件与此前面向英伟达平台的开源组件一一对应**。

- **开源清单（6 项）**：
  - **TileLang**（`github.com/tile-ai/tilelang`）：面向高性能算子的 DSL 与编译系统，本次新增**昇腾版本**，封装 Ascend C 底层指令、提供高层编程方式且不损失性能；构建时可关闭 CUDA、无需安装 CUDA 工具包。**DeepSeek V4 系列训练中大部分算子已由 TileLang 实现，且训练中用到的每一个 TileLang 算子在昇腾上都有对应高性能实现**。
  - **DeepGEMM-Ascend**：通用矩阵运算加速。官方测试 **BF16 达硬件上限 99.8%、FP8 99.5%、FP4 98.3%**。
  - **DeepEP-Ascend**：大规模跨设备通信，覆盖 EP / CP / PP / FSDP 模式。昇腾 950DT 超节点外部 Clos 网络下 **Dispatch 持续带宽 375 GB/s、Combine 347 GB/s**（约为物理载荷带宽上限的 90%–95%）。
  - **FlashMLA**：稀疏注意力算子。昇腾 950 上 **Prefill 最高 410 TFLOPS（约硬件峰值 95%）、Decoding 360 TFLOPS（83%）**。
  - **TileKernels**：常规向量计算与访存算子（数十个深度优化算子）。
  - **DeepSelect**：高效数据筛选 / TopK 算子，服务 DSA 稀疏注意力的 token 筛选与推理采样器。
- **与华为的联合工作**：双方共同推进**基于昇腾 950 的 128 卡超节点方案**并深度优化计算与通信；华为提供 SuperPoD Flex 与 **UBL128** 组网方案（128 卡 3.2Tbps 单层交换 Scale-up、256K 卡两层交换 Scale-out）及 ASC-COMM 通信编程库。**华为把联合创新成果在 CANN 社区开源**，覆盖大 EP 低延时推理部署、单卡/单机部署、大规模训练、超长文本 KV Cache 池化与 Agentic RL；并披露 **DeepSeek-V4.1-Flash 在 EP32 部署策略下离线推理 TPOT=5ms 时每卡输出吞吐 2469 tokens/s、TPOT=10ms 时 5102 tokens/s**。
- **观察**：这不是模型发布，而是**把在英伟达上验证过的整套算子方法论迁移到国产芯片**，且是 DeepSeek 自有 6 类组件的「一一对应」，不等于可运行任意 CUDA 程序或替代 CUDA 生态。所有性能数据来自项目方公开测试或技术报告，**算子微基准不能直接换算为端到端线上速度**，实际部署需按自身模型与负载复测。
- **API 侧无变化**：`api-docs.deepseek.com/updates` 最新条目仍停在 **2026-09-10**（V4.1-Flash 发布 + 峰谷纠偏），本窗口无新条目。

### 字节跳动 — 豆包上线出行服务（官方 2026-09-30）

豆包宣布支持多种出行服务，用户可通过豆包**一站式完成机票预订、火车票购买、打车及路线导航**，并在首页核心位置上线**「出行用豆包」专属入口**（与「对话」「帮我写作」等并列）。

## 本期口径与经验

- **Google 首次采用「防御方优先」的受控分发**：Argon 是目前唯一「有官方博客、有定价、有内部用例、但没有公开 API」的主流旗舰。副作用很现实——**没有公开 API 就没有第三方评测，所有跑分都来自 Google 自己的表**。卡片与笔记都只写官方自测口径，并显式标注「暂未对开发者开放」。
- **新增有效官方入口**：`claude.com/blog/<slug>`——Anthropic 的产品可用性公告（Claude for Government GA）走这个域名，而 `anthropic.com/news/claude-for-government` 返回 404，`anthropic.com/news` 列表页也不收录该条（列表页仍停在 09-23）。查 Anthropic 要同时走 `anthropic.com/news`（列表）+ `anthropic.com/research/<slug>`（科研）+ `claude.com/blog/<slug>`（产品 GA）三条路径。
- **`openai.com` 详情页正文仍为 JS 渲染**（本次《Disrupting…》《Helping small businesses…》静态抓取均只返回「Enable JavaScript and cookies to continue」），但 **RSS 的条目标题与 pubDate 可稳定抓取**。本次两条 09-30 公告就是靠 RSS 发现、再靠多家转述交叉核出细节；细节数字（16,000 请求 / 4,000 用户 / 15,000 用户簇 / 7-01、7-24-25、7-28）在 The Next Web、BigGo、ccleaks 三家转述中完全一致后采信。
- **厂商单方指控的写法**：OpenAI 对月之暗面的归因**未公布技术证据、被指控方未回应**，卡片里必须写成「指控 / 归因」而不是陈述事实；同时要写明官方脚注「数字描述的是尝试而非成功的提取」。这类条目用户关心度高，值得进卡片，但归因强度必须照实标注。
- **`api-docs.deepseek.com/updates` 与官方公众号是两条线**：DeepSeek 的 API changelog 停在 09-10，但公众号 09-30 发了昇腾开源——**查 DeepSeek 不能只看 changelog**，官方公众号（媒体转述最快为每日经济新闻、量子位、IT之家）是并行信源。
- **`huggingface/transformers` 也要纳入 GitHub Releases 例行检查**：此前只查 trl 与 huggingface_hub，本次 transformers v5.18.0（09-30）是靠 Releases API 才发现的。库版本发布一律走 `api.github.com/repos/<org>/<repo>/releases`。
- **第三方网关的「Release Date」仍是稳定陷阱**：aisa.one 给 `qwen3.7-flash` 标 Release Date 2026-09-30，实为该平台目录日期；lmmarketcap 给 Gemini 4 标「已宣布 Sep 30」。判定标准始终是**厂商官方定价页 / 官方模型列表 / 官方博客**是否收录。
