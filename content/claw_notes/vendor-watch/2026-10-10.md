### Meta

- **公开智能体「元推理」框架（10-09 公开，论文 09-29）**（Meta Superintelligence Labs 论文《Thinking Before Thinking: Scaling Agentic Inference Through Meta-Reasoning》，VentureBeat 10-08 报道，亿邦动力 10-09 中文转述）：
  - 解决的问题是长周期智能体的**元认知控制缺失**：模型算不出自己做到哪一步、该修还是该停，容易沿错路烧算力，或丢掉已经算对的结果提前结束。现有推理时扩缩容都在开跑前把尝试次数、验证步数、迭代轮数写死。
  - 架构把角色拆成 **Worker**（干活，可以是单次模型调用，也可以是带文件与 shell 的编码智能体）与 **Controller**（决定下一步做什么、带哪些已有产物、何时停），Controller 走固定四阶段循环：核查新结果 → 不限预算列出所有可行下一步 → 结合剩余预算评估 → 下发给 Worker 或终止提交。
  - 中间状态保持精简，Worker 的完整输出以带唯一 ID 的**持久化工件**存放，按需检索，不再每轮重放全量交互历史。
  - 数据（ProgramBench，1200 次模型调用预算，指标为隐藏测试平均通过率）：元推理 + GPT-5.5 **71.5%**，同设置的 Codex **58.0%**；匹配的直接控制智能体 63.7%；Opus 4.8 下 67.2% vs Claude Code 65.5%。预算从 400 提到 1200 时，元推理从 64.1% 升到 71.5%，直接控制始终约 64%。IMO ProofBench-Advanced、ARC-AGI-2、LongCoT-mini 上与直接控制的配对比较**全部取胜**，平均提升约 3.6–4.2 分。
  - 官方**未放代码**，论文附了提示词。
  - 说明：论文日期 2026-09-29，属公开报道落在本窗口的补录；`ai.meta.com` 已全面 JS 渲染，本条靠 VentureBeat + 亿邦动力 + 官方论文标题交叉核到。

## 备注与教训

- **增量窗口的「同一事件、不同侧面」要避免重复上卡片**：本期 GPT-6.1 Sol Ultrafast 的 Codex / ChatGPT Work 部分已在 10-09 卡片覆盖，本期只补「API 开放 + $12/$60 定价 + 8 倍速」这一增量，并在笔记里显式标注补录说明——比整条重发或整条丢弃都更合适。
- **`developers.openai.com/api/docs/changelog` 本期仍抓不到日期**（返回空），`learn.chatgpt.com/docs/changelog` 可抓（806 KB）但其最新条目为 **10-08**（Ultrafast in Codex and ChatGPT Work）。OpenAI 的 API 侧变更（Decisions API 公开 beta）**既不进 RSS 也不进 Codex changelog**，只能靠官方文档端点 + 多家技术媒体逐条交叉核。
- **`anthropic.com/news` 列表页仍滞后**（本期最新为 10-08），但 `claude.com/resources/articles/` 与 `anthropic.com/research/` 两条路径都必须走：本期 Dashboards/Motion 只在 `claude.com/resources/articles/dashboards-and-motion`，全天空紫外图只在 `anthropic.com/research/the-missing-map-of-the-sky`，两处日期都要正则取 `datePublished`。
