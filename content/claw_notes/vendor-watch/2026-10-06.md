### OpenAI — 欧盟文本溯源与文本水印 textGrain（官方博客 2026-10-05 15:00 GMT = 北京 10-05 23:00）

官方博文 **「Our approach to EU text provenance rules」**（`openai.com/index/eu-text-provenance`），同日发布技术报告《textGrain: Entropy-Calibrated Watermarking for Language Model Text》。

- **合规动因**：欧盟 AI 法案要求生成式 AI 提供方以机器可读方式标记生成文本。OpenAI 自陈文本水印与检测仍是早期技术、局限显著，因此采取**分阶段**推进，并强调「说清水印能做什么、不能做什么」。
- **三步落地**：
  1. **即日起，API 客户全球可自愿开启**部分模型的文本水印；**API 侧默认关闭**。
  2. **未来数周内**，为**欧盟地区**符合条件的 ChatGPT 与 Codex 文本输出加上不可见水印（覆盖所有档位，但**仅限欧盟**）。OpenAI 明确不把文本水印做成全球默认。正在与云伙伴合作，使其平台上访问的 OpenAI 模型输出后续也可支持。
  3. **开放水印检测器申请**，初期仅限**获批研究者与专家机构**，逐案授予。
- **技术做法 `textGrain`**：在模型的选词上加一层**不可见统计信号**（按密钥对下一个词的预测做排序微调），检测器只凭「文本 + 密钥」即可判断是否含水印；水印随复制粘贴一起走。技术报告作者来自**宾夕法尼亚大学、耶鲁大学与 OpenAI**。OpenAI 计划**后续开源**该技术，并在数周内补充报告细节。
- **自报性能与局限**（官方给数）：
  - 在 1% 目标误报率下，200 token 段落检出率约 **80%**，400 token 段落约 **95%**（以心理学类内容为例）；**数学类内容明显更低**，因选词自由度小。
  - **编辑会削弱水印**：400 token 段落中，替换 10% 同义词使检出率从约 **92% 降到 66%**；替换 25% 降到 **17%**。
  - OpenAI 称 textGrain 在其测试过的方法中（含 **SynthID for text**）**持平或更优**，但强调理想条件下的表现不代表日常可用。
  - 对输出质量：在评估 Astra 的基准上**未见有意义差异**（Artificial Analysis Intelligence Index 49.57 → 49.76，GPQA Diamond 94.44% → 93.94%）。
- **官方明确水印「不能证明」的事**：不能衡量人的贡献、不构成所有权或责任归属、**不识别用户**、不暴露提示词与会话、也不证明内容准确；**检不到水印也不等于人写的**（可能文本太短、被大量编辑或翻译、来自不支持的模型，或早于水印系统）。
- **周边口径**：图片与音频的验证工具（`openai.com/verify` 与 Content Provenance API）继续公开可用，不受本次调整影响。
- **背景**：Anthropic 两个月前已宣布对 Claude 生成文本加水印并**全球适用**（本期另有其模型级支持表见下）；OpenAI 此前建过文本水印但因担心用户流向不加的竞品而暂缓（WSJ 2024 年报道）。
- **口径**：官方博客 + 官方技术报告。属**产品/合规与安全**类，非新模型、非 API 定价变更。

### Anthropic — Claude Cowork 新任务改在云端运行，移除「只在本机」选项（官方帮助中心 2026-10-06 生效）

Anthropic 帮助中心在产品文档中给出提示：

- **自 2026-10-06 起，Pro 与 Max 档位的 Claude Cowork 新任务在 Anthropic 云端运行**，「Only on your computer（只在这台电脑上）」设置**被移除**；会话与文件在桌面端、网页端、移动端与 Chrome 侧边栏之间同步。
- 属 **Cowork 与 chat 合并为统一 Claude 体验**这一进程的一环（该合并自 2026-09-16 起分档推进）。**Team 与 Enterprise 档保留本地与云端两种模式**（Enterprise 默认关闭云端模式，需管理员在组织设置里开启并授权）。
- **迁移口径**：已在本机启动的任务留在本机跑完；要保留纯本地工作流，官方给出的路径是 **Claude Code 桌面版**（但项目与计划不随之迁移）。
- **架构变化**：旧架构下**推理在云端、工具调用在本机由 Anthropic 提供的 Linux VM 执行**（macOS 用 Virtualization.framework、Windows 用 Hyper-V）；新架构下**智能体循环与代码执行都在 Anthropic 托管基础设施上的临时沙箱中运行**，会话开始时创建、结束时销毁，沙箱之间不共享状态，且与 Anthropic 的公司、科研、训练环境隔离。
- **官方列举的隔离属性**：默认不能访问用户私有网络、内网与云元数据地址；出网流量经过沙箱无法绕过或重新配置的强制代理，仅可达白名单目标；仅使用数小时即过期的会话级短期凭证，连接器授权 token 不进入沙箱、连接器调用在服务端发起；存储记录按组织与账号做租户隔离。
- **本地文件怎么处理**：云会话需要本机文件或浏览器时，经 Anthropic 中转连到该设备上的 Claude Desktop 应用，范围限于已连接文件夹，每次本地工具调用都按用户权限校验；桌面应用离线则设备不可达。Claude 只取所需文件的副本，删除会话时一并删除。
- **用户侧关注点**：每次运行都会留下**完整执行记录（transcript）**，此前只存本机，现在存在 Anthropic 服务器上直至用户删除；官方口径为删除的运行 30 天内清除（被安全系统标记的运行最多保留 2 年，部分数据因法律原因更久）。已有用户在公开讨论隐私与锁定风险。
- **口径**：Anthropic 官方帮助中心产品文档（`support.claude.com`，Cowork 分类下的「Use Claude Cowork on web, desktop, and mobile」与「Claude Cowork architecture overview」）+ Anthropic 员工 Felix Rieseberg 的公开说明（10-05）。属**产品架构与数据留存**变更，非模型或定价变更。

## 本期口径与经验

- **OpenAI 的「28 天计划」把产品节奏变成了可核验的公开承诺**：10-04 由 @thsottiaux 宣布，10-05 立即交付第一天（GPT-6 提速）。这类条目要照实写成「承诺 + 当日交付」，并注意官方原文是「改进**或**重置」的二选一，多家二手摘要写成了「28 次重置」。
- **文本水印这条的教学点在于「官方自曝局限」比能力本身更有信息量**：OpenAI 主动给出 200/400 token 的 80%/95% 检出率、改 10%/25% 同义词后 92%→66%→17% 的衰减曲线，以及「检不到不等于人写的」。写这类条目必须把局限照实带上，否则读者会高估可用性。另注意 OpenAI 的**区域策略**：全球 API 自愿开启、**欧盟默认但仅限欧盟**，不做全球默认——这与 Anthropic 的「全球适用」是两套口径，不要混写。
