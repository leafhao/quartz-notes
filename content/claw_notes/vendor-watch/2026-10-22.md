### OpenAI：三个渠道统一安全标准，使用政策 11-20 生效

- 官方 **2026-10-21 21:00 GMT ＝ 北京 10-22 05:00**（`openai.com/index/broad-access-through-consistent-standards`），归入 Safety / Company。
- 核心：安全标准与执行统一到**直连、托管模型的合作伙伴、转售商**三类渠道；伙伴必须保持同等防护、自查违规、发现问题时采取行动，并**在执行层面协同**，使限制跨服务生效。
- **使用政策更新，2026-11-20 生效**：厘清安全模型开发与敏感用途的边界；新增要求——**提供模型直连访问的服务（model routers / AI gateways）须先获 OpenAI 审查批准**。这条对做中转、聚合网关的人影响直接。
- 新机制 **SafetyIDs**：客户可传标识，让 OpenAI 在调查中区分终端用户，但不必获知真实身份。
- 配套提法：Private Safety Processing / 零数据保留、Trusted Access Programs。
- 执行原则：按有记录的言行与风险判定，限制后若行为与防护实质改善会复核解除。

### OpenAI：Patch the Planet 完成 PHP 两个危急漏洞的协调披露

- 官方 **2026-10-21 07:00 GMT ＝ 北京 15:00**（`openai.com/index/coordinated-disclosure-of-critical-vulnerabilities`）。
- 事实：**2 个** PHP 关键漏洞，由 Calif 用 **GPT-5.6 Sol** 发现，**Wiz 独立发现并报告**同一对漏洞；处理周期**两个月**；PHP 维护者主导修复与发版。
- 协作面：Wiz、Cloudflare；政府侧为白宫 Super Intelligence Force、ONCD、CISA 及国际伙伴。
- 官方给了一套**五阶段协调披露框架**：上游验证修复 → 给受影响组织留行动时间 → 与政府协调保护关键系统 → 跨受影响产品准备更新 → 发布指南支持部署。触发提前披露的条件写得很具体：野外活跃利用、信息泄露、暴露性公开补丁、修复停滞。
- 配套：**10 亿美元** Daybreak 访问额度补贴资源有限的关键服务防护方；发布 PHP 版本检查器（Codex skill，仓库 `openai/php2shell-checker`）；通过 Codex for OSS 给开源维护者订阅。
- 官方判断：这只是开始，未来数月同类漏洞发现会「急剧增加」。

### OpenAI：数千智能体 32 分钟跑完脑图谱分析

- 官方 **2026-10-21 04:50 GMT ＝ 北京 12:50**（`openai.com/index/scaling-ai-research-for-complex-biological-data`），与 **PerturbAI、Scripps Research** 合作。
- 做法叫**分布式生物推理**：数千个基于 **GPT-Rosalind** 的智能体并行，每个负责一个基因扰动，读全脑 CRISPR 图谱（数百万小鼠脑细胞）→ 查文献 → 给机制解释，最后汇总成「推理图谱」。
- 数字：分析耗时 **32 分钟**（传统人工数月到一年）；分布式智能体引用 **700+ 篇**文献，单智能体最多 **11 篇**；盲评中人类专家 **75%** 更偏好分布式报告。
- 两个生物学发现：小脑中 Tsc2 敲除影响数十个神经元通讯基因而 Tsc1 几乎无影响，与结节性硬化症临床现象吻合；DCTN1 敲除后胆固醇合成基因上调，被连到胆固醇运输障碍与神经退行的假说。
- 产出已公开（GitHub `jinlabneurogenomics/distributed_agent`，数据集在 HF `perturbai/wholebrain_crispr_atlas`，预印本在 bioRxiv）。

### OpenAI：API 支持项目级服务层（Service Tier）选择

- API changelog **2026-10-21**，类型 Feature。

### Anthropic：API 版本 2026-10-21，SDK 全线跳大版本

- 平台发布说明 **2026-10-21**，四条：
  - 发布 API 版本 **`2026-10-21`**，配迁移指南。
  - 新一代客户端 SDK 与 `ant` CLI 同步发：**Python 2.0.0 / TypeScript 1.0.0 / C# 13.0.0 / Go 2.0.0 / Java 3.0.0 / PHP 1.0.0 / Ruby 2.0.0 / ant CLI 2.0.0**，默认发送新 API 版本。
  - **许可证由 MIT 改为 Apache 2.0**（旧版本仍 MIT）。
  - user profiles 新增 `enforcement_status` / `enforcement_actions` 字段，可用 `enforcement_status[]` 过滤被限制或封禁的终端客户。
- 破坏性变更里最该注意的三条：
  - **`temperature` / `top_p` / `top_k` 一律返回 400**，即使传默认值也不行，必须从代码里删掉。默认 temperature 固定 1.0，原本靠调低温度换一致性的做法没了替代。
  - **Text Completions API 移除**（TS/Go/Java/Ruby SDK 与 CLI），须改用 Messages API。
  - **API Key 从 `X-Api-Key` 头改为 `Authorization: Bearer`**——读或改写这个头的代理与网关要跟着改；Foundry 客户端例外。
- 其余：assistant 消息里的 `document` 块、user 消息里带非空 `citations` 的 `text` 块都返回 400；Admin API / 企业分析一批字段改名（`roles`→`role_ids`、`group_id`→`rbac_group_id`、`workspace_id`→`scope` 等）；`MessageParam` 拆成按角色的联合类型；客户端压缩移除改服务端压缩（`compact-2026-01-12`）。
- **Amazon Bedrock 限制**：`2026-10-21` 只支持 Claude 4.7 及更新模型，旧模型要留在原 SDK 版本或先换模型。
