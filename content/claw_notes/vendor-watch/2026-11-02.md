### OpenAI：12 月起 ChatGPT 与 Codex 共用一份额度，按 token 计量

- 位置：帮助中心新文档《Understanding ChatGPT and Codex usage limits》（`help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits`），**页面显示「Updated: 7 hours ago」，即今天上午刚更新**；此前 `openai.com/news/rss.xml` 在窗口内无新条目（最新仍是 10-30 三条）。
- 原文关键句：*Starting in December, Plus, Pro, and Business plans' usage allowance will be shared across ChatGPT and Codex as we bring the agentic capabilities of Work into the main ChatGPT experience.*
- 计量方式变了：**从「按消息条数」改成「按 token」**——*Your usage for ChatGPT and Codex will be measured in tokens*；消耗多少取决于所选模型与任务复杂度，模型越强、任务越复杂扣得越多。
- 唯一豁免：**Instant chat 不占额度**（*Instant chat will not draw from your usage*）。
- 查看与兜底：合并后的剩余额度与重置时间在 Settings → Usage；额度用尽只有三条路——等重置、升级套餐、买 credits。
- 官方给的预期：*We expect most users won't need to wait for their usage to reset more often than they do now*；但**没有给出 12 月的具体日期，也没有公布任何一档的 token 数额**。
- 怎么读：这件事的真正含义是「订阅额度」和「按量计费」开始并轨。对同时用 ChatGPT 和 Codex 的人，两边从此互相挤占；对只用对话的人基本无感（Instant 不计）。官方口径说「重置频率不会更高」，但这只是预期不是实测，且没有额度数字，任何「够不够用」的推算都没有依据。
- 前情（上一期已收，此处只作背景）：10-29 OpenAI 把 Pro 100／Pro 500 的 Work 与 Codex 用量翻倍，同时取消原定对 Pro 200 的削减。

### 谷歌：PlanAssist 从 3 个议会扩到 15 个，官方称审材料时间降 58%

- 位置：`deepmind.google/blog/speeding-up-planning-decisions-with-ai/`，页面 `datePublished` 为 **2026-10-31T09:00Z＝北京 10-31 17:00**，属**上一期漏收的补录**（上一期判定谷歌侧静默，实际这篇不在 RSS 前几条里）。
- 是什么：基于 Gemini 的英国规划审批助手，与英国政府、Google Cloud、Faculty 共同开发，帮规划官处理住宅类申请（扩建、阁楼改造、阳光房，占申请量约七成）。
- 四步流程：校验申请材料与建筑图纸是否齐全 → 核对场地约束（遗产保护区、树木保护令）与地方／国家规划政策 → 查历史异议 → **起草带完整引用的评估报告**，由规划官修改后再决定。
- 规模：从 Barnet、Camden、Dorset 三个试点议会，**扩到 15 个**（新增 12 个分三批加入），进入为期 12 个月、用真实申请的 Beta；英国政府目标 2027 年向英格兰全部议会开放。
- 数字：试点期规划官处理住宅类评估任务的平均耗时**下降 58%**，**超过 70%** 的 AI 草稿被官员零修改直接采纳。两个数字都是厂商与政府部门自报，**未公布样本量、计时方法与错误率**，也没有独立评估。
- 边界：工具**不对外销售**，最终决定权始终在持证规划官手上，各议会自愿使用。

### 阿里云：千问接入国行 Apple 智能，11-04 开放测试、12 月正式上线

- 位置：**苹果中国官网新闻稿**《Apple 智能即将登陆中国》（`apple.com.cn/newsroom/2026/10/apple-intelligence-features-are-coming-to-users-in-china/`），RSS 时间戳 **2026-10-30T20:59Z＝北京 10-31 04:59**，属**上一期漏收的补录**。
- 原文：*Apple 与阿里巴巴达成合作，在部分 Apple 智能体验中加入对千问的支持，让中国用户能直接在 Siri、写作工具以及视觉智能中使用阿里巴巴的千问，包括文本与图像理解相关功能。*
- 时间表：首批功能**自 11 月 4 日起随最新 iOS 开发者 Beta 版开放测试**，**12 月随 iOS 27.3 正式版**面向中国用户推出；iPad／Mac 等其他平台需另行审批。
- 首批功能清单：实时翻译、写作工具（改写／校对／摘要）、视觉智能、照片消除、智绘表情、自然语言搜图、通知与邮件摘要等；**不含 Siri AI 及 WWDC 2026 上宣布的下一代 Apple 智能能力**。
- 千问的三处入口：Siri（可直接调用千问知识回答，支持就照片、PDF 与演示文稿提问）／系统级写作工具的「千问创作」（从零生成内容与图像）／视觉智能的「询问千问」（用相机控制、操作按钮或控制中心唤起）。
- 隐私边界（阿里侧说明）：用户自主选择是否开通；每次把问题、文档、图片发给千问前都会征求同意；请求与回复**不用于训练**；可用 Apple 账户或千问账户登录。
- 怎么读：这是国内大模型第一次以系统级能力进入 iPhone 国行，对千问是渠道级放量而非模型升级；对开发者更实际的意义是——**国行设备从 11-04 起会有一批可被调用的系统级千问入口**，做 iOS 端 Agent／写作类产品的要重估分发假设。

### 深度求索：在 GitHub 开源 Super-agent 研究原型

- 位置：`github.com/deepseek-ai/dsh-superagent-prototype`，仓库 `created_at` **2026-10-31T09:32Z＝北京 10-31 17:32**，描述为 *Towards a More Autonomous Agent System*，**MIT 许可**，属**补录**。
- 它是什么：一个**面向单个 GitHub 仓库的主动式编码 Agent**，打包成 DeepSeek Harness 的 bundle；监听 GitHub（可选接飞书），有人请求干活时开一个 work item，在**自己的 agent session 与目录**里做完，再回到原对话里答复（例如直接给 PR）；带一个 web 面板显示需要人来处理的事。
- 设计原则（README 原话）：*take as little human attention as possible, and give as much value as possible*——只在被要求、或团队写好的规则允许时才动手，只在需要人行动或结果可用时才开口。
- 官方明确降级：*Research prototype for reference only, not an official DeepSeek product*；代码大量由编码 Agent 写成，**可能有 bug**，风格与实践不统一；公开版与内部版本、与配套文章里描述的实现**并不一致**，部分设计只是方向、未落地。
- 怎么读：这不是产品发布，是 DeepSeek 在「Harness + Agent 组织方式」上的一次公开交底。值得看的是它对「一个 Agent 服务整个团队会同时摊薄整个团队的注意力」的处理——授权模型与发言人机制写在文档里（docs/002-authorization.md、004-prompts.md），比模型本身更有参考价值。

- **新入口（重要）**：① **`help.openai.com` 对 curl 一律 403，但 WebFetch 能读**——本期就是靠它拿到 OpenAI 的额度合并原文，并且**页面上的「Updated: N hours ago」是判断窗口内是否更新的唯一线索**（curl 版无任何日期）。以后每期都应抽查帮助中心，产品与计费类改动经常只在这里发。② **`apple.com.cn/newsroom/rss-feed.rss` 是 Atom 格式**（`<entry>` 而非 `<item>`，日期在 `<updated>`），首页与 `/newsroom/` 都是 JS 渲染，只有这个 RSS 能拿到条目与 slug。③ **`kimi.ai/blog` 首页 HTML 里 slug 会带反斜杠转义**（`blog\/kimi-k3`），`grep 'blog/[a-z-]'` 会漏，必须先去转义。④ **`docs.claude.com/en/release-notes/api` 的 HTML 有 306KB 但正文一条都不在里面**（Next.js 客户端渲染），任何「2026」都只出现在页脚版权里——**不要据此判「无更新」**，只能记「未核到」。
