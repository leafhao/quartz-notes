## 1. Claude Code Projects：从文件夹改造成线程调度器

**发布日期：2026-09-17｜类型：代码生成 / Agent 编排**

**为什么值得试**

- 工作单位从「一次任务一个对话」换成「一个项目一个协调器」。协调器自己不写代码，只负责拆解、派活、验收，所以它永远不会被某一次实现卡住，你随时能插话改方向。
- 每个线程是一条独立的 Claude Code 云端会话，各自一条分支、一份仓库副本；线程之间改到同一处代码，按普通 PR 冲突处理。线程内部还能继续拆，用子代理和循环消化大任务。
- 所有线程读写同一份项目记忆。Claude 会记住「发布挪到周五了」「导出功能为什么被砍」「动计费服务前要先找谁确认」，不用每次重新交代。
- 手机端可看进度、可中途转向。官方给了 200 个新线程 / 项目 / 天的上限，并能分别设置协调器与工作线程的模型和 effort。

**注意**：云会话多开，额度消耗明显加速；仓库需在 github.com 且安装 Claude GitHub 应用。Beta 首批面向使用云会话的 Pro / Max 订阅者，Team 与 Enterprise 排在后面；本地执行版官方称「很快」。

**建议用法**：拿一件真正跨仓库的活试——比如设置目标「退役 v1 接口」，让它为 API、Web、移动三个仓库各开一条线程去改调用方、跑测试、提 PR，你只需要决定合并顺序。

## 2. 阿里 OpenCodeReview：把「稳」字写进代码审查 Agent

**发布日期：2026-09-20 开源｜类型：代码生成 / 代码审查**

**为什么值得试**

- 架构取向很明确：能确定性解决的事不交给模型。选文件、打包上下文、匹配规则、把评论对齐到 diff 行号，全部走程序；只有真正需要理解的代码分析才交给 LLM Agent。
- 内置多语言规则集，直接盯空指针、线程安全、XSS、SQL 注入这几类高频问题。兼容 OpenAI 与 Anthropic 两类模型接口，可审 Git diff、分支或整份文件。
- Go 写的 CLI，Apache-2.0 许可。可在本地跑，也能接 GitHub、GitLab、Gerrit、VS Code、MCP，以及 Claude Code、Codex、Cursor 这类编码 Agent。
- 官方口径：内部两万多名开发者用了两年，在自建 200 PR / 10 语言的基准上，精度与 F1 高于 Claude Code，token 用量约其 1/9。

**注意**：它是刻意用召回换精度的——外部reviewer指出最佳配置召回率仅约 20%，跨文件、架构层面的问题基本不在它的射程内；另有一次独立基准跑出约 12% 精度（维护者称为工具调用异常，已修复但无复现验证）。别把它当全面体检，把它当 PR 门口的专用关卡。

**建议用法**：先在团队里数一个更有意义的数字——「它报出来、你确实会去改」的条数。日常 PR 走它，季度大扫除再让通用 Agent 兜一遍。

## 3. Google AX v0.3.0：代理的 Kubernetes，状态搬出 etcd

**发布日期：2026-09-20｜类型：Agent 基础设施 / 开源编排**

**为什么值得试**

- 官方对「为什么需要新一层」的回答很直白：代理既不是无状态微服务，也不是跑完就退的批处理任务。它攒状态、要强隔离、会调模型与工具服务，还能在没人看着的时候把预算烧穿。
- 四个声明式原语撑起整套模型：Task（隔离沙箱 + CPU/内存限额，可挂起恢复）、Workspace（预装 Git 仓库、MCP 服务器、技能包）、Gateway（出站流量收敛到显式白名单）、Model（集中管理 provider、参数与凭据）。
- CLI 刻意做成 kubectl 形状——`ax apply / get / describe / watch / ssh`，会 K8s 的人十分钟上手。
- v0.3.0 把控制面拆成 ax-server / ax-controller / ax-task-runner 三个二进制，任务状态从 Kubernetes 自定义资源搬进 Redis Streams，就是为了扛住海量短生命周期任务而不压垮 etcd。

**注意**：README 至今挂着「稳定版前会有破坏性变更」的警告，v0.3.0 也确实把旧的 Python harness、ATE 客户端、SQL 事件日志和示例技能全删了。跑起来需要 K8s 集群、ko 构建工具和 Agent Substrate 控制面，不是轻量个人工具。

**建议用法**：适合已经在 Kubernetes 上被代理任务折腾过的平台团队，先读它四个原语的划分方式——这套抽象即使你不用它，也值得作为自建编排的参考架构。

## 4. Google ADK for Kotlin 1.0：Android 上跑代理不再需要 Python

**发布日期：2026-09-09（InfoQ 于 09-20 报道）｜类型：开发框架**

**为什么值得试**

- 与 Python、Java 版 ADK 达到功能对等，Kotlin 与 Android 开发者终于不用在项目里塞一层 Python 运行时来做代理逻辑。
- 工具用 `@Tool` / `@Param` 注解声明，KSP 在编译期生成函数 schema 而不是运行时反射——既是类型安全，也让移动端启动更快。
- 端侧推理支持 LiteRT-LM 与 ML Kit（beta），云端与混合场景走 Firebase AI Logic，应用可以在本地跑代理、必要时才切云模型。会话持久化接 Room，语义记忆接 AppSearch。
- 内置人在回路：在工具声明上设 `requireConfirmation`，转账这类敏感动作就必须人工确认后才执行；技能以 `SKILL.md` 承载，按需加载而非每次全量塞进上下文。

**建议用法**：先搭一个「可恢复的单代理 + 显式工具确认」，再考虑多代理层级。官方社区里有句提醒值得抄下来：生产可用性取决于生命周期恢复和确定的工具边界，不取决于代理数量。

## 5. Builder.io agent-native：业务能力定义一次，人和代理共用

**发布日期：2026-09-20 开源｜类型：Agent 框架 / 全栈**

**为什么值得试**

- 它要解决的是一个很实际的漂移问题：UI 能做的事和代理能做的事，各自实现一遍，很快就对不上。agent-native 把业务能力抽象成 action，一次定义，同时产出 React hooks、LLM 工具描述、REST 端点、MCP 接口和 CLI 命令，校验与权限只有一份。
- 人和代理共用同一份数据与状态。代理知道用户当前在看哪个页面、选中了哪条记录，它是走 action 层而不是模拟点击屏幕。
- 本地开发不需要数据库服务：`DATABASE_URL` 未设置时用 PGlite 进程内跑 PostgreSQL，生产切回标准 PostgreSQL 加类型化迁移。
- 模型自带：可接 Builder.io 额度，也可填 Anthropic / OpenAI / Gemini / OpenRouter / Groq / Mistral / Cohere 的 key，或者用本地 Ollama 完全不填 key。MIT 许可。

**注意**：发布节奏是持续构建而非语义化版本（release tag 形如 `v0.1.381-0`），早期曾有仓库未挂许可文件的情况。适合先试点，别急着 vendor 进生产代码。

**建议用法**：挑一个「人要先审、代理先拟」的流程试——比如内容起草与审批，让代理写完在界面里展示来源和待批状态，你在同一屏里改完放行，检查它是否真的没走第二条实现路径。

## 6. Qwen-Image-2.1：7B 就把生成与编辑合并，原生支持透明图层

**发布日期：2026-09-20｜类型：图像生成 / 开源权重**

**为什么值得试**

- 生成与编辑统一在一个模型里：文生图、局部改图、抠主体共用同一个 checkpoint，不用再拼一个抠图模型。原生输出 RGBA，直接生成透明背景素材，也能把照片里的主体抽成带透明通道的图层。
- 编辑最多吃 10 张参考图，适合虚拟试穿（模特 + 衣服 + 鞋 + 包 + 帽子拼一套）、合影合成、室内陈设搭配这类多素材任务。局部修改支持画圈、涂抹标注，或额外传一张 mask，避免整图重绘把没动的地方也改掉。
- 视觉生成部分只有 7B（32 层单流 DiT），官方称在消费级显卡上可跑；配合混合粒度注意力与 prefix KV cache 复用，多参考图编辑的延迟被压下来。文字排版与人像布光相比上一代有提升。
- 开源生态当天就位：Diffusers、vLLM-Omni、SGLang-Diffusion、ComfyUI、Ostris AI Toolkit 均 Day-0 支持，权重在 Hugging Face 与 ModelScope 可直接下。

**注意**：许可是 Qwen Research License，禁止商业使用，商用需单独申请授权。官网榜单上的对比是自家基准，独立复现还很少，先按厂商口径看。

**建议用法**：拿一两个真实素材需求试透明图层——贴纸、抠图、印刷用切图这类以前必须单独跑一次抠图的场景，看一条 prompt 出来的透明边缘干不干净，再决定要不要进设计流程。

## 7. Runway 实时视频：从「提交等渲染」改成「边生成边操控」

**发布日期：研究预览，上线时间未确认｜类型：视频生成**

**为什么值得试**

- 当前 AI 视频的节奏是提示词 → 等几分钟 → 看结果 → 重做，Runway 想把这条链路换成流式：画面逐帧吐出来，你用文字、镜头运动、音频输入实时改方向。
- 技术底座是 GWM-1（2025 年 12 月推出的通用世界模型）加 Gen-4.5，逐帧生成且每帧以上一帧为上下文（自回归因果扩散）。与 Nvidia 合作的预览跑在 Vera Rubin 平台上，目标是首帧 <100ms。
- 时序生成最怕误差累积——一帧小错被下一帧放大成抖动和崩解。Runway 的对策是拿自己（包括有瑕疵的）输出做训练数据，让模型学会纠正自身偏差，而不是假设每帧输入都完美。
- 官方判断实时化把算力从训练侧挪到推理侧，输出单位成本可能反而下降；明确点名教育、游戏、机器人三个场景。

**注意**：官方没有公布任何可用时间表，也没有在公开环境验证过多会话共享硬件时的延迟。当研究方向上值得关注，别排进生产计划。

**建议用法**：想提前摸底，可以设计一段 10 分钟的固定镜头脚本，每 60 秒人为插一次干预（平移、插入物体、音频提示），记录首帧延迟、每分钟画质漂移和干预后能否回稳。这套测法对任何实时生成产品都通用。

## 8. 两件值得留意的代码与上下文工具

### Claude Code 开始读 AGENTS.md（2026-09-21）

项目里没有 `CLAUDE.md` 时，Claude Code 会改读 `AGENTS.md`，开关在 `/config` 的 Project instructions 下。意义不在功能本身，而在于 `AGENTS.md` 已经是多家编码 Agent 共用的格式——一个项目只需要维护一份指令文件，不必按工具各写一份。目前 Bedrock、Vertex、Foundry 上尚未跟进。

### context-mode：把工具输出挡在上下文窗口之外（本周 GitHub 热榜）

在 MCP 协议层和 hooks 上拦截工具输出：原始数据留在沙箱子进程里，只把摘要与取回句柄注入上下文，官方称可减少约 98% 的工具输出体积；同时用 SQLite + FTS5 记录文件改动、git 操作与任务，在 `/compact` 丢掉原始历史后仍能按相关性检索回来。已覆盖 17 个平台，对同时用 Claude Code、Cursor、Gemini CLI 的人比较省心。适合长时间、多代理的编码任务；装之前先看清各平台 hook 的强制力度并不同。

## 9. 一条对开发者的信号：Sora API 于 09-24 关停

按 OpenAI 的弃用页，`sora-2`、`sora-2-pro` 及所有带日期的快照将于 2026-09-24 从 API 移除，推荐替代一栏是空的；官方只提供导出工具、退款路径与导出窗口后的数据删除，没有迁移方案，也没有发布博文。这等于一家前沿实验室退出视频生成的基础设施层——4 月关的是消费端 Web 与应用，这次补上了 API 这半边。

## 尝鲜优先级

1. **工程团队先看**：OpenCodeReview 用一周真实 PR 跑一轮，只数「报出来你会去改」的条数，比看基准表有用。
2. **Claude 用户**：Projects 拿到 beta 后，用一件跨仓库的活验证共享记忆是否真的减少了重复交代。
3. **自建 Agent 平台**：读 Google AX 的四个原语划分，尤其是 Gateway 把网络策略做成一等公民这一点。
4. **设计/素材**：Qwen-Image-2.1 试透明图层产出；商用前先确认许可，非商用则完全放开用。
5. **观望**：Runway 实时视频与腾讯 Gander，都还没有可用时间表。
