## 本期速览

这两天没有「又一个更强的模型」这种单一旗舰，主线是**入口之争**。

**第一条：谁掌握用户打开 AI 的那一下。** 企业微信把 WorkBuddy 收进通讯录变成机器人；千问办公在办公套件里切出「电商经营」模式做垂直 Agent；Google 把 AI Studio 生成的安卓 App 直接装进你手机的 Play 私域通道；NVIDIA 则干脆把前沿级模型塞进 24GB 笔记本显存，让本机 Agent 不再依赖云。四条不同的路，回答的是同一个问题——AI 的第一跳从哪里开始。

**第二条：Agent 开始需要「车架」。** OpenBMB 的 PilotDeck 2.0 把开源办公 Agent 工作台做全流程交付；腾讯把团队技能放进 Git 让同事共审共用；Chainguard、Factory 分别从隔离和沙箱编排两头下手。模型是发动机，Harness 是车架——这个比喻在这一周被反复验证。

**第三条：开源权重继续下探成本线。** 阶跃 Step 5、蚂蚁 Ling-3.1-flash、NVIDIA Nemotron 3.5 Bolt、Fish Audio Drama 3 同周放出，全部走「大总参 + 小激活」的稀疏 MoE，单任务成本被压到旗舰闭源的八分之一到十分之一。

## 一、编码与代理

### 1. OpenCode 2.0：从终端程序变成可被脚本驱动的后台服务

**发布日期：2026-10-12（正式发布，本周铺开）｜类型：编码 Agent / 架构重写**

OpenCode 2.0 不再只是「你在终端里跟它对话」——server 默认作为**单个后台进程**常驻，TUI、Web 界面和桌面 App 都连到同一个实例，脚本通过 `@opencode/client` 也能自己发现并调用它。命令行路线是 `opencode api`，配对命令 `/pair` 或 `opencode pair` 可以把服务暴露给其他机器。官方明确点名这种形态对**定时任务**特别有用。

配套三件：重写过的 server API、`@opencode/sdk`（可把 OpenCode 当库用，CLI 本身就构建在同一份代码上）、以及新的 `@opencode/codemode`——把 MCP server 或 OpenAPI 端点直接转成 Agent 可调用的函数，一次往返串起多个工具调用，减少上下文膨胀。此外还有后台子 Agent 与后台 shell 命令、80+ 功能内部插件化。

**注意**：官方说明里**1.0 的插件不能用在 2.0**，server API 完全变了，升级要跑 `opencode upgrade --major`。发布说明没写许可证，也没给任何性能数字——自建前先去仓库确认授权。

### 2. Cursor Rollouts：盯住代码进了生产之后发生什么

**发布日期：2026-10-14｜类型：编码 Agent / 上线后监控**

Cursor 上线 **Rollouts**，官方称其为「机器人」，持续跟踪代码变更进入生产环境后的表现，监测是否按预期运行。它本质上是 Cursor 收购的 Firetiger 旗下 Change Monitors 在 Cursor 内部的重生，并基于同时发布的新框架 **Bot Development Kit**（`@cursor/bdk`，已上 npm）重建。

**背景**：Cursor 收购 Firetiger 时，其联合创始人 Rustam Lalkaka 的判断是「创建变更的成本已趋近于零，部署变更的成本和风险基本没变」。这句话解释了为什么编码 Agent 的下一战场在 PR 之后。同批发出的还有 Security Review。

### 3. 腾讯云开源 TeamAI：把调好的 AI 技能交给同事接着用

**发布日期：2026-10-10 开源（本周登上 GitHub Trending，本期补录）｜类型：Agent 协作基建**

TeamAI 把技能、工作规范、工具配置和项目资料放进团队共同维护的**文件仓库**，用 Git 管理：提交时自动开分支 + 合并请求，评审通过合并后，支持会话启动钩子的 Agent 会在下一次开新会话时拉取更新。目前支持 16 种 Agent，包括 WorkBuddy、CodeBuddy、Claude Code、Codex、Cursor。

**官方口径数据**：在 13 项研发任务的内部测试中，接入团队知识的低成本模型综合得分提升 6.1%，模型调用成本下降 **76%**。它还会在检测到重复纠正或工具调用失败时，主动提示成员沉淀经验。已集成进腾讯云智能体管理平台 ClawPro。

**注意**：解决的是「最新版 / 最新版2 / 最终确认版」这种附件扩散问题，价值在流程而非模型能力。

### 4. Chainguard 三件套：给编码 Agent 装上笼子、测速带和猎犬

**发布日期：2026-10-14（Workspaces 与 Checks 已进 beta，Harness 走等待名单）｜类型：Agent 安全与验证**

- **Workspaces**：为每个开发者和 Agent 提供独立的加固 microVM，**Agent 拿不到真实凭证**（密钥从外部注入）、可选出口策略阻断未批准的网络连接、每次连接留痕；Agent 等人输入时工作区 10 分钟后自动挂起快照以省算力。
- **Checks**：把 CI 搬进 Agent 循环，Agent 边写边跑测试，每次通过生成**签名的证明（attestation）**随代码流转，合并门禁可直接校验通过证明而不用重跑测试。
- **Harness**：用 Anthropic 的 Claude Mythos 5.1 在隔离 microVM 里构建客户应用、探测运行中副本的漏洞，每个发现都要**可复现**才给出修复建议。上线初期由 Chainguard 工程师代跑，可通过 Claude Marketplace 付费。

**注意**：三项能力与效果数据均来自公司自报，未获独立验证；价格未公布。

### 5. APUS 开源 Reflex Agent：用决策模型当 Harness 的大脑

**发布日期：2026-10-14｜类型：个人 Agent / 开源**

APUS AI 开源 Personal Agent 产品 **Reflex Agent**，MIT 协议，提供桌面端、Web 和 SDK。架构是自研开源决策模型 **Reflex** 承担模型路由、技能选择、结果审查与执行监督，配 **Continuum 记忆引擎**做长期任务信息的积累与检索，走「决策—执行—反馈—再决策」循环。

**官方口径**：实验室实测响应速度最快可达 Claude Code、Codex 等主流 Agent 的 **3 倍**。其「无限上下文」指外部记忆机制支持更长周期任务，**并非突破单次调用的输入长度限制**——这个区分值得留意。

### 6. 阶跃终端 STEPX Neo：默认进入智能体界面的手机

**发布日期：2026-10-13（10-16 10:13 开售）｜类型：终端硬件 + 操作系统**

阶跃星辰发布首款大模型原生智能体手机 **STEPX Neo**，全栈定价 3999 元起，同步发布智能体原生操作系统 **Step AOS 1.0**——解锁后直接进入智能体交互界面，语音发任务、系统自动调度资源，右滑切回传统 App 界面。AOS 不是改造安卓，而是架在 Android、Linux 之上的**中间层**，为智能体重构运行环境。

**关键设计差异**：阶跃选择让智能体**直接调用应用的服务接口**，而不是去「操作」应用界面——与豆包手机二代的路线正好相反。购买先行版可享 12 个月每月百亿词元额度。产线侧与支付宝合作，个人智能体「Amoo」与「阿宝」协同，可在对话窗口里完成推荐、下单、支付、核销全流程。

### 7. 豆包手机二代：放开第三方屏幕自动化权限

**发布日期：2026-10-14｜类型：终端硬件 / 权限开放**

努比亚豆包手机（NaviX Ultra 二代）**逐步放开对第三方应用的屏幕自动化操作权限**，10-14 晚开启「进化直播」升级个人上下文记忆与本地数据检索。执行策略上，二代放弃一代单方面「闯」进 App 的做法，转向 **MCP、A2A 协议调用**。

**注意**：公开合作方仍有限，除字节系 App 外只有曹操出行、汽水音乐等少数几家。IDC 的判断是当前智能体手机仍受生态限制，且消费者端缺乏 PC 那样的刚性需求。

### 8. Product Hunt 编码 Agent 热榜（10-14 前后，一批小工具）

**类型：编码 Agent 编排 / 观测**

围绕「一个人怎么看住多个 Agent」，本周 PH 上出现的答案：

- **Codemind**：委派编码，拿回能跑的代码

**注意**：多为上线数周内的小工具，材料来自 PH 页面的自述，能力未经独立验证。价值在于**暴露了这一类需求真实存在**。

## 二、图像与声画

### 9. Fish Audio Drama 3：35B 稀疏 MoE 开源 TTS，能「导戏」

**发布日期：2026-10-13（权重上 Hugging Face，代码 tag v3.0.0-beta）｜类型：语音合成 / 开放权重**

Drama 3 是 35B 总参、**每 token 仅激活约 3B** 的稀疏 MoE 语音模型，骨干从 Qwen3.5 初始化，输出 44.1 kHz。真正的新意是**控制方式**：你不再猜 `[whispers]` 这类标签，而是像给演员说戏一样在方括号里写平实描述——「勉强撑着，硬挤出一个笑」，且**指令语言可以与台词语言不同**。点标签（`[sighs]` / `[laughs]`）放在声音该出现的字面位置；作用域标签只改包住的那几个词；用音素标签可以钉住发音（英文用 CMU Arpabet、中文用拼音）。一份文本最多带 **16 个说话人**。

另一项不常见的能力是**逐词修补**：请求里带 `previous_takes`，模型只重生改动的词，并参考前后音频接缝，不改情绪与节奏。多说话人场景一次请求即可产出多角色对白。

**官方口径**：Artificial Analysis 发音鲁棒性 93.2% 居首（Eleven v4 为 91.7%）；单 H200 上首音延迟中位 88.9 ms；按 token 级编辑的字错率低于 Cartesia Sonic-3。API 定价 $50/百万字符，**促销价 $10 至 2026-11-12**。本地跑需 FP8 约 48GB 显存，社区有跑双 3090 的案例。

**注意**：许可证是 **Fish Audio Community License v1.0**，不是开源许可证——年收入 50 万美元以下可商用，超过或想转售语音 API 需付费授权。官方明说它最适合**渲染一次就留存的脚本化台词**（有声书、游戏对话），不适合实时客服。

### 10. Meta IWSDK 1.0：让 Agent 在真机 Quest 上测网页 VR

**发布日期：2026-10-14｜类型：开源开发框架 + 3D**

Meta 的 Immersive Web SDK 升到 **1.0**，把 AI Agent 的测试闭环从桌面模拟器接到**插在开发机上的真实 Quest 头显**，帧率与浏览器指标直接来自设备。技术上的关键动作是每个新项目都自带 **MCP server 和 agent skills**——Agent 可以检视场景、控制模拟输入、暂停引擎，并**检索 IWSDK 的真实编程接口**而不是猜。开发者与 Agent 还能在同一个可视化场景编辑器里协作：Agent 用代码加模型、材质和行为，人则可视化调整。

引擎侧用 Three.js，Havok 物理默认跑在独立 worker 里减少与主渲染线程争抢。

**注意**：官方演示「Agent 通关 Hyperform 全部关卡并修到稳定 90fps」是公司自证，未经独立验证。同时开放了 Meta VR Glasses（预计 2027 春）的注视 + 捏合控制预览，但在 Quest 上是用头部朝向模拟，**没有真眼动测试**。

### 11. xAI Grok Voice 3.0：语音到语音延迟压到一秒内

**发布日期：2026-10-15｜类型：语音智能体模型**

xAI 发布新一代**语音到语音**模型 Grok Voice 3.0，响应延迟压缩到一秒以内，面向客服与语音代理场景开放 API。官方称已在星链客服中实现**多数来电自动处理**。

**注意**：延迟与排行均为厂商自报口径；语音智能体场景的真实瓶颈通常不在模型延迟，而在后端系统对接与打断处理。

## 三、文档与办公

### 12. 企业微信 × WorkBuddy：机器人进通讯录，可调十大能力

**发布日期：2026-10-14｜类型：办公 Agent / 渠道打通**

企业微信与 WorkBuddy 联合发布新版本，做双向深度打通：WorkBuddy 进入企业微信**联系人列表**，成为可对话机器人，以对话机器人身份进入企业通讯录；同时支持企业微信账号登录，在企业授权范围内调用消息、文档、会议、微盘等**十大能力**。两个产品共用一套企业微信账号体系。

具体可用：一句话分类总结未读消息与邮件；群聊记录合并转发后自动读取所引文档、日程和纪要；**代发消息须本人确认**。管理员可在后台分配名额、授权并调整用量。面向已认证企业开放。

**注意**：门槛在「企业已认证 + 管理员授权」，个人账号用不上。

### 13. 千问办公电商版：一个 AI 入口管多个平台店铺

**发布日期：2026-10-14（开启邀测）｜类型：垂直办公 Agent**

阿里千问办公发布面向电商行业的 AI 工具，定位**独立第三方电商 Agent**，向所有电商平台与商家开放。在千问办公中切到「电商经营」模式即可体验。

四项专业功能：**跨平台经营看板**（淘宝、抖音、小红书等数据汇到同一工作台）、**趋势洞察及卖点分析**（从社交平台热词捕捉趋势）、**爆款素材批量生成**（结合商品图与品牌调性）、**跨平台 ROI 智能优化**（动态跟投放计划并给建议）。已接入生意参谋、有赞、千牛、阿里妈妈万相台、FastMoss、LinkFox 等。双 11 场景下输入营收目标即可生成作战台，每日更新销售、库存与广告消耗进度。

**注意**：官方称目前约 **20% 付费用户来自电商行业**，这是选它先做垂直版的直接理由。后续规划「主动经营」——Agent 主动发现库存、投放、售后异常并按授权处理。

### 14. openJiuwen 个人知识空间：资料一次采集，反复调用

**发布日期：2026-10-14｜类型：办公 Agent / 知识底座**

openJiuwen 推出**个人知识空间**，原生集成在其 WorkSwarm 中，解决办公智能体反复读取原始资料、耗时耗 token、信息易遗漏的问题。分**来源、采集、处理、使用**四层架构，支持接入多类数据源与手动／定时增量采集。

处理模式三档：规则处理、规则 + 大模型混合、智能体处理，自动整理成带**目录、关联关系与原始出处**的知识库。官方规划后续基于用户行为识别知识缺口并主动补充资料。

**注意**：属「给 Agent 配长期背景知识」这一类，与腾讯 TeamAI（技能共享）、PilotDeck（工作台）解决的不是同一个问题。

### 15. OpenBMB PilotDeck 2.0：开源办公 Agent 工作台

**发布日期：2026-10-15｜类型：开源 Agent 操作系统**

面壁智能联合清华 THUNLP、OpenBMB 与 AI9Stars 推出 **PilotDeck 2.0**，模型无关的开源 Agent 操作系统。2.0 的重点是把 Word、Excel、PowerPoint、PDF 的**读取—整理—计算—生成—编辑—检查串成闭环**，交付可继续编辑的成果文件，而不是一段需要你手动复制的文字。支持桌面一键安装、可视化数据流、Docker Compose 与一行命令部署，工作空间可管文件、批量上传附件、在线预览成果，任务中还能切模式/切模型、从当前对话开新分支并行推进，历史对话可搜索。支持接飞书、微信、企业微信、QQ 等 IM 渠道。

**官方口径**：极限测试持续处理 **2000 条**交互消息仍稳定，中途断网可从中断处续跑；启用智能路由后社媒任务费用降超 **75%**；用「强主模型 + 轻量子模型」组合时仅约六分之一成本取得 70.6 分，高于旗舰单模型 69.1 分。搭 Qwen3.6-35B-A3B 在 Workbuddy Bench 得 79.1 分，官方对比 WorkBuddy 74.7、Claude Code 77.3。

**注意**：AGPL-3.0 授权的 copyleft 影响要按部署方式评估；基准为厂商自报。

### 16. Google Play 私域通道：自搓安卓 App 直接装自己手机

**发布日期：2026-10-13（本周铺开）｜类型：应用分发 / vibe coding**

Google 在 Play Store 里开了一条**私有应用通道**：用户（无需开发者账号、不缴 25 美元注册费）可用 Google AI Studio 以自然语言提示生成原生安卓项目，在浏览器内的安卓模拟器预览，再通过普通谷歌账号把应用**安装到自己设备**上。这类应用与 Play 公开目录**完全隔离**，不出现在搜索结果或详情页，除创建者外无人可访问。

**注意**：首发**仅限美国 18 岁以上用户**；即便私有也必须遵守 Play 现有政策，不合规会被拒。官方计划未来数月扩展到亲友小范围共享；想公开分发仍须升级为专业开发者账号并走完整的信任与安全审查。同批还发布了 Ask Play 应用对比、Game Finder、车载与 XR 版商店等。

### 24. Anthropic Scion：自研版本控制系统，替掉 Git

**发布日期：2026-10-14｜类型：工程基建（非产品）**

Anthropic 工程博客披露自研版本控制系统 **Scion**，用 5 个月把代码单体仓库完全迁出 Git。驱动力是量级变化：**日均合并代码变更从 5 月的约 2500 次增至 9 月的逾 3 万次**，单体仓库每天检出约 2500 万次，用 Git 的话流量会超 600 PB。Scion 由 **7 人团队**开发，把计算放在服务端、客户端按需取数，各层缓存命中率超 99%，代码检出从几分钟缩到几秒；基础设施 CPU 与内存用量较此前的 Git 镜像方案减少约 **200 倍**。

**注意**：Anthropic **明确表示无意开源**，Scion 也不是通用 Git 替代品，目前只分享设计思路。它的判断是其他团队 6—12 个月内也会撞上同一堵墙。这条不是你能装的东西，但它说明**编码 Agent 的量级正在压垮为人类设计的开发基建**。

### 27. NVIDIA Nemotron 3.5 Bolt 74B：前沿级模型塞进 24GB 显存
