## 1. JetBrains Air：把散落的 AI 产品收进一个体系

**发布日期：2026-09-22｜类型：代码生成 / 智能体开发平台**

JetBrains 把过去半年的 AI 工作整合为 Air，三层产品：Air in IDEs（在 IDE 内指挥与验收 Agent）、Air Teams（团队与 Agent 的交付协同）、Air Governance（原 JetBrains Central，做策略、审计与成本管理）。CEO 称这是「26 年历史上最重要的几步之一」。

**为什么值得试**

- 立场明确：未来的 Agentic 开发是多供应商的，所以 Air 不绑定自家 Junie。可接 Claude Agent、Codex、Copilot、OpenCode，以及任何走 ACP（Agent Client Protocol）的 Agent。
- ACP 是 JetBrains 与 Zed 共同开放维护的协议，定义 IDE 与「Agent 完整外壳」（规划、工具、模型路由、可观测性）之间怎么通信，目标是不锁供应商。ACP Registry 可在 IDE 内发现并直接跑兼容 Agent。
- 在 IDE 里可以同时开多个项目，每个项目各自一批会话，跨项目跟踪未读更新、改动文件与待推提交；diff 直接从会话打开，能对具体行留评论让 Agent 去改。
- 模型访问可自带订阅或 API key，也可用 JetBrains AI 按公开 API 价计费，甚至能在同一会话中途切换供应商。
- Air Teams 提供云端共享项目、把代码评审／发行说明／修复这类重复动作做成自动化、按项目控制 VM 规格／网络出口／密钥，MCP 服务器配一次团队共用。Air Governance 提供组织级模型与 Agent 白名单、花费上限、用量分析。

**注意**：Air Teams 与 Air Governance 目前都还在早期访问；桌面版与浏览器版并存，移动端「coming soon」。把治理层引进来意味着要接受一套新的权限与成本模型，先小范围试点。

**建议用法**：一件事就能试出价值——把「同一个人同时在跑三个 Agent 会话」这件事搬进 Air，看跨项目的改动追踪和行内评论是否真的替代了你现在的口头交接。

来源：[JetBrains 官方博客](https://blog.jetbrains.com/blog/2026/09/22/introducing-jetbrains-air) · [The New Stack 解读](https://thenewstack.io/jetbrains-air-agents-ide/)

## 2. GitHub Copilot 本地沙箱：把「别动这个目录」变成硬边界

**发布日期：2026-09-23（公开预览）｜类型：代码生成 / 安全边界**

Copilot 桌面应用上线本地沙箱，按项目定义策略，限制 Agent 会话能碰什么：文件系统（额外可读写、只读、拒绝目录）、网络（外网与本地网络）、凭据（Git HTTPS 与 GitHub CLI 认证）。

**为什么值得试**

- 它把一条提示词变成一条操作边界。「不要改部署文件」只是模型层面的请求；「该路径设为拒绝」是模型即使理解错了也执行不了的规则。
- 底层是操作系统级强制：macOS 用 Seatbelt、Linux 用 Bubblewrap、Windows 用 ProcessContainer（需 Insider 版本）。
- 失败即关闭：如果宿主系统无法执行所请求的策略，沙箱会话会直接报错，而不是悄悄回退到无沙箱运行。
- 企业管理员可以设置比项目更严格的策略。

**注意**：默认是关的。项目策略只对新建会话生效，已开的会话要手动 `/sandbox on`。仅覆盖本地会话，不作用于云端或远程主机会话；Copilot CLI 有自己独立的沙箱配置。

**建议用法**：按官方口径做一次五分钟验证：让 Agent 在允许目录里建文件、去读一个被拒绝路径的测试文件、访问一个允许和一个被封锁的主机、跑一次 Git 操作，看四条边界是否都按预期反应。用一次性测试仓库，别拿生产凭据去试边界。

来源：[GitHub Changelog](https://github.blog/changelog/2026-09-23-local-sandboxing-in-the-github-copilot-app) · [配置文档](https://docs.github.com/en/copilot/how-tos/github-copilot-app/configure-local-sandboxing)

## 4. AWS Strands Harness：把「外壳」也开源了

**发布日期：2026-09-21 开源｜类型：Agent 框架 / 开源**

AWS 在 Strands Agents SDK 之上开源了 Strands Harness——一个预配置好的通用 Agent，Apache-2.0，Python 与 TypeScript 双份。

**为什么值得试**

- 出厂自带 shell、文件读写、联网三个工具，外加上下文管理、长期记忆、会话持久化、提示词缓存，以及把子任务交给助手 Agent 的委派机制。
- 自家基准（ALFWorld、ContextBench、GAIA、WebShop、τ³-bench、Terminal-Bench 2.1 六项）称：同一批 Claude / GPT 模型下，token 用量比 Claude Code、Codex 少约 28%，准确率相当；只用 Terminal-Bench 2.1 + Fable 5 对比时是 $56.29 vs $248.05、得分 69.7 vs 61.8。
- 省 token 的机制是可查的默认值：复用前缀走缓存、单个工具结果超约 1500 token 就截断并把原文落到文件、上下文过 85% 就摘要旧轮次。
- 除模型调用默认走 Bedrock 外，其余全部跑在本机；改一行可切 Anthropic、OpenAI、Google 或 Ollama 本地模型。可部署到 Cloud Run、ECS、Azure Container Apps、Cloudflare Containers、Modal 等任意 Linux 容器环境。
- CLI 可交互配置，`/export` 直接导出成 Python 或 TypeScript 工程。

**注意**：28% 是 AWS 自测数据，且对比对象以编码类外壳为主，尚无第三方复现。它定位是通用 Agent 而非编码助手，shell 与文件工具默认开启，安全边界就是宿主环境本身。

**建议用法**：挑一件真实任务，在现有栈和 Strands 里各跑一遍，看账单差多少——重点不是换不换，而是看清你现在的 token 有多少花在「外壳」上。

来源：[GitHub: strands-agents/harness-sdk](https://github.com/strands-agents/harness-sdk)

## 6. Gemini 3.8 Flash TTS：从「选音色」改成「造音色」

**发布日期：2026-09-23｜类型：语音生成**

Google DeepMind 一次放出两个文本转语音模型：Gemini 3.8 Flash TTS 面向声音与角色设计，Flash-Lite TTS 面向高并发配音与批量音频。

**为什么值得试**

- 核心变化是生成式声音设计：不用先录音，用自然语言描述角色（年龄、口音、音色、状态）就能造出全新音色，覆盖 100+ 语言与方言。
- 音库从原来的 30 种扩展到 2000+ 可直接使用的声音，含墨西哥西语、魁北克法语、苏格兰英语等地区变体。
- 支持 30 秒样本做声音复刻，配同意验证、SynthID 水印与 C2PA 凭据；逐行剧本控制，可指定语气、语速、口音与非语言表达。
- 官方称拿下 Hume AI 语音设计基准第一（71.4），口音建模第一（60.8）；两款模型分列整体质量指数第一与第二。
- 已在 Gemini API 与 Google AI Studio 上线，同步进 Gemini Notebook 与 Google Vids；Figma、HeyGen、Agora、LiveKit、Vercel 等在接入。

**注意**：企业版 Gemini Enterprise API「即将上线」；官方尚未公布完整价目表，流传的报价先按暂定看待。声音复刻在 AI Studio 上不向伊利诺伊、得州、欧洲经济区、英国、瑞士、印度开放。语音赛道已有 ElevenLabs 深耕，「造音色」这个卖点还要看实际交付质感。

## 7. browser-use/video-use：不让模型看画面，照样剪片子

**发布日期：2026-09-23（GitHub 热榜）｜类型：视频编辑 / 开源**

browser-use 团队（AI 浏览器自动化那个项目）开源了 video-use，让 Claude Code、Codex 这类编码 Agent 做视频后期。MIT 许可，GitHub 约 2.6 万 star。

**为什么值得试**

- 设计取舍值得抄：Agent 全程不处理画面帧。每个素材跑一次 ElevenLabs Scribe，拿到词级时间戳、说话人分离与音频事件（笑声、掌声），Agent 对着这份转录文本做剪辑决策；只有真需要看什么时才按需生成画格 + 波形的合成图。
- 效果上：删口误与停顿、自动分段调色、每个剪点加 30ms 音频淡入淡出防爆音、默认按两词一组的全大写烧录字幕，还能用 HyperFrames／Remotion／Manim／PIL 生成动画叠层。
- 会自检：渲染完回头检查剪点，有没有音频跳变、画面跳跃、字幕被挡，有问题就改剪辑表重渲。
- 会话状态存在 project.md，下一次会话知道上一轮定了什么。

**注意**：需要 ffmpeg 与 ElevenLabs API key，yt-dlp 可选；Agent 驱动的剪辑精度有限，适合做「初剪 + 批量清理」，不适合精修。

**建议用法**：把一档口播素材丢进去，让它做「去口误 + 加字幕 + 调色」这种有明确标准的活，先看它交出来的初剪能省掉多少手工。

来源：[GitHub: browser-use/video-use](https://github.com/browser-use/video-use)

## 8. 阿里云栖三件视听新东西

**发布日期：2026-09-22｜类型：音乐生成 / 世界模型 / 图像生成**

**Happy Shrimp 1.1（音乐生成）**：在音乐审美建模与强化学习、世界知识与音乐领域知识融合两个方向上做了提升，音乐表现、人声质量、多语种演唱、指令理解四个维度往前走一代，支持百余种曲风与十余种主流语言，覆盖人声歌曲与纯音乐。官方坦承一个未解问题：还无法随意控制音乐中的任意元素——改一段鼓组而保留旋律、人声与其他段落，仍是待办。

**HappyOyster 2.0 Preview（世界模型）**：把视频生成从「提交等成片」改成「边生成边操控」——生成已经开始，用户还能继续输入指令，换动作、移物体、改场景，世界顺着新操作继续发展。这要求模型记住前面发生过什么，刚移动的物体不能自动归位。官方称在智能实时交互、记忆、实时响应、物理规律遵循上都有提升。**注意**：尚未面向 C 端开放，外部用户无法独立上手；且阿里既是 HappyWorld-Bench 的发起方又是参赛方（视频赛道第一），榜单结果需要第三方复现。

**千问办公「企业上下文」（办公 / 企业 Agent）**：面向企业的上下文数据管理产品，内置专属模型，用极低的 token 成本完成数据的压缩与结构化，并随业务变化及时更新，让 Agent 每次基于企业当前真实情况判断。配合 Agent 托管能力，企业可构建有名称、部门、负责人、授权范围与生命周期的数字员工，在钉钉等 IM 上与员工协同；同时发布安全中心，支持执行前沙箱划界、过程中审批拦截、异常后按记录恢复。同期还发了 AI Agent 硬件 QwenNote 与首款产品 A2，并接入阿里云上的 Salesforce。益海嘉里金龙鱼、一汽丰田、传化集团等一批企业宣布接入。

## 9. 三件值得留意的开源与办公工具

### dream-num/univer：给 Agent 的 Office 运行时（GitHub 热榜）

原先是给 SaaS 产品嵌试算表／文档／简版功能的 Office SDK，最新定位改成「AI Agent 的 Office Harness」：同一个 headless 运行时可在浏览器跑也可在 Node.js 跑，覆盖表格、文档、简报、画布、关系表与 PDF。关键差别在方向——多数「Office + AI」是让 Agent 调既有应用 API，Univer 反过来把公式引擎与画布渲染做成可嵌入、可 headless 执行的组件，Agent 在服务端就能跑试算表逻辑，不用开一个 Excel 窗口。Apache-2.0，TypeScript，今日 GitHub 热榜 TypeScript 语言榜首。企业功能可能收在付费层，接入路径偏 TypeScript。

### Agent Substrate：Agent 的执行底座（2026-09-23 上 GitHub 热榜）

agent-substrate 组织开源的 Go 项目，自我描述为「Agent Substrate: 核心系统」，Apache-2.0。定位是跑 Agent 的底层层——处理多 Agent 共享的那部分机械（Google 的 AX 编排运行时即架在这套执行底座之上）。当前公开文档刻意精简，只有身份与许可，适合想自建 Agent 平台、又不想要重框架的团队做起点；生态与文档都还很薄。

### 小米 MiMo-V2.6：开源阵营的第一个全模态 Pro

小米发布并开源 MiMo-V2.6 系列（Pro 与 Flash），两款均原生支持图片、视频、音频、文本全模态输入；Pro 在 Artificial Analysis 综合智能指数拿到 46 分，超过 Kimi K3 与 Qwen3.8 Max，成为当前最强开源模型、也是开源阵营里唯一的全模态 Pro。价格沿用 V2.5 不变（Flash 输入 1 元／输出 2 元，Pro 3 元／6 元，另有 99% 缓存折扣），官方称同等智能下价格是海外模型的 1/20 至 1/60。RL 后训练不到 6 天，Flash 与 Pro 成本约 85 万与 262 万美元，累计约 75 万条轨迹；配套开源了 7k+ RL 任务环境与端到端训练框架。同批还上线了 Pro 超高速模式与 MiMo Desktop 桌面客户端正式版。

## 10. 一条模型侧信号：同一天两家把旗舰往下压价

**2026-09-22**，相隔约一个半小时，OpenAI 放出 GPT-6 Sol 与 GPT-6 Luna，Anthropic 放出 Claude 5.5 家族首款 Opus 5.5。

- **GPT-6 Sol / Luna**：继承 Astra 的部分能力，靠改进缓存与推理效率降本，API 价格比 GPT-5.6 促销价永久下调 50%（Sol 输入 2 美元／输出 10 美元，Luna 0.1／0.5 美元）；提示词缓存在 30 分钟窗口内复用合格共享前缀最高可享 90% 输入折扣。
- **Claude Opus 5.5**：多数任务达到 Fable 5.1 水平，输入／输出价从 5／25 美元降到 4／20 美元，缓存读取降 60% 至 0.20 美元；算上单任务 token 用量下降，官方称典型工作负载成本比 Opus 5 低约 40%，输出速度提升超 30%。
- **为什么算工具信号**：两家都把「便宜」当卖点而非「更强」，且新模型当天就进了 Claude Code、GitHub Copilot 与各家 CLI 的模型选择器。对跑高并发任务的人，这是一次成本结构的重算。
- **反馈侧留个心眼**：有开发者质疑 Sol 在 DeepSWE 上的表现低于上一代 Sol；Anthropic 自己也承认模型能力接近后，跑分差距越来越难直接代表真实体验。

另有两条较小的发布值得记一笔：Grok 4.7 于 09-21 上线（约 2.1 万亿参数，强化学习侧重数小时级长任务，已进 Cursor 与 Grok Build，价格与 4.6 持平）；华为云码道面向鸿蒙开发者上线「鸿蒙编码大模型 + 鸿蒙智能体 + 实践中心」，官方称千行代码错误率降低 80% 以上、一次编译通过率提升 78% 以上。

1. **工程团队先做**：给 Copilot 配一遍项目沙箱并跑五分钟验证；这一步不花钱，直接降低 Agent 乱动的代价。
