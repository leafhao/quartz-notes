### 1. Docker Agent 1.149：把 Agent 当镜像来打包分发

**发布日期：2026-10-07｜类型：Agent 运行时 / 开源（Apache-2.0）**

Docker Engineering 的 Agent 构建与运行时，是原 cagent 项目。思路和当年 Docker 处理「环境」一模一样：**Agent 是一个 YAML 块**（模型 + 描述 + 指令 + 工具集），写好之后 `docker agent run` 就能跑，也可以推到任意 OCI registry，换台机器 `docker agent run myorg/agent:tag` 直接拉起。一个 YAML 还能描述一个**团队**而不是一个 Agent，根 Agent 把子任务派给专职 Agent。

工具来自内置工具集（think / todo / memory）或任意 MCP 服务器（本地、远程、容器里都行）；检索层可插拔（BM25 / 向量 / 混合 / 重排）；模型侧不锁厂商，OpenAI、Anthropic、Gemini、Bedrock、Mistral、xAI 加 Docker Model Runner 本地模型都在列。Docker Desktop 4.63+ 已内置该插件。

v1.149 有两条值得注意的：**skills 可以直接指向公开 GitHub 仓库并加载**（跟上了这周被 skill 仓库刷屏的生态），以及**evaluator 走 models gateway，OpenAI Decisions 成为原生评判后端**——Docker 是最早把决策模型端点接进评测链路的 harness 之一。

仓库：https://github.com/docker/docker-agent

**注意**：环境变量与部分 lint 规则里还留着旧名 `cagent`。1.147/1.148 两天前刚加了 hook 驱动的 Agent 路由、工具结果 50 KiB 上限（防止超长输出卡死压缩）、codemode 工具调用可见性。

### 2. Google Stitch CLI + stitch loop：给编码 Agent 一份设计系统

**发布日期：2026-10-01（CLI）/ 10-02（stitch loop，**本期补录**）｜类型：设计系统 / 编码 Agent 接入**

Google Stitch 本来是「AI 驱动的设计画布」加一个 MCP 与 SDK。10-01 补上了 CLI，补齐了最后一块拼图：终端里生成页面、抓运行中应用的快照、导出设计规格、把整套东西接给编码 Agent，全程不开浏览器。

真正有价值的是 **DESIGN.md**：把设计令牌（YAML frontmatter）与设计理由（markdown 正文）写在同一份文件里。传统 token 格式只能告诉模型 `color.action.primary = #1A1C1E`，DESIGN.md 还能写「主色承载信任信号，破坏性操作不要用它」——**前者是值，后者是判断**。配套 CLI 有四个命令：lint（含 WCAG AA 对比度校验）、diff、export（导出 Tailwind 或 W3C DTCG）、spec。

10-02 之后的 `stitch-loop` 是另一个思路：以 `.stitch/next-prompt.md` 做「接力棒」，一轮四步（读任务 → 用 Stitch MCP 生成页面 → 集成进站点 → 写回下一个任务），让 Agent 自己迭代一座站点。安装走 Agent Skills 标准：`npx skills add google-labs-code/stitch-skills --skill stitch-loop --global`。

仓库：https://github.com/google-labs-code/design.md ｜画布：https://stitch.withgoogle.com/

**注意**：社区反馈里最该看的一条是 **Stitch 里的 AI 经常「报成功但没真改」**；免费档有每日额度且暂无付费通道；DESIGN.md 规范本身标着 `alpha`，会变——真要进 CI 就把 lint CLI 版本钉住。

### 13. Kandinsky 6.0 Video：29B 开源视频模型，一次生成画面与声音

**发布日期：2026-10-06｜类型：视频生成 / 开源（MIT）**

Sber 的 Kandinsky Lab 放出 **Pro 29B / Lite 3B** 两档扩散模型，**MIT 许可、无地域限制**——这一点与 MiniMax H3 的开源权重排除美/欧/英/韩形成鲜明对照。

它做的事是开源视频模型一直缺的那件：**一次生成 5 秒画面 + 同步 44kHz 音频**，含口型对齐，另有独立超分模型把画面抬到 1920×1080；音频可关掉只出画面。架构是双流 CrossDiT：预训练视频流 + 新训音频流，通过**双向交叉注意力**逐层互看，所以「关门」和「砰的一声」落在同一帧上。训练含 SFT → RL → 蒸馏（10 步）三段，官方称 **RL 阶段把生成语音的词错率降了 47%**。

**注意**：官方对 LTX 2.5 与 Veo 3.1 Fast 的对比**全是 Sber 自己做的**；只有 5 秒、没有延长模式；非蒸馏 Pro 在 H100 上一条 Full HD 约 292 秒。定位是开机与预演，不是成片。

### 17. LlamaIndex OpenDocRouter：十个解析器，一个 API

**发布日期：2026-10-07/08｜类型：文档解析 / 托管 API**

把 PDF 与图片转成一致的 Markdown，背后并排放 **10 个解析器**（5 个前沿 + 5 个开源，开源侧含 MinerU2.5-Pro、PaddleOCR-VL-1.6、dots.mocr 等），每个都跑在**带版本的解析配方**里，并在 ParseBench 上同时标出质量与成本。

它自己给出的理由比功能更值得读：Hugging Face 上有 4,000 个 OCR 模型，前沿实验室几乎每月出新——**今天最好的那个到明年 Q1 就不是了，所以真正的问题不是「选哪个」，而是「换起来有多快」**。切换就是改一行：同一个请求、同一份 Markdown 输出，不用改提示词或集成。可选 `layout: true` 给没有原生支持布局的模型补上带坐标的边界框与统一 layout 类；按 token 计费，失败页面不计费。

**注意**：价格区间跨度很大（约 $0.86–48.82 / 千页），不同解析器差几十倍，接入前先按自己的文档类型跑一轮 ParseBench 式的对照。
