## 1. 微软新版 Copilot：Office 从「被调用」变成「被收编」

**发布日期：2026-09-25（宣布）｜类型：办公 Agent / 编程 / 常驻代理**

微软对 Copilot 做了一次定位级改版，CEO 纳德拉称其为「work 的操作系统」。核心是四个部分：Autopilot、Code、Home，以及 Microsoft 365 深度整合。

**为什么值得试**

- Word、Excel、PowerPoint 被直接整合进 Copilot 应用与浏览器标签页，可在 Copilot 内直接创建、编辑、协作，文件与原有 Office 应用保持同步。Copilot 的角色从「Office 里的侧边栏」变成「进入 Office 的统一入口」。
- 新增 **Code**：采用与 GitHub Copilot 同源的技术，用自然语言创建应用、仪表盘与工作流，产物可直接托管在企业自己的 Microsoft 365 租户内。
- 新增 **Autopilot**：是此前 Scout 代理的升级版，可被指派角色与目标、监控沟通渠道、管理周期性任务并自主推进项目；有独立身份与权限控制，9 月底扩大至私人预览。
- Home 把交互拆成 Chat（快问快答）与 Cowork（长周期多步任务），并加了 Today，主动推送邮件、会议与待办里的相关事项。
- 消息公布当天微软收涨 3.66%。

**注意**：Autopilot 的自治程度直接取决于企业已有的权限与治理模型，落地前要先想清楚它能代表谁、能碰什么。这是把「助手」改成「入口」的一步，切换成本是组织性的，不是功能性的。

## 2. Cursor 的两个 Bot：把「最后一段」自动化

**发布日期：2026-09-23 上线，本周广泛铺开｜类型：代码生成 / 部署监控 / 安全审查**

Cursor 推出两个软件开发 Bot，Teams 与 Enterprise 版本可用。二者都源自 Cursor 一个多月前收购的生产监控公司 Firetiger。

**为什么值得试**

- **Rollouts 盯部署**：PR 打开时先读 diff 和它涉及的系统，写一份监控规划作为 PR 评论——列出识别到的风险、变更预期效果、要检查的信号，以及埋点缺口（这是问题变更最常被漏掉的原因）。规划人可以直接在 PR 里改，Rollouts 采用你的版本。部署事件触发后，它对着 Datadog / Grafana / Honeycomb 的日志、指标与链路跑规划，逐环境跟踪，因此同一变更可能预发布验证通过、生产被标红。
- 检测到回归时，它会指出怀疑的变更、通知作者，可按配置开一个待审批的回滚 PR，或把发现交给云端 Agent 修；**目前不会自行合并或回滚**。
- 它擅长的三件事：在全局告警触发之前发现只在某个区域／端点出现的回归；区分预期效果与真回归（有意为之的指标激增不惊动人）；合并前标出缺失的埋点。
- **Security Review 审漏洞**：结合整个代码库上下文读每个 PR，只报可利用缺陷，风格与质量仍归 Bugbot。覆盖面包括 SQL／命令／模板／LDAP 注入、新增路由上的认证与授权绕过（含「某次重构后没再跑」这类）、硬编码密钥、SSRF 与未校验重定向、不安全反序列化、危险依赖变更。每条带严重级别、攻击路径与修复建议，可一键修；支持团队自定义规则（例如「外部调用必须走哪个 client」）。官方自测称平均评审时间从 4.8 分钟降到 3.8 分钟、评论采纳率从 45–50% 升到 60–70%。
- 免费额度给 10 天（Teams 约 50 次变更、Enterprise 约 500 次）。

**注意**：Cursor 没有公布 Rollouts 与 Security Review 各自的定价，只有「包含在 Teams／Enterprise 套餐内」。一个工程负责人没法拿不存在的价格做成本收益测算，这是真实的采购障碍。启用前先把分支保护、自定义规则与事故责任人定下来，比先开 Bot 更要紧。它与 Datadog 的 Bits Release、Harness、LaunchDarkly 的 Guarded Rollouts 正面撞车；Cursor 的差异不在信号采集，而在它同时握着编码 Agent、代码托管（Origin）、PR 与生产反馈四段。

**建议用法**：先在非核心仓库开 Security Review 跑两周，只数「报出来你确实会去改」的条数；Rollouts 则在一次真实灰度里验证它能不能在全局告警之前叫停。

## 3. 英伟达 Open Agent Safety Platform：把边界做进芯片

**发布日期：2026-09-28｜类型：Agent 安全 / 开源运行时**

英伟达发布 Open Agent Safety Platform，由开源的 **OpenShell** 安全运行时与 **Sentry** 参考系统设计组成，目标是在模型与 Agent Harness 之外建立一层可强制执行的边界。

**为什么值得试**

- **OpenShell**（现已广泛可用，Apache 风格的开放软件）：把运营者的指令变成可验证策略——先声明 Agent 能访问哪些文件、网络、工具、进程与凭据，运行前检查、运行中强制。支持 Claude Code、Codex、OpenCode、GitHub Copilot CLI、OpenClaw 等既有 Agent，也支持自带 Agent 与沙箱镜像；开放与闭源模型通吃。在 Vera CPU 上开销极低，且可扩展到 Arm、Intel 等第三方平台。
- **Sentry**：跑在 BlueField-4 DPU 上的带外看门狗，独立于主机与工作负载，在隔离的信任域里持续监测。Agent 若试图越出软件边界，可在**毫秒级**隔离并停止它——即使主机资源已不可信，这层仍在。基于 DOCA，可做请求／响应检查、可验证遥测、Agent 身份校验与细粒度零信任策略。
- 英伟达给这套东西的动机很直白：近期几起事故的模式完全一样——Agent 绕过了应用层的安全控制去完成被指派的任务。所以边界必须落在应用层之外。
- 官方口径是：如果你已经跑在 Vera + BlueField-4 上，开启这层保护只是一次软件更新。
- 生态侧名单很长，Anthropic（Claude Managed Agents 把 Agent 循环与执行沙箱分在不同服务器）、Microsoft、CrowdStrike、Palo Alto Networks、Hugging Face、JPMorganChase、Salesforce、SAP、ServiceNow 等均在列；SpaceXAI 称会把该平台用于 Cursor 编码 Agent 与 Grok 模型。

**注意**：OpenShell 不需要 BlueField-4 也能跑（支持本地、本地部署、云与 Kubernetes），但芯片级隔离那部分只有买了硬件才有。整件事目前仍偏「平台厂商定义标准」的路径，跨厂商策略语言能不能真统一，要看后续。

来源：[NVIDIA 新闻稿](https://nvidianews.nvidia.com/news/open-agent-safety-platform) · [英伟达开发者博客](https://developer.nvidia.com/blog/nvidia-open-agent-safety-platform-a-reference-for-continuous-in-silicon-agent-monitoring) · [中文解读](https://blogs.nvidia.cn/blog/open-agent-safety-platform)

## 4. 可灵 4.0 / 4.0 Flash：单次生成翻倍到 30 秒

**发布日期：2026-09-28（Flash 上线，正式版 10 月）｜类型：视频生成**

可灵宣布 Kling 4.0 将于 10 月正式发布，**Kling 4.0 Flash 已于 9 月 28 日面向 Ultra 年度订阅用户开放**。这是 Kling 3.0（1 月 31 日）之后约八个月来的首次大版本跳升。

**为什么值得试**

- 单次原生长度从 15 秒翻倍到 **30 秒**，并支持视频延长至 2 分钟；Flash 版支持到 20 秒。
- **多关键帧控制**从「首末帧」扩到最多 **10 个关键帧**；**多模态参考**从 3 个 Kling Elements 扩到最多 **15 路**（最多 10 张图 + 5 段视频合计 30 秒 + 主体），可给每个主体分配音色，跨镜头保持角色与元素一致。
- 画质与音画：最高 4K、**10-bit HDR**（约 10.7 亿色，是 8-bit SDR 的 64 倍，渐变与明暗过渡更顺）、双声道立体声、更准的口型同步、新增 21:9 超宽画幅（共 5 种比例）。高频运动场景（多人打斗）四肢与面部逐帧保持完整，打击有重量感。
- 可控性：支持最长 8000 token 的提示词；可上传参考片段复用其运镜或动作；可用文字／图片／主体参考增删改主体与背景、调天气与风格（演示里把街景人群事后抹掉）。语言支持扩到德、法、印地语等。
- Flash 定位高频创作，主打更快的生成速度与更高的成本效率。

**注意**：可灵截至 9 月 28 日未公布 4.0 的价格变动，API 价目表仍只列 3.0 时代模型，也没有任何官方基准。Flash 只对 Ultra 年度订阅开放，普通用户暂时试不到。竞品对照看，字节 Seedance 2.5 是同一档的对手。

**建议用法**：拿一条真实的 30 秒广告分镜试——重点看三件事：跨关键帧的角色一致性、运动最激烈那两秒有没有崩、立体声与口型是否对得上。

## 5. 阿里 Qwen-Audio-3.1：五模型升级，顺手下调全线价格

**发布日期：2026-09-28｜类型：语音生成 / 语音识别 / 实时交互**

千问发布 Qwen-Audio-3.1，升级 ASR、TTS、Realtime 三条线，并新增 **TTS-Next** 与 **ASR-Next** 两个新模型，组成五个模型的阵列，覆盖音频的理解、生成、交互与创作。

**为什么值得试**

- **ASR-Next**：新增多人识别，带说话人标签与时间戳，并能理解声音与情绪。
- **TTS-Next**：把语言模型与扩散结合，一次生成语音、音效与背景音，而不是只出人声。
- 全面下调价格：**TTS 降约 70%、Realtime 降约 85%、ASR 最高降 95%**。这个幅度基本把语音 AI 从「专用功能」推成普惠基础设施。
- 官方称在识别准确率、语种覆盖、低信噪比场景、说话人分离精度四个维度全面提升。

**注意**：官方未逐项公布新模型的完整价目与延迟数据；Realtime 降 85% 后的绝对值仍需按实际用量算。语音赛道同期还有 Google Gemini 3.8 Flash TTS（[[2026-09-24]]）与 Inworld TTS-2 在推进，「便宜」会成为这一轮的主要竞争维度。

**建议用法**：如果你在跑客服、会议转写或播客剪辑，直接按新价重算一次账单——ASR 降 95% 意味着原来为了省钱而做的「先粗筛再精转」流程，可能已经没必要了。

## 6. Cloudflare cf CLI + Forge：为 Agent 重做的官方命令行

**发布日期：2026-09-28｜类型：开发基建 / 开源**

Cloudflare 发布了一个 **agent-first 的 CLI：`cf`**，覆盖 3000+ Cloudflare API 操作——对比之下 Wrangler 大约只有 280 个。同时开源了 **Forge**，Cloudflare 内部用来从 API 定义生成 SDK、CLI、文档、schema、MCP 服务器与基础设施绑定的 CI 流水线。

**为什么值得试**

- 覆盖面的差距是量级级的：从「能配 Workers」到「几乎整个 Cloudflare API 都能从命令行调」，这对让 Agent 接管运维是最关键的前提。
- 支持用 TypeScript 做程序化配置，并支持跨 API 搜索——Agent 不必预先背下命令，可以自己搜出该调什么。
- Forge 的价值在方向：把「API 定义」作为唯一真相，每次 PR 自动重生成全部下游产物并保持同步。Apache 2.0。这等于把 Cloudflare 自己维护 SDK 的方式开源出来，任何人都可以照抄这套「定义驱动」的生成流水线。
- 已经有人（Brayden Wilmoth）演示了用它让 Agent 直接控制 Cloudflare 账号。

**注意**：3000+ 操作意味着权限面也同步放大，给 Agent 用的凭据必须按最小权限切；Forge 是内部工具开源，文档与社区还在早期。

## 8. 华为双线：openPangu-2.0 全流程开源 + 小艺 Work 上架

**发布日期：2026-09-28（开源）／2026-09-24（上架）｜类型：开源模型 / 办公 Agent**

**openPangu-2.0 开源训练全流程**：9 月 28 日华为宣布，盘古 openPangu-2.0 的**预训练代码、SFT 代码与后训练 RL 代码**正式开源上线，配套昇腾原生训练与推理的最佳实践。开放地址在 GitCode 的 ascend-tribe 组织下（openPangu-2.0-Training 与 openPangu-2.0-RL 两个仓库）。

意义在于「开」的深度：国产开源大模型正在从「开放权重」走向「开放全流程」。当海外厂商把最强能力锁在 API 后面时，华为选择把训练管线交出去——既是押注生态厚度，也是给国产算力找真实应用场景。想复现训练或做后训练研究的团队，这是少见的完整材料。

**小艺 Work 上架众测**：9 月 24 日华为小艺 Work 正式上架应用市场并开启众测，定位从「AI 帮你写」走到「AI 帮你做」。用户给一个工作目标，它自主拆解任务、匹配能力、调度工具、推进流程，最终**直接交付 Word、PPT、Excel、网页等可用成品**，覆盖办公、编码、创作三大场景。

- **双执行环境**：电脑端可在「云电脑」与「本地设备」间切换。云电脑模式任务在云端独立运行、不占本机算力，长报告生成、批量数据处理可 7×24 小时后台推进，合盖离座也不中断；本地模式直接调度本机文件与专业软件，数据不出设备，适合敏感资料。
- **全端覆盖**：鸿蒙手机、平板、鸿蒙电脑、鸿蒙手表与 Windows。原鸿蒙手机／平板端的小艺 Claw 升级为小艺 Work 并保留原有偏好与项目记忆，Windows 客户端全新上线，鸿蒙手表可远程创建任务、查状态。
- **办公连接器**：可接钉钉、飞书、华为云空间，直接调用群聊消息、在线文档与云盘文件，成果一键存回云空间。鸿蒙电脑上还支持浏览器自动化，做网页采集与流程填报。
- 安全侧：专属安全沙箱、提示词注入防护、指令分类分级管理，风险操作需明确授权，高风险操作审慎拒绝。另有 100+ 专家与专家团能力按任务接入。

## 9. Agent 基建三件：记忆、技能与真机

### Hindsight（vectorize-io）：会学习的 Agent 记忆

**（本周 GitHub 热榜，单日 +4561★）** 它要解决的不是「检索对话记录」，而是「从历史里学习」。记忆被分成四类——世界事实、经验、观察与心理模型，对外提供 retain / recall / reflect 三类操作；支持 Python、Node.js、Go、MCP 与 LLM 包装器接入，README 称在 LongMemEval 基准上取得领先成绩。适合需要长期记忆、个性化与深度推理的 Agent 应用。同一天热榜上，cognee（持久长期记忆平台，+96★）与 microsoft/SkillOpt 也在同一方向。

### microsoft/SkillOpt：给冻结模型训练自然语言技能

**（GitHub 热榜，+136★）** 一个「文本空间优化器」：模型权重不动，改为迭代训练可复用的自然语言技能（skills）。思路和本轮其他几家（把能力沉淀为 SKILL.md 一类文件）一致，但多了「自动优化」这一层。如果你已经在用技能文件喂 Agent，这个值得看一眼它是怎么把「技能文本」当成可优化参数的。

**（GitHub 热榜，+449★，Apache-2.0）** 一个 MCP 服务器，让 Agent 直接驱动真实的 iOS / Android 设备、模拟器与仿真器，支持原生 App 自动化与数据抓取。关键设计：**优先读无障碍树，不烧视觉 token**，只在必要时才回退到截图 + 坐标。至今多数 computer-use Agent 止步于浏览器，这一步把 MCP 的能力面推到手机端。

## 10. Block 开源 Buzz：人和 Agent 用同一套签名身份

**发布日期：2026-09-27（GitHub 热榜，34.8k★）｜类型：Agent 协作 / 开源**

Block（Square 母公司，也是 Goose 的开源方）开源了 Buzz——一个建立在 Nostr relay 之上的人机共享工作区，Rust 编写，Apache-2.0。

**为什么值得试**

- 多数 Agent 协作工具的做法是「往 Slack／Discord 上接一个机器人」。Buzz 反过来：Agent 用**和人类完全相同的协议**进入工作场所——自己的密钥对、自己的频道成员身份、自己的审计轨迹。每条消息、每次代码评审、每个工作流步骤都是同一份日志里的一条签名事件。
- Agent 可以开仓库、发补丁、评审代码、跑工作流，甚至加入语音讨论。身份模型只有一套，而不是事后附加一层独立的权限系统。
- 技术上基于 NIP-34 的 git 事件，这意味着一份人类可读、可验证、可自托管的协作记录。

**注意**：默认部署是自托管（你要自己跑 relay），且要理解 Nostr 的签名事件模型才能把权限设计想清楚。上手门槛不低，适合已经在意「审计轨迹能否自证」的团队。

## 11. 办公与写作：四件新东西

### open-slide 2.0：Agent 写的幻灯片，人能接着改

**（本周发布）** 一个**面向 Agent 的幻灯片框架**，MIT 许可。每张幻灯片就是一个 React 组件，跑在固定的 1920×1080 画布上。工作流是「Agent 起草 → 人做最后调整 → 源码文件始终是唯一真相」。

2.0 版本三个新东西：**可视化编辑器**（拖拽、缩放、旋转、原位改文字、评论、演示模式）、**可编辑的 PPTX 导出**（同时保留 PDF / HTML 导出）、重构的界面。工具链同步升到 React 19 / Vite 8 / TypeScript 7，要求 Node.js 20.19+，并新增 current-slide 这一面向 Agent 的协作机制。

和市面上两类 AI PPT 的差别值得说清：模板填空型改起来还是得手动调；文生图型好看但改不动。open-slide 走第三条路——让 Agent 直接写页面代码，产出是结构化的、可反复迭代的。

### Univer 1.0：给 Agent 的 Office 运行时发布正式版

**（2026-09-26）** 上周以「GitHub 热榜」形式出现过，本周发布 **1.0 正式版**——这次是版本级的里程碑，值得单列。定位是「AI Agent 的 Office Harness」：同一个 headless 运行时既能在浏览器跑、也能在 Node.js 跑，覆盖表格、文档、简报、画布、关系表与 PDF。关键差别在方向——多数「Office + AI」是让 Agent 调既有应用 API，Univer 反过来把公式引擎与画布渲染做成可嵌入、可 headless 执行的组件，Agent 在服务端就能跑试算表逻辑。Apache-2.0，TypeScript。企业功能可能收在付费层。

### MuM：为「读」而不是「写」做的 Markdown 引擎

**（2026-09-28，Product Hunt）** 由开发者 IceskYsl 发布的 macOS 原生 Markdown 阅读器，开源。它不是又一个 Obsidian／Typora——那些以写为主、预览为辅；MuM 针对的是「快速阅读、搜索、在多个文件夹之间导航散落的 Markdown 文档」这个真实需求。

用纯 AppKit 写，没有 Chromium 也没有 Electron：安装包 **1.7 MB**，冷启动 **< 0.3 秒**，5 MB 文件滚动保持 100+ FPS。有意思的一点是它的开发流程本身——用 Claude Code 做自动化测试，用 DeepSeek Harness 做发布门禁。

### 天工工作台（SkyProduction）：AI MV 与智能配乐

**（2026-09-27）** 一次放出三个能力：**AI MV 创作**（分析歌曲结构、节奏与歌词，自动生成导演方案与分镜，再用 Seedance 2.5 出片并保持跨镜头角色与场景一致）、**Mureka V8／V9／V9.5 音乐模型接入无限画布**（文字生成原创歌曲）、以及**图／视频智能配乐**。三者都在同一个画布工作区里完成，不必换工具。对做短视频与音乐内容的人，这是把「出歌 → 出 MV → 配乐」串成一条线。

## 12. 其他值得记的信号

### Prime Agent：自改进的编码运行时（2026-09-28 开源）

Prime Intellect 开源了 Prime Agent，一个自改进的编码 harness，核心是 Recursive Language Model 加一个「Continual Harness」——Agent 能在干活的过程中修改自己的外壳。同批的 PRIME-RL 多 Agent 训练也更新了：支持编程式定义 Agent 之间的交互、选择哪些角色参与学习、在多 Agent 回合间分配信用。prime-rl 与 Verifiers 两个发布同为开源。这条方向值得留意：外壳（harness）本身成为被优化的对象。

### Paperclip：把 Agent 当员工管（GitHub 热榜，92.8k★）

开源自托管的 AI Agent 编排系统，Node.js 服务 + React 界面，把多个 Agent 组织成有角色、层级、预算和审批的公司结构。可接入 Claude Code、Codex、Cursor、OpenClaw 等，通过任务票据、心跳调度、审核日志与成本控制跟踪工作。它自己点名的目标痛点很诚实：「同时开 20 个 Claude Code 终端，已经搞不清谁在干什么」。对需要协调大量 Agent、又想保留审计与预算管控的团队是正解。

### PixAI Tsubaki.3：动漫专用的一体化模型（2026-09-28）

PixAI 发布 Tsubaki.3，一个覆盖**插画、漫画、视频**的动漫专用模型，从零自研而非微调既有公开模型，并公开了完整技术报告。数据侧约 5 亿图文对经三阶段过滤压到约 5000 万；专门处理了「风格塌缩」——强化学习容易把模型推向单一平庸审美的倾向，方法是在约 7000 张人工精选图上做监督微调，再分两阶段 RL（先修解剖与多主体正确性，再优化作为插画的观感）。可从一张参考图展开表情集、多角度、换装与年龄变体且保持面部与体型一致，能逐步走线稿→灰度→平色→成稿，也能把单张插画变成带分镜、气泡与对话的漫画页（四语文字渲染）。同时开源了 **Tagger 1.0**（30,877 个标签的动漫打标模型，基于 SAM 3 主干，角色标注 micro-F1 提升 10.4 点，Hugging Face 免费供研发使用）。**注意**：发布时间口径不一（技术侧称 09-16，公开报道为 09-28），此处按本周公开记录。

### MiniMax-Music3：开源权重，五分钟整曲（本周开源）

MiniMax 在 Hugging Face 放出 MiniMax-Music3 权重：输入歌词与详细的音乐描述，可生成最长**五分钟**的完整歌曲，输出 32kHz / 16-bit 立体声 WAV。架构是分层的——8B Global LLM（由 Qwen3-8B 初始化）负责长程音乐结构，0.6B Local LLM 负责帧级声学细节，合成模块基于 Flow Matching 与 Flow-VAE（改自 MiniMax Speech），训练分词器用八层 RVQ（首个语义码本 16,384 项，其余七个声学码本各 1,024 项）。支持结构化 caption 与歌词段落标签做细粒度控制，已有 SGLang-Omni、diffusers、ComfyUI 支持。公开权重开源到音乐生成这一步，开发者生态的门槛被显著拉低。

### Inworld Realtime TTS-2 / Fish Audio transcribe-1（2026-09-28）

**Inworld Realtime TTS-2** 给开发者**自然语言控制**：语气、停顿、节奏、笑声等表达细节都可直接描述；Flash 版针对极低延迟高并发。同批发布的 Realtime Router + Jev 则把「打字问一句」变成便宜的 yes/no、选择或打分决策，官方称这类决策任务比走生成式模型快得多也便宜得多。

**Fish Audio** 的语音转文字上线 transcribe-1 与 transcribe-1-pro，Pro 可标注说话人，并捕捉笑声、情绪线索这类非语言信号。

### VoiceStudio：本地版「ElevenLabs」（GitHub 热榜，+3221★）

完全本地运行的开源语音工具集，覆盖声音克隆、配音、转录与有声书制作，支持 646 种语言。默认使用 OmniVoice 引擎且可换引擎，工作流跑在用户自己的硬件上，远程服务只是可选项。适合想替掉商业语音服务、又不愿把音频送出本机的人。

### Mo（Momentic）与 Tapkit：两个具体到能上手的 Agent（2026-09-28）

**Mo** 是 Momentic 的无脚本 AI 质量工程师：把应用指给它、描述要测什么，它自己去折腾产品、验证失败、返回复现步骤、日志与录屏。Momentic 官网称已累计抓到 117,000+ 个 bug。**Tapkit** 让 Claude Code 或 Codex 通过 MCP / REST 控制一台真实 iPhone——截图、点击、滑动、打字、操作 App Store 应用、iMessage、2FA，标价 49 美元／台／月。两个都是「Agent 从屏幕里走出来」的例子。

### Claude Sonnet 5.5 / Haiku 5.5：Anthropic 预告补全 5.5 世代（2026-09-28）

在 Opus 5.5（[[2026-09-24]]）之后，Anthropic 正式预告将在未来数周推出 **Claude Sonnet 5.5 与 Claude Haiku 5.5**，覆盖中端主力与轻量极速两条线，完成 5.5 世代的全档位布局。官方口径是延续 5.5 系列在推理效率、长上下文、工具调用与安全对齐上的优化。同期 Claude Code 2.1.284 已把默认模型切到更快的 Sonnet 5.5，并给出 1M 上下文窗口。对按量付费的团队，这通常意味着中档任务的单位成本会再降一档。
