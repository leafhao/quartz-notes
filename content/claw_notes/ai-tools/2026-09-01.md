# AI 工具推荐 | 2026-09-01

> 只收录最近 7 天（2026-08-26 至 2026-09-01）发布的新内容。Tavily 本周在图像生成、音视频生成方向没有检索到可信硬发布，因此不以横评、招聘页或旧公告凑数。

## 本周精选

### 1. ZCode 3.10.1 + GLM-5.3-Flash（代码生成）

- **动态**：ZCode 于 8 月 28 日发布 3.10.1；其 8 月 26 日的 3.9.2 已内置 GLM-5.3-Flash，并改善 Computer Use 的识别与稳定性、权限提示、浏览器标签复用等。GLM-5.3-Flash 同时进入 GLM Coding Plan，官方文档标注其额度是 GLM-5.3 的 3 倍，周末及低峰调用按 50% 积分计费。
- **推荐理由**：这是本周最适合实际试用的编码工具更新；对比只看模型榜单，它同时给出了 IDE/Agent、额度和 Computer Use 的完整落地入口。
- **适合谁**：想补充 Codex / Claude Code 之外编码 Agent 选项，或希望以较低调用成本测试多模态编码任务的开发者。
- **注意**：建议先用真实仓库的小任务评估长程稳定性；不要仅凭匿名模型阶段的榜单决定迁移主力工具。
- **日期**：2026-08-26、2026-08-28
- **来源**：[ZCode Changelog](https://zcode.z.ai/en/changelog) · [Z.ai GLM-5.3-Flash 文档](https://docs.z.ai/guides/vlm/glm-5.3-flash)

### 2. Qwen3.8-Flash-Next（开源模型 / 开发库）

- **动态**：Qwen 团队于 8 月 26 日开放 Qwen3.8-Flash-Next 权重。该多模态 MoE 模型采用 125B 主模型加 51B N-gram embedding、每 token 激活 6B 参数，并被定位为 Qwen4 架构的早期预览；官方仓库称其侧重编码与办公任务。
- **推荐理由**：对做模型服务、Agent 后端或架构研究的人，它比泛化的“新模型发布”更有观察价值：开源权重、长上下文与低激活参数组合，为成本敏感的编码/办公工作负载提供了新选项。
- **适合谁**：有云端 GPU / 托管推理资源的模型工程团队，以及关注混合线性注意力架构的研究者。
- **注意**：模型总体规模仍很大，不适合在当前家用 Mac mini 上本地部署；优先用 API 或托管服务小规模验证。
- **日期**：2026-08-26
- **来源**：[Qwen 官方博客](https://qwen.ai/blog?id=qwen3.8-flash-next) · [GitHub 官方仓库](https://github.com/QwenLM/Qwen3.8-Flash-Next)

### 3. Claudeforce / Salesforce in Claude（文档与企业工作流）

- **动态**：Salesforce 与 Anthropic 于 8 月 26 日宣布 Claudeforce。Salesforce in Claude 通过 AIforce 提供的 MCP Server、API 与 CLI，把 CRM 数据、业务流程和治理规则接入 Claude，目标是在对话界面中直接完成销售、服务等企业任务。
- **推荐理由**：这是“AI 写作助手”向“带企业上下文的可执行工作流”演进的明确信号；对企业知识问答、报告生成与业务操作一体化设计有参考价值。
- **适合谁**：同时使用 Salesforce 与 Claude 的企业团队，或正在设计 MCP 企业数据接入层的开发者。
- **注意**：价值依赖 Salesforce 数据质量、权限治理与审计能力；个人用户无需追新。
- **日期**：2026-08-26
- **来源**：[Salesforce 官方公告](https://www.salesforce.com/news/press-releases/2026/08/26/salesforce-and-anthropic-announce-claudeforce) · [VentureBeat](https://venturebeat.com/orchestration/salesforce-just-put-its-entire-crm-inside-claude-and-says-youll-never-need-its-app-again)

### 4. GitHub Copilot 企业策略与计费调整（代码生成 / 管理）

- **动态**：GitHub 于 8 月 26 日开始逐步启用 Copilot 全局模型策略，未单独配置的新 GA 模型会继承全局策略，开放权重及需保留数据的模型默认关闭；8 月 28 日又公布后续席位预付费、超额用量付费，以及 Copilot Chat / cloud agent 策略统一计划。
- **推荐理由**：它不是新模型，但会直接影响企业 Copilot 的模型可见性、预算与治理，是管理员本周必须处理的实际变化。
- **适合谁**：Copilot Business / Enterprise 管理员与平台工程团队。
- **注意**：先检查组织的全局模型开关、预算控制和默认 review effort；个人 Pro 用户无需因本次企业策略立即调整。
- **日期**：2026-08-26、2026-08-28
- **来源**：[GitHub：全局模型策略 GA](https://github.blog/changelog/2026-08-26-global-model-policy-generally-available) · [GitHub：策略与计费变更](https://github.blog/changelog/2026-08-28-upcoming-changes-to-github-copilot-policies-and-billing)

## 本周建议

1. **优先试用**：用 ZCode + GLM-5.3-Flash 跑一个中等规模仓库的“定位问题—修改—测试”闭环，与当前主力编码 Agent 对照成功率和成本。
2. **企业 Copilot 用户先治理**：管理员检查全局模型策略、开放权重模型默认关闭状态和后续用量预算，避免 9 月策略统一后出现模型不可用或意外费用。
3. **暂不本地部署 Qwen3.8-Flash-Next**：家用 Mac mini 不适合承载该体量模型；把它作为 API / 托管推理候选和架构观察对象即可。
4. **图像与音视频本周不追新**：没有经过日期与来源核验的硬发布，继续使用现有工具比被横评文章带节奏更稳妥。
