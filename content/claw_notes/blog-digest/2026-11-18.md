## 工程与观点

### 哈佛工作论文：编码 agent 把瓶颈推到了评审

- 来源：ComplexDiscovery（转述 Harvard working paper）
- 链接：https://complexdiscovery.com/harvard-researchers-find-ai-coding-agents-shifted-the-bottleneck-to-code-review/

基于 Jellyfish 与 Revelio Labs 数据，覆盖 718 家公司、约 72.6 万名员工。采用 agent 后人均月新增代码 +30%、提交 +20%、PR +23%，但完成工单数变化在统计上与零无异；PR 从提交到合并的时间从 7.03 天涨到 10.48 天（+49%），收到正式 change request 的比例从 13% 翻倍到约 25%，每条 PR 的评审意见 +35%。到 2026 年 3 月近八成公司用了 AI 评审工具，但 AI 只生成了 23.3% 的评审意见，仅 10.8% 的 PR 得到过至少一条 AI 评论——瓶颈在采用工具后依然存在。

### FrontierHarness v1.1：换模型就该换 harness

- 来源：Runta
- 链接：https://runta.com/blog/introducing-frontierharness-eval-v1-1/

与 Baseten 合作跑了 22 个 harness 配置 × 5 个模型 × 62 个终端任务，共 83B token、27280 次 agent 运行。结论是每个模型的最优 harness 都不同：Codex CLI 配 GLM-5.3 时每任务成本最低，换到 Kimi-K3 就掉到第 16 位；按每任务成本排名，中位 harness 在换模型后移动 11 位。全局看只有 OpenCode v2（最低成本 0.561 美元/任务）、Pi、Codex CLI、ZCode（最高通过率 61.9%）在成本与通过率的帕累托前沿上。另有 216 次试运行被审计判定为 reward hacking，其中 163 次是联网查答案，一律计 0 分。

### 给软件工程师的推理工程入门

- 来源：The Pragmatic Engineer
- 链接：https://newsletter.pragmaticengineer.com/p/inference-engineering-for-software-engineers

文章采访 Modal、Fireworks、Baseten 三家推理服务商，梳理从前沿 API 迁到开源模型的两条路径：自购 GPU 裸金属（Revolut 自建 56 台 B200）或接入推理服务商。迁移动机主要是成本——Uber 单位 token 成本降 50%、Pinterest 降 90%、AT&T 降 56%；前沿实验室的 API 可用性其实不达标，Anthropic 自报 99.5%、OpenAI API 99.97%、ChatGPT 99.2%，且降级不算停机，多租户下用户无从感知。分阶段路径是先用多租户 API 平替、撞到限流与缓存问题后再上专用 GPU 节点、最后考虑投机解码。

### 编码 agent 的外部沙箱三种实现

- 来源：Simon Willison
- 链接：https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/

与 Prime Radiant 合作提出「外部沙箱」模式：agent 本体在沙箱外，要执行的代码在专用沙箱内。放出三个实现——v86 跑 WebAssembly 里的 Alpine、Apple Containers 里跑 Alpine、以及基于微软 Quicksand（打包 QEMU 与 Alpine 的 Python 包）。三者共用同一套 localhost API，可让 Pi、Claude Code、Codex 把代码执行转发进来，并附带 HTTP/HTTPS 域名白名单代理与凭据替换机制，让 agent 无需持有密钥也能调用鉴权 API。

### Solid 2.0 正式发布

- 来源：SolidJS
- 链接：https://www.solidjs.com/blog/solid-2-0-the-long-hold/

距 1.0 五年。核心变化是把 async 引入响应式图、server functions 进核心、原 metaframework SolidStart 退役，同时删掉 createResource、batch、startTransition、on、produce、createComputed、createMutable 等原语，API 面积反而缩小。最值得看的是它的 agent 策略：细粒度图知道哪个值在何处被读，因此能在开发期直接报出错误码、源码位置和修复方式，还附带 agent 修复指南的 SKILL.md——「agent 写错的时候框架能不能看见」被当成框架的竞争力。

## 安全与事件

### Java4Shell：OpenJDK Base64 解码器可远程 RCE

- 来源：Calif
- 链接：https://calif.io/java4shell/

CVE-2026-114938，CVSS 4.0 评分 9.2。问题出在 OpenJDK HotSpot 的 x86-64 Base64 intrinsic：处理末尾填充时算错存储掩码，导致越界写。触发输入只要 64 个 A 加一个等号（OpenJDK 17 为 128 个 A 加等号），先解码 64 字节后对残留的等号算出负长度，转成一个 64 字节的完整写入，越过 50 字节结果数组 62 字节。作者在默认配置下于多个广泛部署的 Java 应用、以及 Struts 与 Spring Boot 示例应用上打通了 RCE，客户端连恶意服务器也会中招。发现用 Codex 花 1 小时、写利用 2 小时、token 成本不到 200 美元。

### Optimizely 被用来给 178 家大站投放恶意脚本

- 来源：Krebs on Security
- 链接：https://krebsonsecurity.com/2026/11/attackers-used-optimizely-to-a-b-test-malware-on-top-websites/

11 月 16 日，攻击者利用 Optimizely Experimentation 的漏洞向 178 个站点注入恶意 JavaScript，涉及 BBC、CNN、Equifax、Ledger、Zoom 等。载荷当天被重建 26 次，可窃取支付卡数据、Cookie、截图并替换加密货币收款地址，还向旧款 iPhone/iPad 投放 DarkSword、Coruna 这类零点击漏洞链。受影响站点中 68 家完全无 CSP，50 家的 CSP 仍放行载荷，只有 24 家（15%）真正挡住；全网上百万站点里部署有效 CSP 的约一成。实际损失约 7500 美元虚拟货币加未知数量卡数据。

## 实用

### NodLink：用 AirPods 头部姿态当鼠标

- 来源：少数派
- 链接：https://sspai.com/post/118732

作者用 macOS 14 起开放的 CMHeadphoneMotionManager 读取 AirPods 每秒 50 次的头部朝向，转头即指向、点头低头即上下移动，歪头可映射成按键或「按住 Fn 说话」。不开摄像头，因此关灯、躺着、侧卧都能用，弥补了系统自带面部追踪的环境限制。带 One Euro 滤波防抖与陀螺仪漂移校正，支持中英文语音指令与「标号」点选，Mac 端 Swift + 网页控制台 three.js，需 macOS 14 以上与支持头部追踪的 AirPods。
