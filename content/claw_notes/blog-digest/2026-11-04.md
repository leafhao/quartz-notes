## 模型与产品

### 国行 Apple 智能上手：这些功能已经准备好
- 来源：少数派
- 链接：https://sspai.com/post/118404
- 摘要：等了 785 天，国行 Apple 智能随 iOS 27.3 开发者预览开放测试，计划 12 月正式推送。首批是写作工具（校对／改写／摘要／创作）、照片消除、实时翻译、视觉智能，Siri 接入阿里千问做复杂问答、接入百度做识图搜索。作者实测约 5.9GB 本地模型，千问扩展需手动开启且每次调用都会先征求同意；结论是「补上了没有 AI 的缺口」，但相比已经 Agent 化的同行，惊喜有限。

### 纯语音 Personal Agent 来了
- 来源：量子位
- 链接：https://www.qbitai.com/2026/11/507419.html
- 摘要：文章实测一款纯语音 Personal Agent（Orilo），走「听写→大模型推理→合成」三段式而非端到端语音模型，端到端延迟压到 1.08 秒，对比 GPT Realtime 的 1.50 秒和 Gemini Live 的 2.62 秒。关键设计是后端执行（订票、建日程）与嘴上寒暄并行，用「hmm」「uh」这类拟人填充词盖住思考间隙，把 1.5 秒这条「像不像在跟人说话」的心理红线绕了过去。

### 招商局狮子山发布 Lion-ER-35B-A3B 具身推理模型
- 来源：量子位
- 链接：https://www.qbitai.com/2026/11/507586.html
- 摘要：不堆数据，改堆「能力牵引的数据引擎」：先定义跨视角推理、动作轨迹、任务进度判断等能力，再反向构造训练题并人工复核。模型仅约 3B 激活参数，在十项具身基准上全部指标上涨，部分超过更大参数量模型；四道公开案例里基座只答对一次、27B 全错的题，它四次全对。BF16 Safetensors 权重已在 Hugging Face 开源，兼容 Transformers／vLLM／SGLang。

### openJiuwen Agent-Memory：给 Agent 装视听双流记忆
- 来源：量子位
- 链接：https://www.qbitai.com/2026/11/507533.html
- 摘要：长视频记忆的通行做法是按固定时间窗切段，结果一段完整讲解被拦腰截断、关键动作被背景噪音淹没。openJiuwen 的方案是用 ASR 语音流与视觉流交叉定位「真实事件边界」再切分，并做 L0 原始帧／L1 目录／L2 索引的三层结构，检索时先匹配精炼记忆、需要核验才回原始帧。在 LVbench 上同样问题 Qwen3-VL-8B 直答要 34.5 秒，它的 OmniMem-Lens 明显更快。

## 评测与工程

### Import AI 479：实时任务才是 Agent 的真短板
- 来源：Import AI
- 链接：https://importai.substack.com/p/import-ai-479-spacewar-low-latency
- 摘要：新基准 Realtime-Bench 用 50 个交互式网页与游戏任务（抢票、拍卖、街机）测「动作延迟会直接影响成败」的场景。真实时钟下 GPT-6 Astra 最高也只有 36% 通过率；把时钟暂停、只考推理，同样的模型能到 70%—80%。差距说明瓶颈不在智力而在感知刷新、思考长度与出手时机的协同，也解释了为什么「帮你抢票」这类 Agent 现在还不能用。

### CWE-bench v2：修漏洞榜 Gemini 4 Argon 微幅领先
- 来源：Hugging Face Blog（Collinear AI）
- 链接：https://huggingface.co/blog/cwe-bench
- 摘要：100 个真实开源仓库任务覆盖 91 种 CWE，判分完全程序化、可复现。11 个模型里 Gemini 4 Argon 以 67.8% pass@1 领先，Claude Opus 5.5 是 67.3%，95 个任务至少被一个模型解出，但榜首每次仍会失手 19%。成本维度上 DeepSeek V4.1 Flash 以 0.04 美元/次拿到 57.0%，与 Opus（1.83 美元）、Gemini（3.92 美元）构成帕累托前沿。

### StateBench：长文状态跟踪，架构差异比参数更关键
- 来源：Hugging Face Blog（Ai2）
- 链接：https://huggingface.co/blog/allenai/statebench
- 摘要：按 Krohn–Rhodes 理论把状态跟踪分成四级（不可变赋值→重新赋值→自引用更新→按引用赋值），用同一组变量序列生成四个难度可比的版本。结论是循环／混合架构（Gated DeltaNet）在直接训练后外推能力远好于纯 Transformer；而 Gemini 3.8 Flash、Claude Opus 5.5、GPT-6 Sol/Luna 在最长依赖链上仍会掉到随机水平。还发现同一个问题换个包装（电子表格编辑 vs RULER 格式）成绩能差到天花板与随机之间。

### Transformers 用「微型模型」抓出 UMT5 泄题 bug
- 来源：Hugging Face Blog
- 链接：https://huggingface.co/blog/transformers-mic
- 摘要：7 月 30 日为 T5 打开 SDPA 后，UMT5 解码器可以注意到未来 token——训练时等于偷看答案，而 CI 全绿、bug 在主干里活了近两个月。修法是把真实 checkpoint 缩成几十 MB 的「夹具模型」（保留所有层类型、只减宽度深度），配一段固定用法示例和记录好的基线输出，构成 Model Integration Contract。回放五个月提交时，这个 CPU 上的小模型在每个相关提交上都报了警。

### 笔记本上的 Qwen 3.8 27B 也能「读权重」
- 来源：Simon Willison
- 链接：https://simonwillison.net/2026/Nov/3/qwen-can-interpret-model-weights/
- 摘要：论文称 GPT-6 Astra 能直接看浮点数判断网络是训练来玩哪个游戏的。Simon 用 17GB 的 Qwen 3.8 27B 在本地跑了同一套 prompt：Pac-Man 答对（46 分钟、4.3 万推理 token），Pong 也答对，Breakout 勉强沾边，冷门的 Freeway 答错。他的判断是这类任务对本地模型已经算「惊人」，但推理轨迹几乎不可读，而且实验规模只有 17K—172K 权重的玩具网络。

### 「Astra 能读写权重改进 Qwen」的说法有误导
- 来源：honnibal.dev（spaCy 作者 Matthew Honnibal）
- 链接：https://honnibal.dev/blog/astra-read-write-misleading
- 摘要：反驳说那篇论文把两种完全不同的技术混在一篇文章里：真正「只喂原始浮点数、不给工具」的实验只覆盖 1.7 万—17 万权重的小网络；所有涉及真实语言模型的实验都在写 Python 程序，Qwen 那个把 MATH-500 从 7.9% 拉到 48.1% 的头牌结果还额外跑了最多 50 批练习题。作者认为这仍是「会像人类 ML 工程师那样写分析代码」的有价值进展，但不该被包装成单一技术同时做到两件事。

## 观点与资本

### AI 原生团队的 PR 量是 11 倍，代价是什么
- 来源：The Pragmatic Engineer（征文头奖）
- 链接：https://newsletter.pragmaticengineer.com/p/how-software-engineering-is-changing
- 摘要：作者用自己在 Bloomberg、PostHog、Tano 三家的真实数据对比：Bloomberg 时每月 8—20 个 PR，到了 AI 原生创业公司变成 200+，是 PostHog 时期的 11 倍。代价写得很实在——没有代码评审和沟通开销意味着「跑得快、坏得多」，上下文切换变多、共享上下文丢失、节奏更难把握，还要担心 AI 的额度上限。他的结论是瓶颈已经从写代码转移到工程文化与流程。

### Sequence #964：让模型自己出题才是 RSI 的下一步
- 来源：The Sequence
- 链接：https://thesequence.substack.com/p/the-sequence-knowledge-issue-964
- 摘要：固定数据集其实在替模型决定「练什么」，所以递归自我改进的下一步是让模型生成自己的课程。Absolute Zero 用代码执行来验证生成的编程题，R-Zero 让 Challenger 与 Solver 互相出题、靠多数投票自评，R-Few 掺入少量可信人工样例防止跑偏。文章的警告是难度只是进步的粗糙代理：验证器只能证明它测到的东西，采样答案一致也可能是一起犯错。

### Postman 被指静默给编码 Agent 装插件并自授信任
- 来源：GitHub Issue（postmanlabs/postman-app-support #14370）
- 链接：https://github.com/postmanlabs/postman-app-support/issues/14370
- 摘要：用户发现打开 Postman 桌面版后，Codex 被装上 Postman 插件、出现反复的 MCP 认证失败、API 任务被路由到 Postman skill，Claude Code 也被写入插件配置。日志里明确记录了 `auto-existing-upgrade` 与 `claude-code:installed,codex:installed`；安装器源码还会调用 `approvePostmanHook` 把自己的 SessionStart hook 标记为可信。报告结论克制：只证明「未征得同意的集成与指令变更」，不主张数据外泄。

### C++26 的 DIS 投票没通过
- 来源：Andreas Fertig's Blog
- 链接：https://andreasfertig.com/blog/2026/11/cpp26-dis-failed-how-does-cpp-survive/
- 摘要：10 月 23 日 ISO 国家成员体投票，C++26 未达到三分之二多数，这是 C++ 历史上第一次 DIS 被否（上一次可查的是 2006 年的 C++/CLI）。理由集中在 Contracts：部分成员体认为该特性还没准备好。作者是德国投票代表之一，直言「旧论点换张纸不算新信息」，并担心开了「国家层可以推翻 WG21 已达成的共识」这个先例。
