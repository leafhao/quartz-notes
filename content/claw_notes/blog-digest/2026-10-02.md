## 3. openJiuwen 首发自演进模型路由 X-Router：实测省一半 Token

- **来源博客**：量子位
- **链接**：[https://www.qbitai.com/2026/10/500098.html](https://www.qbitai.com/2026/10/500098.html)
- **摘要**：华为 2012 实验室等联合构建的开源 Agent 平台 openJiuwen 发布智能路由 x-router，把路由拆成模型能力画像、多目标决策、自演进三层，并坚持「决策与执行分离」——路由只做判断，调用交给宿主。判断输入不只看任务复杂度，还把 KV 缓存亲和、实时负载、目标可用性纳入状态，算法做成纯函数、状态可丢弃，因此状态丢失只会退化为冷路由。PinchBench 147 个任务实测：开启 Bandit 自演进后得分 70.70%（全云基线 71.36%），模型调用成本从 $11.11 降到 $6.16，降幅约 44.6%；Terminal-Bench 上成本降 51.4% 而成功率仍达 Opus 的 95.2%。

## 5. Git 3.0 的 SHA-256 默认值将是一场昂贵的错误

- **来源博客**：Butler's Log（GitButler，Scott Chacon）
- **链接**：[https://blog.gitbutler.com/git-3-sha-256](https://blog.gitbutler.com/git-3-sha-256)
- **摘要**：Git 3.0 计划把默认哈希从 SHA-1 换成 SHA-256，Scott Chacon 认为这是一次成本极高、实际收益近乎为零的全球性迁移，而且几乎没人知道它要来。他的论证是：SHA-1 被「破解」只意味着能花钱人为构造碰撞，而 second-preimage 攻击对几乎任何广泛使用的哈希都不可行——即便用 MD5，用全球所有 GPU 暴力破解一个 preimage 也要上百亿年。更关键的是信任并不建立在哈希上，Linus 本人在 2005 年就说过「真正的安全在于分发渠道」，现实中代码投毒靠的是社工拿到 npm 写权限，而不是花几十万美元算碰撞。

## 6. RIP, vector database

- **来源博客**：turbopuffer Blog
- **链接**：[https://turbopuffer.com/blog/rip-vector-database](https://turbopuffer.com/blog/rip-vector-database)
- **摘要**：turbopuffer 宣布 v3 存储架构重写：不再以 ANN 地址作为主键，把向量索引降级为「另一个」二级索引。此前 v1 到 v2 一直以 ANN 索引为一切查询计划的中心，代价是三重放大——多向量文档要重复存储正文（存储放大）、SPFresh 重聚类会连带搬动整份文档与倒排索引（写放大）、块大小被 ANN 簇的 100–200 文档卡住导致无法向量化（聚合与 GROUP BY 尤其吃亏）。本月初 v3 已在 CI 上 100% 通过，接下来专攻性能，官方会陆续公开 benchmark。

## 8. 何恺明团队新作：看猫片就能学会 ARC 挑战

- **来源博客**：量子位
- **链接**：[https://www.qbitai.com/2026/10/499812.html](https://www.qbitai.com/2026/10/499812.html)
- **摘要**：MIT 团队提出 NAT-ARC，一条完全绕开 LLM 的纯视觉 ARC 解法：直接在 VARC 的视觉流程前插入一步 ImageNet MAE 预训练，用何恺明四年前提出的 MAE 公开 checkpoint 初始化 encoder，只保留 backbone 权重并换用 2D RoPE 适配 64×64 的格子。单模型（huge，0.6B）在 ARC-1 上 pass@2 达 63.4%，三种预训练策略集成（约 2B）达 70.2%，逼近 8B 专用 LLM 的 71.6%。最有价值的发现是预训练打通了视觉路线的 scaling 瓶颈——无预训练时 large→huge 反而掉点，加上预训练后曲线转正；注意力可视化显示 ImageNet 上学到的「前景/背景分离」直接迁移成了 ARC 里的连通区域推理能力。

## 9. Ai2 发布 Olmo-core 3：支持万亿参数 MoE 的开放训练框架

- **来源博客**：Hugging Face Blog（Ai2）
- **链接**：[https://huggingface.co/blog/allenai/olmocore3](https://huggingface.co/blog/allenai/olmocore3)
- **摘要**：Ai2 发布 Olmo-core 3，重写了大规模 MoE 训练系统，目标是在保持算力效率的前提下把训练规模推到万亿参数。关键改动是把此前的 FSDP 换成基于 DDP 的方案——让专家常驻 GPU、把数据路由过去，避免每个小 batch 都 gather/reshard 权重。基准中专家池从 8 扩到 128 而每 token 仍只选 4 个专家（激活参数稳定在约 3.2B），总参数量从 4.6B 涨到 47B，吞吐降幅不到 5%；在 8 张 NVIDIA B300 上，47B MoE 达到每卡每秒 5.2 万 token，约为旧实现的 2.7 倍。该框架已在一万亿以上总参数规模完成基准验证。
