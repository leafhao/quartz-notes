## 1. Orchard: 可扩展 Agentic AI 的开源框架

- **来源**：Microsoft Research
- **链接**：https://www.microsoft.com/en-us/research/blog/orchard-an-open-framework-for-scalable-agentic-ai/

微软开源了 Orchard，核心是 Orchard Env——一个基于 Kubernetes 的轻量环境服务，同一套基础设施无需改造就能同时支撑软件工程、网页导航、个人助理三类 Agent 的数据收集、RL rollout 和评测。最亮眼的数字是 Orchard-SWE 仅用约 30 亿激活参数在 SWE-bench Verified 上拿到 69.7%（加 value-model 重排到 73.0%），逼近参数量 10 倍以上的前沿系统。项目同时放出训练数据和评测方法，直指"做 SOTA Agent 必须依赖闭源沙箱和私有数据"这个复现瓶颈。

## 2. LFM2.5-2.6B：端侧 Agent 的完整后训练配方

- **来源**：Hugging Face Blog（Liquid AI）
- **链接**：https://huggingface.co/blog/LiquidAI/lfm2-5-2-6b

Liquid AI 发布 2.6B 端侧 Agent 模型，在 Apple M5 Max 上 220 tok/s、AMD Ryzen CPU 上 113 tok/s，内存占用不到 2.5 GB，工具调用和指令跟随能打过约 4 倍大的模型。后训练分四段值得细看：两轮偏 Agentic 数据的 SFT → 按领域（数学/代码/工具调用）训专家教师 → 多领域 on-policy 蒸馏（MOPD）把教师并进单个学生 → 在真实 harness 里做多轮 Agentic RL。预训练约 34T tokens，中期训练把上下文拉到 128K。

> 值得关注 Harness Proxy 的设计：把 Agent harness 当黑盒不做修改，同时透明捕获 token 级轨迹用于重建和校验 RL 样本——这是 SFT/RL 数据工程上一个干净的解法。

## 3. Shieldstral：3B 策略自适应的多模态安全分类器

- **来源**：Mistral AI（经 Hacker News）
- **链接**：https://mistral.ai/news/shieldstral/

Mistral 开源（Apache 2.0）3B 多模态安全分类器，文本安全上匹配 7 倍大的模型，多模态审核刷到新 SOTA，单张 16GB 显卡即可跑。关键创新是把内容审核建模成**二元问答**而非固定的伤害类别分类：请求由 `<Instruct>`（评估上下文与严格度）、`<Query>`（一个 yes/no 问题）、`<Document>`（待判内容）三部分组成，推理时只读 yes/no 两个 logit 做 softmax 得到连续安全分数。因此换部署场景只需改写自然语言策略，不用重新训练。

> 这个"策略在推理时以自然语言传入"的思路，比把 taxonomy 焊进权重要灵活得多，也顺带解决了"不存在唯一正确的伤害分类体系"这个根本问题。

## 7. Import AI 467：能自我维持的 AI 病毒

- **来源**：Import AI（Jack Clark）
- **链接**：https://importai.substack.com/p/import-ai-467-self-sustaining-ai

多伦多大学、Vector Institute、剑桥和 ServiceNow 的研究者做出了一个原型蠕虫：入侵主机后**征用被控机器的 GPU 跑开源权重 LLM** 来维持自身推理，再用这份推理能力发现漏洞、为每个新目标定制攻击方案继续扩散。全程只依赖单张本地 GPU 上的开源模型，不调用任何可被监控或吊销的厂商 API。底层模型只说明是 2025 年发布、能塞进单张 80GB A100。

> 工程上值得注意的是它的"推理图"设计：把 Agent 推理拆成有向图上的专职节点，每个节点只看到与自身角色相关的工具和 prompt，以此控制注意力焦点并把上下文增长限制在当前子目标所需范围内——这其实是通用的 Agent 上下文管理技巧。
