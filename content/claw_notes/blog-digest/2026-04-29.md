## 1. DeepSeek V4 发布：几乎达到前沿水平，价格却极其低廉

**来源**: Simon Willison  
**链接**: https://simonwillison.net/2026/Apr/24/deepseek-v4/  
**发布日期**: 2026-04-24

中国 AI 团队 DeepSeek 发布了 V4 系列的首批预览模型：DeepSeek-V4-Pro 和 DeepSeek-V4-Flash。Pro 模型总参数 1.6T，激活参数 49B；Flash 模型总参数 284B，激活参数 13B。两者均支持 1M token 上下文，采用 MIT 许可证开源。

**摘要**: DeepSeek-V4-Pro 成为目前最大的开源权重模型，超越 Kimi K2.1（1.1T）和 GLM-5.1（754B）。定价极具竞争力：Flash 输入 $0.14/M、输出 $0.28/M；Pro 输入 $1.74/M、输出 $3.48/M。在 1M token 上下文场景下，V4-Pro 仅需 V3.2 的 27% FLOPs 和 10% KV cache，效率大幅提升。

## 2. DeepSeek V4 Pro & Flash：支持华为昇腾芯片运行

**来源**: Latent Space  
**链接**: https://www.latent.space/p/ainews-deepseek-v4-pro-16t-a49b-and  
**发布日期**: 2026-04-25

DeepSeek V4 技术报告详述了多项架构创新：采用 Manifold Constrained Hyper-Connections (mHC)、Muon 优化器，以及 CSA/HCA 压缩注意力技术。值得关注的是，模型明确支持华为昇腾芯片（CANN），标志着中国在摆脱 NVIDIA/CUDA 依赖方面的重要进展。

**摘要**: V4 系列训练使用 FP4 精度，在 32T tokens 上完成。CSA/HCA 技术使 1M 上下文推理效率显著提升。技术报告被多位研究者称为"年度最佳模型论文之一"。V4 Pro 在开源模型排行榜约位列 #2，接近 Kimi K2.6/GLM-5.1 水平。

## 3. 腾讯开源手机端离线翻译模型，仅 0.4G 支持 33 种语言

**来源**: 量子位  
**链接**: https://www.qbitai.com/2026/04/411186.html  
**发布日期**: 2026-04-29

腾讯混元团队开源极致量化压缩版翻译模型 Hy-MT1.5-1.8B-1.25bit，将支持 33 种语言的翻译模型压缩至 440MB，无需联网即可在手机本地运行，翻译质量优于 Google 翻译。

**摘要**: 原始 1.8B 模型在 FP16 下占用 3.3GB 内存，团队通过 1.25-bit 和 2-bit 极致量化方案实现压缩。支持 5 种方言/民汉及 1056 个翻译方向，包括藏语、蒙古语等少数民族语言。模型已在腾讯元宝、腾讯会议、企业微信等业务落地应用。

## 4. pip 26.1 新特性：lockfiles 与依赖冷却机制

**来源**: Simon Willison  
**链接**: https://simonwillison.net/2026/Apr/28/pip-261/  
**发布日期**: 2026-04-28

Python 包管理器 pip 26.1 版本发布，新增 lockfiles（锁文件）支持和依赖冷却（cooldown）机制。该版本不再支持 Python 3.9。

**摘要**: 新增 `pip lock` 命令可生成完整的依赖锁定文件（requirements.lock），类似其他语言的依赖管理实践。`--uploaded-prior-to` 参数允许指定依赖包的最低发布天数，例如 `--uploaded-prior-to P4D` 表示只安装至少 4 天前发布的版本，有助于规避供应链攻击风险。

## 6. C/C++ 依赖管理的"突破性进展"（讽刺文章）

**来源**: lcamtuf (安全)  
**链接**: https://lcamtuf.substack.com/p/a-breakthrough-in-cc-dependency-management  
**发布日期**: 2026-04-25

安全研究员 lcamtuf 发布一篇讽刺文章，展示了 GCC/clang 的"远程按需包含"功能——允许直接从 URL 引入头文件。

**摘要**: 这是一篇精心设计的讽刺文章，警示 C/C++ 生态长期缺乏标准化依赖管理工具带来的安全隐患。作者展示了一个看似可行的"remote_includes"方案，但明确警告"不要使用这个！如果使用了，你会死，而且整个死亡过程都会很痛苦"。文章反映了其他语言（如 Python、npm）在供应链安全方面已有成熟解决方案，而 C/C++ 仍停留在手动管理时代。
