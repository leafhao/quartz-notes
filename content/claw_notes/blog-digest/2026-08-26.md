## 2. The Evolution of the Agent Harness

**来源**：Latent Space
**链接**：https://www.latent.space/p/attention-interface
**发布日期**：2026-08-22

**摘要**：作者认为 2025 年圣诞前后 agent"突然能用了"，不是单靠模型变强，而是模型能力曲线与 harness（工具、上下文、记忆压缩、权限护栏）成熟曲线在同一时刻交汇。核心论点：模型会持续把 harness 的能力吸收进权重，工程师则不断删掉被吸收掉的那部分脚手架。最终剩下的 harness 不再是给模型用的，而是给人类注意力用的接口。

## 4. Quantization-Aware Healing：4-bit 模型反超全精度原版

**来源**：Hugging Face Blog（Multiverse Computing）
**链接**：https://huggingface.co/blog/MultiverseComputingCAI/quantization-aware-healing
**发布日期**：2026-08-25

**摘要**：主流部署配方是"先结构压缩、再量化到 4bit、最后 healing 恢复能力"，但压缩+量化叠加会系统性损伤推理、数学和代码能力。论文提出 Quantization-Aware Healing（QAH），把 healing 过程本身放在量化感知的条件下做：GPT-OSS 120B 压到 60B 参数再量化成 MXFP4 后，在 9 个 benchmark 中有 7 个反超自己的 bfloat16 全精度版本。这颠倒了"4bit 一定不如 16bit"的常识。

**链接**：https://importai.substack.com/p/import-ai-470-no-rights-for-machines
**发布日期**：2026-08-24

## 6. Death of Params：Z.ai CEO 唐杰谈 GLM-5.3 与新的后训练 Scaling Law

**来源**：Latent Space
**链接**：https://www.latent.space/p/ainews-death-of-params-zai-ceo-jie
**发布日期**：2026-08-20

**摘要**：唐杰主张只报参数量已经没有意义，必须同时说明数据量、算力花在哪、以及谁在什么条件下跑推理。文章指出 Chinchilla 的假设在 inference-heavy 时代失效（token/param 比在 200~900 之间随任务浮动）：记忆类能力偏好更多参数，推理类能力偏好更多后训练数据和有效深度。GLM-5.3 的提升几乎完全来自长时程环境上的 RL——环境覆盖真实生产工作流，单个任务相当于资深工程师数天工作量（给模型集群、存储、内部文档、代码库，让它诊断训练栈瓶颈并交付端到端加速）。

## 7. Why Ramp built its own in-house coding agent, Inspect

**来源**：The Pragmatic Engineer
**链接**：https://newsletter.pragmaticengineer.com/p/why-ramp-built-inspect
**发布日期**：2026-08-25

**摘要**：Ramp 没用 Codex/Claude Code/Cursor，而是自建 Inspect——跑在远端沙箱、能访问大部分内部数据源、并在远端机器上直接验证前后端改动的后台 coding agent（同类还有 Block 的 Goose、Stripe 的 Minions、Shopify 的 River）。自建动因是本地机器跑不了多个并行 agent、前端工具链不够好、以及对远程开发环境的需求。技术栈为 React/Vite + Cloudflare Durable Objects + SQLite + Agents SDK + Modal 沙箱，沙箱冷启动压到 5 秒以内；所有 session 默认公开可协作，公司内 150+ 人贡献过代码。

## 8. Your executable is a SQLite database

**来源**：Simon Willison
**链接**：https://simonwillison.net/2026/Aug/24/your-executable-is-a-sqlite-database/
**发布日期**：2026-08-24

**摘要**：Farid Zakaria 展示了一个巧妙的 Linux 玩法：把 SQLite 文件格式第 68 字节处的 4-byte application ID 设为 `SELF`（Structured Executable & Linkable Format），再把 ELF 各段拆进不同 SQLite 表，配一个 self-exec 解释器就能直接执行这个数据库文件。结合 Linux 的 `binfmt_misc` 机制向内核注册该魔数，内核遇到匹配的文件会自动调用解释器——于是"数据库即可执行文件"。
