# Blog Digest - 2026-09-28

> 本期从最新未读文章中精选 10 篇。主线是「推理性价比」的集中爆发：TPU 靠手写 megakernel 反超 GPU、SSD 被当成显存跑 744B 模型、蒸馏把推理 token 砍掉四成；另一端则是失控 Agent 的真实代价被越挖越深。

## 1. Ember-1: half the tokens, same answers

- **来源博客**：Fireworks AI Blog
- **链接**：[https://fireworks.ai/blog/ember-1](https://fireworks.ai/blog/ember-1)
- **摘要**：Fireworks 基于 Kimi K3 训练出 Ember-1，在几乎不掉分的前提下把推理 token 砍掉约 40%，等价于「K3 的质量、一半的账单」。团队跑了 50 多组训练实验和 200 多次评测，自研算法专门压缩冗余思考链却保留自省能力，因为 K3 生成的 token 里超过 90% 花在内部推理上，且多轮 agent 场景下这些推理会被反复重读重计费。在 7 个基准和两家客户的线上 A/B 中，token 节省 35%—50%，质量指标持平或更好；内部开发者日常使用完全没察觉切换。

## 2. 700 TPS on Kimi K3: A Case for TPU Megakernels

- **来源博客**：量子位
- **链接**：[https://www.qbitai.com/2026/09/497425.html](https://www.qbitai.com/2026/09/497425.html)
- **摘要**：vLLM 原班人马创立的 Inferact 用 16 块 TPU v7 Ironwood 跑 Kimi K3，跑出每秒 709 token，比同条件 16 块英伟达 GB200 的 452 token 快 57%，而且推理引擎、模型完全一致，唯一变量是芯片和 kernel。关键手段是 megakernel：把原本要调度几百次的独立 kernel 合并成一个 Pallas 程序，一次调用走完 92 层 MoE 前向，从而消除 kernel 切换时的内存带宽空转。有意思的是 GB200 的 HBM 带宽（8000 GB/s）反而高于 TPU v7（7380 GB/s），差距来自软件层而非硬件规格。

## 3. Colibrì：SSD 当显存的纯 C 推理框架

- **来源博客**：量子位
- **链接**：[https://www.qbitai.com/2026/09/497624.html](https://www.qbitai.com/2026/09/497624.html)
- **摘要**：GitHub 上火起来的开源框架 Colibrì（已 32k Star）用纯 C 实现、零引擎依赖，靠「内存装不下就别全装」的思路，把 MoE 的常驻部分（约 17B 参数，int4 后 9.9GB）留在 RAM，把 1.9 万个路由专家整体丢在 NVMe SSD 上按需捞取。作者最初的开发机只有 12 核 CPU + 25GB RAM，却跑起了 744B 的 GLM-5.2；目前支持 9 个模型家族，最大到 2.8T 的 Kimi K3（需 1.6TB 硬盘、32GB RAM 起步）。它会记录专家热度做 LRU 缓存，并利用相邻层路由相关性提前一层预取，实测可预测性 71.6%；128GB 纯 CPU 桌面机约 1.8 token/s，堆到 6 张 RTX 5090 可到 5.8—6.8 token/s。

## 9. 慢即是快：1. Shampoo 的尽头是 Muon？

- **来源博客**：科学空间（苏剑林）
- **链接**：[https://kexue.fm/archives/11917](https://kexue.fm/archives/11917)
- **摘要**：苏剑林从凸优化的平均收敛上界出发，提出「正交最慢下降」原理，并把它用在所有基于 Kronecker 积的预条件优化器（Muon 与 Shampoo 家族：KL-Shampoo、OKLS、PSGD、SOAP 等）上。推导结论是：不管原始预条件矩阵 P、Q 长什么样，正交最慢下降都会把它的特征矩阵「洗掉」，至多留下特征值来修正梯度或动量的奇异值谱，使其趋于均衡——这正是 Muon 做的事情。作者坦言自己本意是想找出比 Muon 更好的优化器，测了很久没有一种 Shampoo 变体能胜过，于是有了这篇结论；他也明确声明推导依赖一系列不严格假设，无意捧 Muon 踩 Shampoo，但指出 Shampoo 路线的额外状态变量和计算代价在工程上始终是实打实的负担。
