## 六、发现的缺陷与待办

### 1. arXiv 摘要硬截断问题本期未复现（好消息）

- 09-26 与 09-27 连续两期出现"同分段摘要统一长度"的硬截断（热榜侧 900→700 字符、雷达侧 200→250 字符）。

- 判定：该现象属波动性瑕疵而非持续缺陷，本期不列为待办；继续观察是否回摆。

### 2. arXiv 去重库污染连续第 7 期未修（长期项）

- 内部元数据自述历史库为 **355 个 ID**（近期序列 346→347→352→355），窗口仍为 **11 天**，而任务提示词规定为 **7 天**。
- 磁盘证据：5 篇 6—7 月残留笔记的 mtime **仍固定为 2026-09-18 08:06:38**，未被任何后续操作刷新，因此仍在 11 天窗口内。
- 自指污染持续：任务目录内的内部工作记录自身也被计入历史库。
- 影响：本期交付未受影响（最终 25 篇与历史库零重叠），风险是潜在的静默漏检。
- 09-25 提出的升级建议（改建基于 ID 的持久去重库 + 排除内部文件）**连续 3 期未落地**。

### 3. 取数方式变更未在公开笔记留痕（连续第 5 期）

### 5. 本期新坑：检索参数漏写会静默返回空结果（内部记录）

- 现象：高级检索参数未配 `advanced=`（或首项未显式写 `AND`）时，16 式**全部返回 0 条**，但 HTTP 状态为 200、页面约 30KB —— 实际拿到的是未提交查询的空白检索表单页。

- 当日已自查修复（补上参数后同样 16 式取回 800 条）。
- 建议把"任一式 0 条时先检查页面是否含结果块"写入常规自查。
